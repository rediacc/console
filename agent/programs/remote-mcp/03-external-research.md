# remote-mcp: external research

Three research rounds run on 2026-11-20 against official sources. Every claim names its source; "unconfirmed" marks a claim no official page stated. Facts here change fast, so a writer re-checks a load-bearing one before building on it.

## 1. MCP specification and SDKs

- **Current revision is 2026-07-28**; it removes protocol sessions and the `initialize` handshake, replaces server-initiated requests with the retry pattern MRTR, and moves tasks to an extension. Sources: https://modelcontextprotocol.io/specification/versioning, https://modelcontextprotocol.io/specification/2026-07-28/changelog
- **SDK 1.32.2 (installed) implements up to 2025-11-25 only**; its README says 2026-07-28 support "is not planned for v1.x". v2 (`@modelcontextprotocol/server`, `@modelcontextprotocol/client`, 2.4.0) implements 2026-07-28; v1.x gets fixes until at least 2027-01-27. Source: https://github.com/modelcontextprotocol/typescript-sdk
- **Authorization** (https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization): optional for HTTP; when used, the server is an OAuth 2.1 resource server publishing RFC 9728 metadata; 401 carries `WWW-Authenticate: Bearer resource_metadata=...`; clients send RFC 8707 `resource` and PKCE S256; Client ID Metadata Documents are SHOULD, Dynamic Client Registration is deprecated; tokens are audience-checked and never passed through; public-client refresh tokens rotate; `iss` (RFC 9207) SHOULD appear. A static bearer token is not forbidden but generic clients cannot discover it.
- **Streamable HTTP** (https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http): stateless; no `Mcp-Session-Id`, GET stream, DELETE or resumability; each POST answers JSON or a request-scoped SSE stream; `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` headers required; `server/discover` required; `Origin` validated. v2 `createMcpHandler(factory)` returns `{ fetch }`, runs on Workers, builds a server per request, `legacy: 'stateless'` by default, and does no Origin validation itself. Source: https://ts.sdk.modelcontextprotocol.io/v2/serving/web-standard.html
- **Elicitation** (https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation, `.../basic/patterns/mrtr`): the server returns `input_required` with an opaque `requestState`, which it MUST integrity-protect, SHOULD bind to the user, give a short TTL and make single-use; form mode never asks for secrets; URL mode is "may change" and must not authorize the user to the same server.
- **Progress and tasks**: progress is stable but rides only the request's SSE stream; tasks are the extension `io.modelcontextprotocol/tasks` (https://modelcontextprotocol.io/extensions/tasks/overview), only partly served by SDK v2.
- **Tool results** (https://modelcontextprotocol.io/specification/2026-07-28/server/tools): execution errors return `isError: true` and clients SHOULD show them to the model; protocol errors are JSON-RPC errors clients MAY show; `structuredContent` must match `outputSchema`; annotations default to `destructiveHint: true`, `readOnlyHint: false` and are untrusted hints; `tools/list` may vary by token scope only. An expired credential of the server itself is an HTTP 401 that makes the client re-run OAuth.
- **Security best practices** (https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices): no token passthrough; per-client consent and exact `redirect_uri` matching; state handles keyed `user_id:handle`; SSRF applies to authorization servers fetching CIMD documents.

Impact on design: SDK v2 for both servers (D12); stateless JSON transport; OAuth with CIMD first (D11); an expiry of the OAuth token is a 401, while grant revocation and bearer-fallback expiry use an `isError` result with a re-auth link; confirmation through MRTR elicitation with a signed, single-use `requestState` (D21).

## 2. Client support (all pages fetched 2026-11-20)

| Client | OAuth | Static header | Tool-call limit |
|---|---|---|---|
| claude.ai, Desktop, mobile, Cowork | DCR and CIMD; RFC 9728 required, `resource` must equal the URL; refresh on 401 | beta, limited orgs, one credential per org | 240 s, about 150k characters |
| Claude Code | RFC 9728 then RFC 8414; DCR, CIMD or manual client id | yes: `-H`, `.mcp.json` `headers`, `headersHelper` | `MCP_TOOL_TIMEOUT` (long default); output capped at 25k tokens unless `_meta["anthropic/maxResultSizeChars"]` |
| Claude API `mcp_servers` | caller passes `authorization_token` | that field only | unconfirmed |
| ChatGPT dev mode / Apps SDK | CIMD, then DCR, then static client credentials; PKCE S256 | no ("cannot present custom API keys") | about 60 s (forum, unconfirmed) |
| OpenAI Responses API `mcp` tool | caller passes `authorization` | `headers` in older docs only | unconfirmed |
| Cursor | DCR or static `auth`; RFC 9728 and 8707 | yes, `headers` | about 300 s IDE, 60 s CLI (forum, unconfirmed) |
| VS Code Copilot | DCR, built-in providers, manual client id | yes, `headers` with a password input | 128 tools per request |
| Windsurf | OAuth (details unconfirmed) | yes, `headers` | 100 tools total |
| Gemini CLI / Antigravity | discovery, DCR, ADC; Antigravity adds CIMD | yes | 10 min default |

Sources: https://code.claude.com/docs/en/mcp, https://claude.com/docs/connectors/building.md, https://claude.com/docs/connectors/building/authentication.md, https://platform.claude.com/docs/en/agents-and-tools/mcp-connector, https://developers.openai.com/apps-sdk/build/auth, https://developers.openai.com/api/docs/guides/tools-connectors-mcp, https://developers.openai.com/api/docs/guides/developer-mode, https://cursor.com/docs/context/mcp, https://code.visualstudio.com/docs/agents/reference/mcp-configuration, https://docs.devin.ai/desktop/cascade/mcp, https://geminicli.com/docs/tools/mcp-server/, https://antigravity.google/docs/mcp

- Claude surfaces need redirects `https://claude.ai/api/mcp/auth_callback` and loopback on any port; Claude picks CIMD only when metadata advertises `client_id_metadata_document_supported: true` and `none` in `token_endpoint_auth_methods_supported`.
- No client documents a `client_credentials` grant or MCP tasks; progress does not extend Cursor's timeout (forum, unconfirmed).
- Only ChatGPT documents a confirmation prompt driven by `destructiveHint`; Claude Code uses `readOnlyHint`, `idempotentHint` and `_meta["anthropic/requiresUserInteraction"]`; VS Code states annotations are not permission grants.

Impact on design: OAuth is mandatory for ChatGPT and in practice for claude.ai; the bearer header covers Claude Code, the APIs, Cursor, VS Code, Windsurf and Gemini; a synchronous call returns within about 60 s (D15); large outputs are paged; per-URL scoping that narrows the tool list keeps VS Code and Windsurf under their tool caps.

## 3. Cloudflare

- **Containers** went GA on 2026-04-13 (https://developers.cloudflare.com/changelog/product/containers/); the `durable_object` scheduling policy is public beta and `default` is deprecated (https://developers.cloudflare.com/containers/configuration/scheduling-policy/); the `Container` class is maintained through 2026-12-31 (https://blog.cloudflare.com/faster-agent-sandboxes/). PX/org-executor.ts already drives `ctx.container` directly, so the freeze does not bind this program; a scheduling policy cannot change on an existing application.
- **Limits** (https://developers.cloudflare.com/containers/platform-details/limits/): instance types lite to standard-4; `max_instances` unsupported under the policy, so the code cap stands; cold start 1-3 s generally, median 648 ms for `ctx.container` per the blog; disk wiped on sleep unless snapshots (beta).
- **Outbound** (https://developers.cloudflare.com/containers/platform-details/outbound-traffic): interception covers HTTP 80 and HTTPS 443 only, at most 128 entries; with `enableInternet: true` SSH on port 22 goes direct and cannot be intercepted.
- **workers-oauth-provider** 1.2.4 (https://github.com/cloudflare/workers-oauth-provider): OAuth 2.1 server and resource wrapper with PKCE, DCR, CIMD, RFC 9728, RFC 8707, token exchange, revocation; grants in KV, tokens hashed, token shape `userId:grantId:secret`; scopes advertised but not enforced. Props encryption (https://github.com/cloudflare/workers-oauth-provider/blob/main/storage-schema.md) wraps a per-grant key under `HMAC(static constant, token)`, so any holder of the token decrypts props; it protects only KV at rest.
- **Agents SDK**: `createMcpHandler` is stateless and Streamable-HTTP only; `McpAgent` is marked deprecated in favour of SDK v2 (https://developers.cloudflare.com/agents/model-context-protocol/transport/). Guidance: https://developers.cloudflare.com/agents/model-context-protocol/authorization/
- **Logging** (https://developers.cloudflare.com/workers/observability/logs/workers-logs/, https://developers.cloudflare.com/workers/runtime-apis/handlers/tail/, https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/zone/http_requests/, https://developers.cloudflare.com/workers/observability/traces/spans-and-attributes/): invocation logs carry method and URL; Tail Workers redact auth-like headers and long hex or base64 runs heuristically, `getUnredacted()` exposes all; Logpush `ClientRequestURI` holds full path and query and headers only through custom fields; OTel spans record `url.full` unredacted.
- **Durable Objects** about 1,000 req/s soft limit per object (https://developers.cloudflare.com/durable-objects/platform/limits/); the rate-limit binding counts per location, eventually consistent, 10 or 60 s periods (https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

Impact on design: the authorization server, `OAUTH_KV` and validation sit in the dedicated MCP Worker so S never reaches the account Worker (D13), and scope enforcement is ours; no secret in a URL path or query, with CI guards against header-capturing Logpush fields and `getUnredacted()` (D14); a strict per-grant limit uses one Durable Object per grant, the binding only as a cheap throttle.
