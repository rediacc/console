# fix(ci): the post-merge CI reader, and four defects it exposed

Follow-up to #574, found by *using* what that PR shipped rather than by reading it.

## The bug that started it

`/pr-merge` step 5 tells a session to watch Console CI on `main` after a merge:

```
$ .ci/scripts/ci/ci-trace.py --ref main --wait --until-final
no-verdict: no open PR for ref 'main'
```

It exited without watching anything. `wl_ci.ci_rollup` only ever asked
`pullRequests(headRefName:)`, and `main` after a merge has no open PR.

This is worse than one broken invocation, because `ci-trace.py` is the **only
sanctioned** CI reader: `block-adhoc-sanctioned.sh` refuses hand-rolled `gh`
watch loops and `block-ci-polling.sh` refuses `sleep`+`gh run view`. The
post-merge step had no working instrument at all — which pushes a session toward
either skipping verification of the release path or evading a guard.

## The fix

GitHub exposes the identical `statusCheckRollup` under
`repository.ref(qualifiedName:).target`, so this is a second **source** for one
payload, never a second reader — `ci_classify`, `ci_steps` and the verdict logic
are untouched. Both sources now share one pager, so `CI_MAX_PAGES` and the
`truncated` flag cannot drift apart.

Three deliberate constraints:

- **`allow_branch` defaults to `False`.** The Stop hook reads `no-pr` as a
  meaningful answer; silently substituting a branch read would *change* that
  check's meaning rather than extend it. Only an explicit `--ref` opts in.
- **A missing ref answers `no-ref`,** distinct from `no-pr`. A typo must not read
  as a branch that merely lacks a PR.
- **The output names its source** (`branch main @ b4b5797e (no PR)`). One
  undifferentiated channel is exactly the defect #574 fixed in `run.sh`.

## Three more defects found while driving it

(A fourth, in the Stop hook itself, has its own section below.)

1. **`toolchain_pin_for` returned `""` with return code 0** when the pins had not
   been loaded, so `pin=$(…) || return 2` never fired and an empty version
   reached a download URL:
   `…/releases/download/v/shellcheck-v.linux.aarch64.tar.xz` → curl 404. The 404
   names GitHub, pointing away from the cause. `toolchain_check` already guarded
   this; `toolchain_acquire` did not. Root-caused by loading in `pin_for`
   (idempotent) and mirroring the guard. `toolchain_acquire shellcheck` now
   downloads and checksum-verifies **0.10.0** instead of 404ing.
2. **`devbox_exec` died whenever docker needs sudo.** `devbox_docker` answers two
   words (`sudo docker`); `devbox_exec` was the only caller quoting it as a
   single command name → `sudo docker: command not found`. Swept the class:
   `devbox_shell` was the last site still passing the numeric
   `-u $(id -u):$(id -g)`, aligned to `-u vscode`.
3. **`Build (CLI) / CLI (mac-arm64)`** failed on `main` at `Set up job` on
   GitHub's *internal* DNS, and is **not** in the watchdog retry allowlist
   (`E2E,OPS,Fork Isolation,Migration Test`), so nothing retried it. Noted, not
   code-fixed; the same shape will recur.

## Gates

- **`test-ci-trace-branch.sh`** (new, wired as `gate-test:ci-trace-branch`).
  Hermetic — `gh` is shimmed with a fake that answers the PR and branch queries
  *differently*, which the shared `with_fake_gh` helper cannot do. Control built
  by construction (copy + appended override), and it fires on the real pre-fix
  source: `TypeError: ci_rollup() got an unexpected keyword argument`.
- **`check:ci-devbox-exec`** (new, wired three-point: `package.json:86`,
  `manifest.ts` with `gate: true`, `ci-quality.yml:535`). Defect 2 is
  *unreachable* in CI — runners and containers grant docker without sudo, so the
  branch that breaks is never taken, and a runtime test would have to
  manufacture a sudo-requiring docker. But it is fully visible in the source, so
  `.claude/skills/testing` routes it to a static gate. **B1** forbids invoking
  `devbox_docker`'s possibly-two-word answer as one quoted command, with an
  anti-vacuity floor (22 invocations actually scanned, because a scan over
  nothing passes). **B2** forbids a numeric `-u` into the container. Four
  controls built by construction, two of them over-broadness controls: the array
  and unquoted forms must *not* be flagged, and a comment describing the bad
  shape must *not* be flagged. Fires on the real pre-fix `devbox.sh` at
  `7230af97`.
- **A10 in `check-toolchain-pins.sh`**: *all three pin readers must still READ
  the pins.* A3 proved the file is **parseable** by three readers; nothing proved
  they still read it. Delete the source from `constants.sh`, or the `COPY` from
  the Dockerfile, or the `--env` step from `ci-quality.yml`, and every other
  assertion stays green while that lane's tools revert to whatever is on PATH.
  Each reader is checked for the *mechanism* it uses, not for the string
  `toolchain.env` — all three files carry comments naming it, so a substring scan
  would be satisfied by prose describing the wiring instead of the wiring. Proven
  by darkening each reader in turn: all three fire independently and name the
  lane, while the wired baseline stays green.
- **A9 in `check-toolchain-pins.sh`**: *a pin must RESOLVE, not merely exist.*
  A1–A8 are source scans and every one was green while defect 1 was live,
  because the fault was in a **return value**, not in the text. A9 therefore
  executes the library in a subshell that sources nothing else — the exact
  caller that broke. Proven against the real pre-fix library at `8c049245`,
  where `shellcheck`, `ruff` and `shfmt` all resolve empty.

## And one defect in the machinery that judges all of this

`e87bf667`. `prove_new_gate` in the Stop hook used **working-tree dirtiness as
its entire freshness test**, silently assuming a session leaves its work
uncommitted. Commit the gate in the stop that created it — which the findings
rule pushes toward once a fix is headed for a PR — and the path is clean,
`prev is None`, and the gate is filed at `exit=-3`: a glob widening, never run,
never evidence.

Measured here: `check-devbox-exec.sh` was written, wired, proven against
pre-fix source and committed inside one stop; the next stop reported *"no NEW or
CHANGED check script this stop"* while the marker held that exact gate at
`exit=-3`. The finding then had **no reachable exit** — writing the gate again
could not change the outcome, and the judge was already answering "no further
work needed".

`_new_since_head` asks whether the path existed at the marker's last-seen head,
which is exactly *"did this session create it"*, independent of commit state. It
errs toward `True` on any git failure, matching `_is_dirty`: run the gate rather
than skip it silently. Verified both directions —
`check-devbox-exec.sh` → `True`; `check-toolchain-pins.sh` and
`check-editorconfig.sh` → `False`; an empty head is never evidence.

## Blind spots

Stated so the green is not read as more than it is: no CI job runs
`./run.sh quality` with a devbox container present, so the lane and its probes
are covered by host-side assertions and a manual matrix; the pin gates assert
*wiring*, not *runtime*, except A9; and `test-ci-trace-branch.sh` does not
validate its GraphQL selection against the live schema — a deprecation would
surface as `unreadable`, which at least says so.
