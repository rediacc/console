### Options for Workers telemetry (Cloudflare docs read 2026-10-23)

**(a) Native Workers Observability OTLP export. Recommended.**
- Config: `[observability.traces] enabled = true, destinations = [ "<name>" ], head_sampling_rate, persist`, and the same block for `[observability.logs]`; "Each name must match a destination configured in the dashboard." (https://developers.cloudflare.com/workers/observability/opentelemetry-export/)
- Destinations are created by API and referenced by name: `POST /accounts/{account_id}/workers/observability/destinations` with `{"configuration": {"headers": {...}, "logpushDataset": "opentelemetry-traces | opentelemetry-logs | opentelemetry-metrics", "type": "logpush", "url": "..."}, "enabled": true, "name": "..."}`, permission `Workers Observability Write`; `PATCH .../destinations/{slug}` takes `configuration.headers` and `replaceHeaders`; the response carries `configuration.jobStatus` (`last_complete`, `last_error`, `error_message`). (https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/destinations/methods/create/, .../update/)
- A destination has a free `headers` map (the export guide notes most providers require authentication headers, https://developers.cloudflare.com/workers/observability/exporting-opentelemetry-data/); `Authorization: Basic` is not named explicitly, so T6 proves it against Traefik. Cloudflare does not export the binary protobuf format; Alloy's OTLP/HTTP receiver accepts JSON.
- Workers infrastructure metrics and custom metrics cannot be exported through OpenTelemetry (opentelemetry-export page): request metrics come from Tempo spanmetrics, which the dashboards already use.
- Identity: spans carry `service.name` (the Worker name, e.g. `edge-rediacc-account-us`, not `rediacc-account-server`), `cloudflare.script_name`, `faas.name`, `cloudflare.script_version.id`, `cloudflare.colo`; fetch spans also carry `url.full`, `url.path`, `user_agent.original`, `geo.*` (https://developers.cloudflare.com/workers/observability/traces/spans-and-attributes/). Some attributes apply only to some spans and the names are not yet final (https://developers.cloudflare.com/workers/observability/traces/known-limitations/); T6 records the placement from a live probe before T7 is written.
- Custom attributes: the runtime `tracing` API (`ctx.tracing`, `getActiveSpan()`) adds attributes that appear in traces and in the OpenTelemetry export (https://developers.cloudflare.com/workers/observability/traces/custom-spans/).
- Cost: export has no separate charge; with `persist = true`, persisted data counts toward Cloudflare Observability ingestion and storage from 2026-12-01 (50 GB ingestion and 10 GB-month included, then $0.25/GB and $0.10/GB-month, https://developers.cloudflare.com/observability/pricing/). Worker CPU and subrequests are untouched.
- Trace ids are not propagated to services outside Cloudflare, so CLI and account traces do not join.

**(b) An OTel SDK inside the Worker. Rejected.** `@opentelemetry/sdk-node` is a Node SDK; a Workers exporter would flush from `ctx.waitUntil` at the cost of subrequests and CPU per request (https://developers.cloudflare.com/workers/platform/limits/), duplicate the runtime's automatic spans, and put exporter code and a credential on every request's hot path. Its one advantage, a credential the rotation reaches, (a) gets from T1.

**(c) A tail Worker or Logpush bridge. Rejected.** A tail Worker receives statuses, console output and exceptions but not spans, is billed by CPU time and needs a hand-written OTLP mapping (https://developers.cloudflare.com/workers/observability/logs/tail-workers/). Logpush is already the transport under (a).

### Recommended design

1. **Destinations.** Eight account-level destinations, `otlp-<r>-traces` and `otlp-<r>-logs` for r in eu, us, asia, bench, at `https://otlp.rediacc.io/v1/traces` and `/v1/logs`, with `Authorization: Basic` of that region's active credential. Stable and edge of a region share the pair, as they share the Traefik user. The proxy (`rediacc-proxy-eu`) uses the eu pair.
2. **Rotation reaches the destination.** A rotation consumer `cf-otel-destination:<name>` (T1) upserts the destination with `replaceHeaders: true` when `rotate otlp-<r>` runs. The new htpasswd entry is appended before the old one is removed (the existing grace flow), so delivery continues through a rotation. The value travels only in the API request body.
3. **Identity.** An Alloy transform (T7) maps script names to resource attributes on every span and log: `service.name` = `rediacc-account-server` for `(edge-)rediacc-account-*` and `rediacc-proxy` for `rediacc-proxy-eu`; `deployment.environment` = `production` | `edge` | `bench`; `rediacc.region` = `eu` | `us` | `asia` (bench is `eu`, told apart by `deployment.environment=bench`); `rediacc.worker` = the original script name. The tracing middleware (T2) also sets `deployment.environment`, `rediacc.region`, `http.route` and `rediacc.probe` on the root span through `ctx.tracing`.
4. **Spanmetrics and dashboards.** Tempo's spanmetrics dimensions (`service.version`, `deployment.environment`) gain `rediacc.region`, the Prometheus label `rediacc_region`; dashboards gain `$environment` and `$region` (T10).
5. **PII.** The Worker serves links carrying live one-time tokens in the query (magic link `private/account/src/services/auth.service.ts:192`, password reset `:411`, email confirm `private/account/src/services/billing.service.ts:293`, invite `private/account/src/services/org.service.ts:840`), so `url.full` carries them. The Alloy transform strips the query from `url.full`, drops `geo.locality.*`, and rewrites `token=<value>` in log bodies; the middleware stops copying the raw user agent.
6. **Sampling.** `head_sampling_rate = 1` for traces and logs while traffic is low; T8 records the daily volume, and stable traces drop to 0.1 first if it would pass the included ingestion.
7. **Proxy.** The proxy Worker exports through the eu pair as `rediacc-proxy` (T14), recording only a reason code for refusals. The container's CLI reports as `rediacc-proxy-executor` (T13). The CLI root hook runs once per dispatched command (`packages/cli/src/services/serve/command-dispatch.ts:381`), and the container fetches credentials from `REDIACC_ACCOUNT_SERVER` = `https://eu.rediacc.com` (`workers/proxy/wrangler.toml:14`), so the otlp-eu credential. Four in-process defects need fixing first: a process-wide SDK singleton (`packages/cli/src/services/telemetry/telemetry.ts:157`), shutdown on any error (`packages/cli/src/utils/errors.ts:117`), context globals keyed by command name (`packages/cli/src/cli.ts:51-60`), and user attributes taken from the executor's own token.
8. **renet.** No change: `renet-execute` and `renet-list` already deliver (`private/renet/pkg/telemetry/telemetry.go:30,36`).
9. **Hostinger "observability" repo.** Not in this tree; its files below (CLAUDE.md, README.md, tempo.yaml.template, the Alloy config, Grafana provisioning, `.env`) come from the prompt, and the ops writer locates the exact paths.

### How the live checks reach the stack

Live acceptances query through the Grafana datasource proxy, `https://grafana.rediacc.io/api/datasources/proxy/uid/<uid>/...`, with a read-only Grafana service-account token in Bitwarden as `OBS_GRAFANA_READ_TOKEN` (new, minted by the operator). `<tempo>`, `<prom>` and `<loki>` are the datasource uids from Grafana provisioning. A probe is `GET https://<host>/account/api/v1/health` with header `X-Rediacc-Probe: <uuid4>`, sent by T16's tool to each of the seven hosts (eu, us, asia, edge-eu, edge-us, edge-asia under rediacc.com, and bench.rediacc.com).
