## Design

**The name is `onprem`.** It is already the internal token for this stack: `onprem` appears 609 times in console and 203 in account (`onprem-extras.ts`, `test_onprem_template_parity.py`, the `backup-onprem` drill, the `ONPREM_<sha12>_*` BWS names, `PLAN-onprem-*`), it reads as the public "on-premise server", it is short, and it greps uniquely. `server` was rejected: the image `ghcr.io/rediacc/server` and the verb `rdc server` already use it, and as a repository, env prefix (`SERVER_DOMAIN`) or grep target it collides with every other server in the tree (`rdc serve`, `services/server/`, the account server). `on-premise-server` was rejected as long and unlike every existing identifier. No `ONPREM_` name collides: the existing family is `ONPREM_FREE_TIER_*` and `ONPREM_HALF` only.

**The mapping.** `rediacc/elite` -> `rediacc/onprem`; `private/elite` -> `private/onprem` (submodule name, path and url); template `elite` -> `onprem` and `DEFAULT_REPO` -> `onprem`; container names `elite-*` -> `onprem-*`; `ELITE_{DOMAIN,STORE_DOMAIN,IMAGE,OFFLINE,TLS,CA_FILE}` -> `ONPREM_*`; `WK_ELITE_REPO` / `ELITE_REPO` -> `WK_ONPREM_REPO` / `ONPREM_REPO`; `ci_start_elite`, `ci_stop_elite`, `elite_s3_probe[_stub]` -> `*_onprem*`; drill `backup_elite_compose` -> `backup_onprem_compose` (verb `backup-onprem-compose`, flag `--onprem`); shims `ci-{start,stop}-onprem.sh`; job `onprem-run-test` named "On-Prem Run", scope key `onprem_run`, `RESULT_ONPREM_RUN_TEST`, area `onprem`; `ELITE_S3_PROBE_*` -> `ONPREM_S3_PROBE_*`; `elite-recovery.env` -> `onprem-recovery.env`; prose "Elite" -> "on-prem server". The image `ghcr.io/rediacc/server` and the verb `rdc server` stay.

**Clean break.** No alias, no dual env read, no fallback template name. The one live box (`acme-onprem` on hostinger) is moved forward by L1 (rewrite its env keys, then upgrade), not by compatibility code.

**Order, so nothing breaks half-way.**
1. G1/G2 rename the repositories first. GitHub and GitLab both redirect the old path, so main's checkouts of `rediacc/elite` keep cloning while the branch moves. One hypothesis is unproven: whether `actions/create-github-app-token` accepts the OLD name in `repositories:` after the rename. G1's accept probes it; if it refuses, main's scheduled runs red until the batch lands on main, and they are re-run then (fix forward).
2. S1 moves the submodule in the main checkout (the lead's commit, since a lease never commits a gitlink), so every lease starts with `private/onprem` in place.
3. W1-W6 run in leases with disjoint Owns, landed submodules first.
4. R1-R3 lock the result: the retired term, the live-plan citations, and the console grep.
5. One `ci:quick`, one `vm:check -- --changed` (renet and account move), one push, then the live boxes.

**Kept on purpose** (the R3 grep excludes exactly these): `agent/**`; `.ci/shadow/**`; `.ci/rediacc_ci/tests/fixtures/**`; `docs/ci-overhaul/**` (a dated program record, `06-progress.md` declares itself one); `docs/backup-storage/archive/**`; `docs/agent-reference/deleted-branches-20260730.md`; the DORA "elite performers" quote lines. Everything else moves, including test names, hook goldens and the dated row in `.ci/policy/README.md`.

**i18n.** English changes first (7 keys), then the 12-locale delta goes through the naturalization flow in `docs/i18n/CONVENTIONS.md`; most of the delta is the token itself. The www doc change is a code sample, identical in every locale.

**Out of scope.** GHCR (no `elite` package exists, `PLAN-ghcr-registry-cleanup.md`). The `ON_PREMISE_*` account variables, which already carry the public name. Rewriting history in `agent/**` or the shadow ledgers.

## Risks

- **App token after the rename.** If `create-github-app-token` refuses the old name, every main workflow that mints a token reds between G1 and the batch landing on main. The window is one batch; G1's probe says which case holds before S1 starts, and a red main run is re-run with `gh run rerun --failed` once the batch is on main.
- **Other checkouts.** Every other checkout and devbox keeps an orphan `private/elite` directory and `.git/modules/private/elite` after it pulls; `git submodule sync && git submodule update --init private/onprem` makes the new one, and the old directory is removed by hand once its branch is pushed. Leases opened before S1 must be landed or collected first (`./run.sh worktree leases`).
- **A live writer on the server verbs.** `PLAN-enterprise-tenants.md` has 30 open boxes, some on `packages/cli/src/services/server/**`; `exclusive` concurrency makes `block_plan_concurrency` refuse the overlap, so the rename waits for a quiet window rather than racing it.
- **Install records on a device.** A record created with the default repo names `elite`; `rdc server` verbs given no `--repo` would then look for `onprem`. The only known install passes `--repo acme-onprem`, so nothing in use breaks; a stray dev record is reinstalled.
- **Goldens.** A regolden that moves a value not caused by the rename hides a regression; the writer reads each `intentional:` diff before landing.
- **Open questions for the operator.** (1) Confirm `onprem` over `server` and `on-premise-server`. (2) G1 and G2 are outward actions: run them, or approve the agent running them. (3) R2 adds one citation line to plans another session owns; approve or name the plans to leave alone.
