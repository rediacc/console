## Design

1. REGISTRY `.ci/config/pins.json`, read by `scripts/lib/pins/registry.ts` and `.ci/rediacc_ci/core/pins.py`. Entry: `id`, `kind` (family|leaf), `driver`, `source` (npm-registry, go-list, go-dl, github-release, github-tags, pypi, obs-repomd, quay-tags, dockerhub, or `none` with a BLOCKER reason), `safety` (release-age | mirror-tag | same-host-version | assisted, plus `major: refuse|allow-file|assisted`), `holds`, `gates` (manifest ids), `sites` (`{repo, file, match}` with an anchored regex, named groups per role, and an `expect` count), `derive` steps (`{run, cwd, writes[]}`), and `literals` (context regexes for prose or comment copies, each a site or a reasoned `ignore`). A family names a `scope` whose members the driver enumerates. embed-asset-sources.ts, devcontainer-pin-sources.ts, the SOURCE_CONSTS list and PIN_SITES become readers of the registry; their literal arrays are deleted.
2. COMPLETENESS GATE `check:ci-pin-registry` (offline): scanners over every tracked file of the console and each declared submodule (Dockerfile ARG *_VERSION/_SHA256*/_COMMIT, toolchain.env KEY_VERSION/SHA256, FROM images, `uses: x/y@<sha>`, package-lock.json, go.mod and its `go` line, *.lock.json pin files, .ceph-image-pin host/image). An unclaimed hit is red with the entry shape to add; a site matching other than `expect` times is red; each `literals` regex runs over tracked text and an unclaimed occurrence of a pin's current value is red; a dead ignore is red; `source: none` needs a reason; a missing declared submodule under CI fails closed. Controls: one planted unclaimed instance per scanner, a dead site, a duplicate match, an unclaimed literal and a dead ignore each red, with a mutant per scanner.
3. COMMAND `npm run pins -- <verb>` (scripts/pins/pins.ts): `status [<id>] [--json]`, `when <id>` (the instant the newest too-new release clears the window, with a ready worklist DEFAULT line instead of parked hand patches), `plan <id>|--all`, `bump <id> [--to <v>]`, `bump --all`, `apply-soaked`, `bump <id> --major --reason "<why>"`, `hold <id> --reason "<why>" [--expires YYYY-MM-DD]`, `remove <pkg>`, `lockfiles [<dir>]`, `verify`. Every driver resolves the target from its source of truth through scripts/lib/upstream.ts and judges it with scripts/lib/release-age.ts; the npm driver IS check-deps' extracted planner. Atomic rewrite: plan everything first, refuse the whole pin when any site does not match `expect` times, refuse when a site file holds changes the run did not make (another session's work), journal every file it writes under .ci/cache/pins/<stamp>/, write sites, run derive steps, run the gates, and on failure restore only files that still hold the bytes the run wrote, naming any it leaves alone. npm steps run as `npx -y npm@<NPM_VERSION>` only; each touched lockfile gets the canonical `install --package-lock-only --ignore-scripts`; a changed root lockfile is followed by `npm ci && npm run install:natives`. Majors: npm writes a transient allow entry, runs the planner, then removes the dead entry and any blocklist line or exception for the package; Go majors are refused (import paths are code). `remove <pkg>` uninstalls from every declaring manifest and cleans blocklist, exception, allow, override and `_overridesReasons`, syncpack groups and knip ignores, then runs check:ci-runtime-imports-are-deps. Output: it never commits; per repo, submodule first, it prints the changed paths, the exact add and `commit -F <draft> -- <paths>` lines and the pointer line, with message drafts (versions, publish times, soak-clear instants, gate rcs, `PR-TASK: <--task>`) under .ci/cache/pins/<stamp>/.
4. REMEDIES: one helper (scripts/lib/pins/remedy.ts and rediacc_ci.core.pins.remedy) builds every freshness gate's failure line: `npm run pins -- bump <exact id>` (or `bump --all`), `npm run pins -- lockfiles <dir>` for check:ci-lockfile. The old to-do lists and the sed recipe go. A gate test drives each gate red on its fixture seam and asserts the line.
5. COVERAGE: a new pin-freshness gate (registered under its check name by T10) compares every registry leaf that has a source and no family gate (toolchains, devcontainer ARGs); it fails closed and is red at once (operator answer).
6. SCHEDULE `.github/workflows/pins-soaked.yml`: daily at 00:30 UTC, on workflow_dispatch, and on workflow_run of CI - OBS Mirror; `permissions: contents: read`; runs `npm run pins -- apply-soaked --json --out pins-soaked/`, uploads per-repo patches, drafts and the report as an artifact with a job summary; green when nothing is soaked or every soaked bump passes its gates, red otherwise; opens nothing and pushes nothing (operator answer). A session applies the result by re-running `apply-soaked` on its own branch against the live tree.
7. Rules kept: no inline suppressions; fail closed on network, match counts, dirty files and a foreign npm; controls and mutants for every gate; one branch, one PR; writers never commit and the tool never commits.
