## Ask

Five open correctness items from console#523 (the P4 cluster/datastore wave backlog, still open after the 2026-07-19 audit) that all sit on the repo/datastore naming and migrate path:

1. A clean `repo migrate` leaves its temporary phase-1 delta base image on both machines, although the cutover push asks for it to be pruned.
2. `repo up` of a kube repo on a fork datastore (`<parent>:<tag>`) renders a StorageClass name, a node-affinity label key and three label values that the API server refuses.
3. `replicaSetNameFor` maps `shop:test` and a literal `shop-test` to the same set name and datastore fork tags, and nothing refuses the second one at creation.
4. The datastore placement arm of the mutating-verb presence check returns true without any check.
5. The ops-loop zot container image is pinned at 2.1.18 while the embedded zot is 2.1.23, and the image literal is invisible to `npm run pins`.

No existing plan covers these: `grep -rlI -E 'retain-base-prune|replicaSetNameFor|DSSlug' agent/plans` hits none, and the zot mentions in `agent/plans/_done/` (PLAN-pins-command, PLAN-retired-terms-submodule-scan, PLAN-renet-fetch-hardening) cover the embedded binary, not the container image literal.

## Design

**A. Prune without retain.** Split `retainDeltaBase` into `retainDeltaBase` (unchanged contract, runs only when `retainBase` is set) and `pruneDeltaBase`, which runs after every successful file/LUKS push whenever `retainBasePrune` is set and differs from `retainBase`. Both names are validated before use, as today. The remote runner becomes a package variable (`runRemoteBestEffortFn`) so a test observes the remote `rm` without SSH. The migrate cutover keeps passing only `retain-base-prune`; no new base is retained after a migrate, because the source is unmounted and removed and no later push will delta against it. Rejected: passing `retain-base` on the cutover too, which would leave a fresh base behind instead of the old one.

**B. One slug, owned by the datastore package.** Move the slug to `pkg/datastore/slug.go` as `datastore.Slug`, delete `kubecsi.DSSlug`, and point its three callers (`private/renet/pkg/kubecsi/driver.go:66`, `private/renet/pkg/kube/csidriver/objects.go`, `private/renet/pkg/kube/distro/label.go`) at it. `kube_templates.go` uses `datastore.Slug` for the StorageClass name, the label values at `:48,:238,:274`, and builds the node-affinity key through `distro.DatastoreNodeLabel` (or `kubecsi.TopologyKey`, whichever imports without a cycle) so the static-PV key cannot drift from the node label again. `private/renet/pkg/reporuntime/kube.go:138` names the slugged class. ConfigMap data and CSI `parameters.datastore` stay raw (Context 6).

**C. Collision refusal at creation, both layers.**
- CLI: a new `services/repo/repo-slug-collision.ts` exports `assertNoSlugCollision(newKey, existingKeys)`. The display key is the bare name for a `latest` grand and `name:tag` for a fork; two keys collide when their `repoKeySlug` matches and the keys differ. `registerNewRepo` and the fork registration call it before any write and throw a `ValidationError` (exit 2) naming both refs. One new i18n key `errors.repo.slugCollision` in all 13 `cli.json` locales.
- Renet: `datastore.Create` and `datastore.Fork` refuse, inside the same `WithRegistry` transaction, a new key whose `Slug` equals an existing key's `Slug`. The "ACCEPTED ALIASING" comment in `kubecsi/driver.go` is deleted with the function.
- No rename or migration of existing rows: there is one operator and no colliding pair exists in the operator's configs (C2 records the check in its commit body).

**D. Datastore presence through the existing precondition.** The datastore arm defers exactly like the machine arm, with `expect: repo_present`, so renet's `probeRepoState` answers from `<ds>/repos/<guid>` at `job start`. D1 first proves which machine datastore the vault of a datastore-arm job carries; if it is the machine default and not the named mount, the vault directive gains a `datastore` field that `executor-factory.ts` writes into the job's machine datastore. The `absentOk` arm stays docker-only (a converge-to-absent verb on a kube repo dispatches and renet answers). No new renet verb is needed.

**E. zot image pin through pins.** Add two `match` sites to `embed:zot` in `.ci/config/pins.json` (role `version`, regex `zot-linux-amd64:v(?<value>\d+\.\d+\.\d+)"`, one per file, `expect: 1`), then align both literals to 2.1.23 so `npm run pins -- verify` agrees. A later `npm run pins -- bump embed:zot` then moves binary and image together.

Out of scope: #42 router-on-cluster, the rehearse and replicate-remove live re-runs, the zot manifest-list commit failure (PLAN-zot-manifest-list-commit.md), and the other #523 items the audit closed.

## Risks

- Design B changes the rendered names for any datastore key that already holds `:`. No kube repo on a fork datastore has ever come up (the render fails today), so no live object carries the old name; a plain datastore name is unchanged by the slug.
- C refuses a name an operator could create yesterday. A pre-existing colliding pair would block nothing already registered (the check runs only on a new registration), and C2's commit body records that none exists.
- D1 may find that the vault carries the default datastore, which turns a two-line change into a directive field. The box is written to absorb that, not to descope it.
- A pruned base on the destination is also the only delta base a later `push` back to the source could have used. After a migrate the source copy is gone, so no such push exists.
