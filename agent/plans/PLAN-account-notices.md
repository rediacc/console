## Design 1: the notices store (A)
- **Table `account_notices`** (migration 0084), one row per recipient and episode: `id` text PK; `user_id` NOT NULL, FK users ON DELETE CASCADE; `org_id`, `team_id`, `subscription_id`, each nullable; `kind` (`repo_licence` | `backup_health` | `licence_renewal` | `cert_expiry` | `eval_expiry` | `terms_notice`); `severity` (`info` | `warning` | `critical`); `dedupe_key`, `payload` (JSON); `created_at` (the episode start), `updated_at`, `read_at`, `dismissed_at`. Unique `(user_id, kind, dedupe_key)`; index `(user_id, dismissed_at, updated_at)`; index `(updated_at)` for the sweep.
- **Scope.** USER_SCOPED, shard class `global` (same class as users, so the cascade holds). One scope-registry and one shard-router entry.
- **The payload holds GUIDs and dates only, never names.** `repo_licence`: `{counts: {hardExpired, refreshRecommended}, items: [{guid, grandGuid?, kind, sizeGb?, freshness, refreshRecommendedAt?, hardExpiresAt?, teamId?}]}`. `backup_health`: `{items: [{kind, lineageGuid, streamId?, storeId?, detail}]}`. `licence_renewal`: `{planCode, renewsAt}`. `cert_expiry`: `{track, certificateNumber, expiresAt}`. `eval_expiry`: `{planCode, expiresAt}`. `terms_notice`: `{version, effective}`.
- **Dedupe key per kind.** `repo_licence`: sha256 of the sorted `guid:freshness` list (the same GUIDs moving from refresh-recommended to hard-expired is a new set). `backup_health`: the digest's `dedupeKey`, or the UTC day. `licence_renewal`: `subscriptionId:expiresAt`. `cert_expiry`: the cert id. `eval_expiry`: the eval id. `terms_notice`: the version.
- **`NoticeService`** (src/services/notice.service.ts): `upsert(userId, {kind, dedupeKey, severity, orgId?, teamId?, subscriptionId?, payload}, now)` inserts, or on conflict updates `payload` and `updated_at` keeping `created_at` and `read_at`; returns `{id, createdAt, inserted}`. `list(userId, {cursor?, limit<=100, includeDismissed?})`, newest `updated_at` first, keyset cursor. `unreadCount(userId)`: not read, not dismissed, updated in the last 30 days. `markRead`, `markAllRead`, `dismiss` (another user's id is 404). `pruneRepoGuid(subscriptionId, guid)` takes the GUID out of every open `repo_licence` payload of that subscription; a payload left empty becomes dismissed. `purge(now)`: `DELETE ... WHERE id IN (SELECT id ... WHERE updated_at < ? LIMIT 500)`, repeated (the retention-sweep.service.ts shape).
- **Retention:** 180 days after `updated_at` (O3), from `runRetentionSweeps` (entry/cloudflare.ts:323-335).
- **Wire shapes** (fixed here, so S, C and W run in parallel): list `{notices: [{id, kind, severity, createdAt, updatedAt, readAt, dismissedAt, orgId, teamId, subscriptionId, payload}], nextCursor}`; `unread-count` `{count}`; `read` / `dismiss` `{id, readAt|dismissedAt}`; portal retire `{repositoryGuid, retired: true}` (same as the token route).

The token route keeps its path, scope and behaviour. The new session twin `POST /portal/subscription/repos/:guid/retire` is open to an org owner or admin, or a `team_admin` for a licence its team issued; a plain member gets 403; a licence that is not `hard_expired` gets 409 `LICENCE_NOT_EXPIRED` (Context 8).
- **Root trigger, `POST /admin/reminders/run`** (sessionAuth + `requireRole('root')`, src/routes/root.ts): body `{kinds?: ('repo'|'renewal'|'cert'|'eval')[]}`, runs `runDueReminders` for those kinds and returns counts. Idempotent inside one cadence bucket. The bench drill uses it because `/test` is dark on Workers (Context 6).

## Design 3: the mail redesign (B)
- **One digest shape**, `renderDigestEmail(locale, {subjectKey, titleKey, leadKey, sections: [{headingKey, count, consequenceKey?, lines[]}], fixLines[], noticesUrl})` in src/email/templates/digest.ts, used by the repo licence, backup health and renewal mails. A section with `count === 0` is not rendered. Every line is rendered (no slice, no `BACKUP_HEALTH_DIGEST_MAX_ITEMS`). Counts use `tCount(key, count, params, locale)`: `key.<Intl.PluralRules(locale).select(count)>`, falling back to `key.other`.
- **Repo licence mail**, to each recipient: subject "`{{count}}` repository licence(s) need attention in `{{orgName}}`"; one section per state: hard-expired ("resize, expand and backup push/pull stop until refreshed", Context 14), refresh recommended ("refresh before `{{date}}`"); each line `<guid[0:8]> · grand|fork · <size> GB · refresh by <date> · hard expiry <date>`, sorted by hard expiry; the fix: `rdc subscription refresh -m <machine>` or `rdc subscription refresh --repo <ref>`, then "`rdc subscription status` names each licence and its exact command", then "`rdc subscription retire <guid>` or Dismiss in the portal removes a licence whose repository is gone"; the link `${PUBLIC_SITE_URL}/account/notices`. No repo or machine name and no `machineId` in the mail.
- **Recipients.** Per subscription: org owners and admins get every non-valid item; each affected team's `team_admin`s get that team's items; per user the item sets are joined and the user gets one mail. `getRepoLicenseSummary` runs once per subscription; entries gain `teamId` (billing.service.ts:194, already computed as `entryTeamId`).
- **Cadence.** The episode is the recipient's `repo_licence` notice row: `created_at` is when this exact GUID set was first seen. With `d` whole UTC days since `created_at`, the bucket is `d<d>` for `d < 7`, otherwise `w<floor(d/7)>`; the fingerprint is `repo_licence:<subscriptionId>:<userId>:<setHash>:<bucket>` in `notification_reminder_log`. An unchanged set mails on days 0-6, then 7, 14, 21...; a changed set has a new hash and starts daily again.
- **Preferences.** Hard-expired sections need `repoExpiryDigest`, refresh sections `repoRefreshDigest`; with nothing left there is no mail. New keys `certExpiring` and `evalExpiring` (default true) gate the cert and eval mails (closes notification.service.ts:241). The notice row is written whatever the preference says.
- **Outcome.** Every send returns `'sent' | 'suppressed' | 'failed'`; `failed` is not recorded (the next run retries), `suppressed` is recorded (as the backup digest does, reminder.service.ts:418-424). Applies to repo licence, renewal, cert, eval and backup health.
- **Other producers** write their notice before mailing: backup health (one per org owner or admin per digest), renewal (one per owner or admin), cert (holder), eval (customer contact and partner), terms (one per user in `sendTermsNotices`). Backup health and renewal move to the digest shape; cert, eval and terms keep their templates and gain the notices link.
- **i18n.** `repoReminder` is replaced by `repoDigest.*` (subject, title, lead, section and plural keys, consequences, fix lines, retire line, notices link); `digestCommon.*` holds shared labels; `backupHealth.more` is removed. All 13 emails.json, naturalized (docs/i18n/CONVENTIONS.md section 2). Plural categories: en/de/es/et/fr/it/pt/tr one/other; ru one/few/many/other; ar zero/one/two/few/many/other; ja/ko/zh other. `check-account-email-templates.ts` learns `tCount`: every locale holds `.other` plus the categories `Intl.PluralRules` gives it.

## Design 5: CLI (D)
- **`rdc subscription notices [--all] [--unread] [--mark-read] [-o json]`** reads `GET /account/api/v1/notices`: by default undismissed notices of the last 30 days; `--all` walks every page, dismissed included; table of age, kind, severity and a one-line summary with names joined from the local config through `repoNamesByGuid` (short GUIDs when absent); `-o json` keeps the server payload with `name` and `machine` per item; `--mark-read` posts read for the listed ids. Plane `other`. No token -> `unreadyTokenDiagnostic`, as `status` does.
- **`rdc subscription retire <guid>`** posts to the existing token route through `services/account/license-retire.ts` (also used by `settleRepoLicense`, repo-delete-settle.ts:127-143). Accepts a full GUID or an 8+ character prefix matching exactly one licence in the server report; confirms with `askConfirm` naming the joined name or short GUID and its state; the global `--yes` skips the prompt; non-TTY without `--yes` refuses; a GUID still in the local config whose licence is not hard-expired is refused without `--force` (O1).
- **`rdc subscription status`** (account view) adds a per-licence table under the counts: name (`ref@machine`, or `<guid8>` with "not in this config"), kind, state, refresh by, hard expiry, and the exact fix command (`rdc subscription refresh --repo <ref>`, or `retire <guid8>` for a deleted repository). `-o json` gains `licences: [{guid, name, machine, kind, freshness, refreshRecommendedAt, hardExpiresAt, fix}]`. Names come from `configService.getCurrent()` through the shared join; `readConfigRepoGuids` is replaced.
- cli.json gets the new keys in all 13 locales; then the generated CLI contract, the command tree and the CLI docs.

## Design 6: mail volume and cost (F)
- For one subscription with a non-empty non-valid set: `A` = org owners and admins; `T_t` = the team_admins of affected team `t`; `U` = the distinct opted-in users in `A ∪ ⋃T_t`.
- **Before:** `A + Σ T_t` mails per day for as long as the set is non-empty; with hard-expired licences of deleted repositories, forever. Over `D` days: `D·(A + Σ T_t)`.
- **After:** over an episode of `D` days with an unchanged set, `U·(min(D,7) + max(0, ceil((D-7)/7)))`: D=30 -> 11U, D=365 -> 59U. Example: 2 admins and 3 affected teams with one team_admin each, one of whom is also an admin (U = 4): 150 mails over 30 days before, 44 after. Retire or Dismiss ends the episode for a licence whose repository is gone.
- **D1:** before, `3·(1+T_o)` summary queries per org per run; after, 3 per subscription plus `U` notice upserts and at most `U` log reads and writes, inside the per-tenant 500 writes/day budget. Notice rows grow by one per set change per recipient, capped by the 180-day sweep; a 200-licence payload is about 40 KB.
- **SES** at USD 0.10 per 1000 is negligible either way; the cadence bounds the volume, so no per-org rate limit is added.

## Open decisions (each default stands unless vetoed)
- O1 Retiring a live licence. Default: the portal refuses anything not hard-expired (409); the CLI refuses a GUID still in the local config whose licence is not hard-expired, unless `--force`. Reason: retirement is sticky (Context 8).
- O2 The token scope for notices. Default: `subscription:read`, which every CLI login holds; no new scope, no re-login.
- O3 Retention. Default: 180 days after the last update, read or not.
- O4 Episode reuse. A set that changes and then changes back returns to its old row (old `created_at`), so it mails weekly. Default: accepted.

## Risks
- **Root login on bench.** The drill needs a root session for `/admin/reminders/run`. If the bench root has two-factor on, D1 reuses the TOTP path of `rediacc_ci.ops.login_bench`; if that cannot work, the drill gets `--wait-cron` (waits for the 03:00 UTC tick of the deployed cron), and X2 says so.
- **The event log is tenant-sharded** (shard-router.ts `eventLog: 'tenant'`). The drill plants events through the D1 path `free_to_registered` uses, resolving the subscription's shard through `subscriptionShards` first.
- **Payload size.** Thousands of non-valid licences make payloads of hundreds of KB per recipient; E2's test plants 1000 items and asserts the upsert stays under the D1 row limit (2 MB); docs/d1-scaling-review.md is consulted if a real tenant nears 1 MB.
- **Names visible only for the active team's config.** A licence another team issued shows a short GUID; the history page states it.
- **No name may leak into mail.** The digest is built from the payload, whose type has no name field; E2 asserts no `machineId` in the body, and the drill asserts the planted repo name is absent from the captured mail.
- **Clean break.** `repoReminder.*` and `BACKUP_HEALTH_DIGEST_MAX_ITEMS` are deleted with no alias; the CLI `retire` and `notices` verbs need a CLI built from this tree.
