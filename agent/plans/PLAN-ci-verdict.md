## Design detail

### A. GREEN rule
1. `info["truncated"]` -> no-verdict. 2. `CI Complete` CheckRun COMPLETED+SUCCESS (rollup holds the latest per context, `wl_ci.py:195`). 3. no hard among blocking contexts. 4. liveness recomputed over BLOCKING contexts only (not GitHub's aggregate rollup state, `wl_ci.py:525`; reuse `_branch_rollup_state` idea `:333-346`). 5. no cancelled blocking context. Review gate is not part of GREEN (it starts after green+ready); print it as a separate `review:` line from `wl_ci.review_gate_row`.
Registering: `CI Complete` absent -> `running`, detail from `wl_ci.commit_ci_runs` (`:266-284`): run status + contexts registered, or "no Console CI run registered yet (pushed Ns ago)"; past `_noci_settled` grace on a PR head -> `no-ci` (exit 4) with the [skip ci] hint.
Cancel attribution order: watchdog evidence (Watchdog Monitor runs `created>=run.created_at` with display_title `Watchdog: run <id> `; parse `CI BUDGET VIOLATION: '(.+?)' ran ([\d.]+)m \(budget (\d+)m\)` and the `Watchdog: pipeline-cancelled` roster), then superseded (PR head != run head_sha), then timeout-kill ("has exceeded the maximum execution time"), then manual (human canceller), else unknown ("cause unknown; not proven superseded").
Tests red-first: selftest "THE 2026-10-02 FALSE GREEN" (only OBS Mirror contexts, all success -> running, names CI Complete) + old-logic proof; controls (full success -> green; truncated -> no-verdict; only Review Complete failing + CI Verdict in progress -> green); attribution fixture (104/33/29 + watchdog annotation -> red, detail has `watchdog budget` and the job, no "newer push"); superseded and unknown controls; hermetic end-to-end cases in `test_gate_ci_trace_branch.py`; Stop hook cases in `test_wl_ci_status.py` (absent CI Complete -> not ok; attributed budget cancel -> note); raise `wl_ci --selftest` floor.

### B. ci_diagnose
Functions: `run_jobs(run_id, attempt)` (steps with timestamps included), `first_failure(jobs)` (earliest failure/timed_out, skipping non-blocking and watchdog-excluded), `cancel_cause(run, pr_head)`, `job_log(job_id)` (cached at `${XDG_CACHE_HOME:-~/.cache}/ci-trace/logs/<job_id>.log` when completed; ANSI stripped), `failing_step_slice`, `excerpt` (`##[error]` + signature hits, ±3 lines, ≤3 hits, ≤8 lines each, 200-char clip), `log_gaps(log, min_s=120)` (top 3), `durations(job)` (vs `job_p90_minutes`), `history(job_name, n=5)` (on demand), `diagnose(run_id, pr_head) -> dict` (ci-verdict/v1), `render(d, budget_lines=12)`.
Signatures (category infra|code): CDN/registry 403/503/toomanyrequests; Bitwarden 5xx; runner shutdown / lost communication; package mirrors (Curl error, repomd.xml, Failed to download metadata, apt Failed to fetch); network ECONNRESET/ETIMEDOUT/unreachable; code (--- FAIL, FAILED, AssertionError, Error:, ✘, panic:). Output labels `infra-likely|code-likely|unknown`.
`ci-trace.py` loads it by file path (as it loads well_known, `ci-trace.py:42-50`). `_emit` (`:226-239`) and `wl_ci.ci_rows_text` print `ci-trace.py --job <id> --errors` instead of raw gh (update test_120's needles).
Tests: `.ci/rediacc_ci/tests/test_ci_diagnose.py` with redacted fixtures from run 36953549081 plus CDN 403, Bitwarden 5xx, runner shutdown and a code failure; hit + near-miss per signature; the 900 s gap found; step slice picks the failing step; render ≤12 lines and ≤1,500 chars on the largest fixture; anti-vacuity on min_s.

### C. Guard
`block_raw_ci_read.py`: CHAIN pre-bash, ORDER next free (highest today 49), OWN_SUITE=True; `shellscan._analyse(cmd).runs` with basename `gh` (descends `$(...)`, `sh -c`, eval, heredocs; prose in commit messages is not a run). Header cites the 2026-10-01 command-position precedent (#8e5a6452) and why read verbs differ from the text-matched watch registry. `CI_READ_VERBS` rows (match, use template, why, example, counter) beside REGISTRY in `sanctioned.py`; `check_sanctioned_registry.py` self-checks them, including that each `use` flag exists in `ci-trace.py --help`. Refusal format `BLOCKED (raw-ci-read): use: <exact ci-trace command>   why: ...`. No env bypass; `--job <id> --log` is the full-log route. EDGE_CASES ≥10 refusals (every row; `$(gh pr checks 591)`; `gh api .../logs --allow-escape-sequences | sed | grep`) and ≥10 allows (carve-outs, a commit message mentioning `gh pr checks`, `gh run download`). DEFECT turns a POST into a refusal. Golden via `regolden.py guards`; regolden ALL guards in the same commit (EDGE_CASES cross-feed under REDIACC_GUARD_DIFF_FULL=1). `ci_watch_recipe` check C scans docs for CI_READ_VERBS, so SKILL.md (all new flags, fix line 30, a Diagnosing section starting with `--why`), pr-babysitter.md (:107, :185, :189), ci-gates.md (:115, :131), TRAPS.md (:139, :160, :546-549), e2e-local.md (:75) change in the same commit. `wl_ci.adhoc_watch` stays as is.

### D. CI Verdict
Workflow: `ubuntu-slim`, timeout 10, permissions `{contents: read, actions: read, checks: write}`, sparse checkout `.ci/scripts` + `.ci/rediacc_ci`, concurrency per run id, step `PYTHONPATH=.ci python3 -m rediacc_ci.ci.publish_ci_verdict --run-id ... --attempt ... --head-sha ...`. Publisher: `diagnose`, upsert check-run (PATCH if exists else POST), conclusion always neutral, sanitised excerpts, posts on green too (overwrites a stale red), a failed diagnose posts `unknown` rather than crashing.
Schema `ci-verdict/v1`: `{schema, generator, generated_at, head_sha, run_id, attempt, workflow, conclusion, verdict, cause{kind, job, minutes, budget_min, watchdog_run}, first_failure{job_id, name, step, step_s, p90_s, category, signature, excerpt[]}, gaps[], next}`.
Non-blocking everywhere: `wl_ci.CI_NONBLOCKING_CONTEXTS` (`wl_ci.py:148`), `WATCHDOG_EXCLUDE_PATTERNS` (`watchdog-monitor.cjs:446-449` + yml env), `report-nightly-status.cjs:144`, `budget_report.py:468`, `_trace_run` filter (`ci-trace.py:164`).
Local: tracer reads `CI Verdict` only when run/attempt match, else computes locally; branch-keyed cache `<worklist>.civerdict-<sha1(branch)[:8]>`; `.claude/hooks/stop/wl_civerdict.py` called from `wl_checks.py` beside `ci_trouble` (before the multi-session skip), informational, once per session per (sha, run, attempt) via `<worklist>.civerdict-seen-<sid8>`; SessionStart line from the cache only (no network). Optional: watchdog enforced-budget message carries the job's last log line and its age (`getLogTail`, `watchdog-monitor.cjs:907`).
Tests: `test_ci_publish_verdict.py` (upsert, green overwrites red, neutral, sanitise, failed diagnose posts unknown); workflow gates accept the file; `test_wl_ci_verdict_surface.py` (two sessions each notified once; same key silent; new attempt re-notifies; SessionStart makes zero gh calls); selftest that CI Verdict never makes live/hard true.

### E. renet
Stream markers (`sshCommandStreamMarkers` replacing `sshCommandOutput` + after-the-fact `LogSetupMarkers`, `service.go:136-140`); heartbeat in `setupPhase` (`pkg_install_retry.go:182-189`) with the last line from a mutex-guarded tee in `runPkgInstallCaptured`; bounded `--downloadonly`/`--download-only` then cached install; `pkgIndexRefresh` before the first attempt; minrate env; per-phase deadline error naming phase, elapsed and last line. Go tests in `pkg_install_retry_test.go` and `service_test.go`.
