## Operator ruling (2026-10-03), condensed

1. The Stop hook blocks only on: (a) the live PR's plan boxes (the plan named by the PR body's `Plan:` line, or by the QUEUE.md head before the body has one); (b) that PR's CI and its per-commit and PR reviews; (c) worklist items attached to that plan's epic (`agent/worklist/epics.jsonl`, `PR-TASK:` trailers, `wl_epic`); (d) the loop's own duties: STATE.md freshness, dead or expired watches and leases, unread writer reports, findings this session raised, hook integrity, expired `[?]` DEFAULTs.
2. Every other open item and every other plan appears in ONE line as queued (a count plus a pointer to `worklist.py --list --open`). It never blocks.
3. "Next plan" (the plan-backlog advisory) reads QUEUE.md: Promoted first, then Generated.
4. The plan-unimplemented ("PLANS ARE NOT IMPLEMENTED ... ALL") and plan-adopted pushes are scoped to the PR's plan.
5. Backlog migration: session d778be9d's open items move onto the epic of the plan that owns them, or are deferred with a DEFAULT. The lead does this in one pass. Item #93798daa (held plans after open ones in plan priority) folds in.
6. Addition (operator, 2026-10-03): after the PR's plan is finished and the PR is MERGED, the hook blocks until the loop continues. That means the next MMDD-N is cut from fresh main, the next QUEUE.md plan becomes the queue head and the PR `Plan:` line, its first box is worked, and the new PR is opened. While QUEUE.md has an entry, the hook never reports "nothing to do". With no live PR and a non-empty queue, the block names the next plan and the exact next command. With an empty queue it allows.
7. Addition (operator, 2026-10-03, amending this plan before implementation): one PR per plan, plus the plans the operator puts in the same PR, plus the plans the PR's plan depends on. The PR's plan set is its `Plan:` plans (every one when the body carries `Operational-Reason:`) and every UNFINISHED plan they depend on, transitively, through `Depends-On:` headers and task refs. A finished prerequisite is not in the set; a held one is. Prerequisites order before the plans that need them. The hook, the CI gate (P-A1) and the merge gate count the same set.

## Design

### 1. One resolver: `wl_prscope.loop_state`

A new module `.claude/hooks/stop/wl_prscope.py` computes, once per stop, `LoopState(kind, branch, pr, plans, epic_items, next_plan, queue_head, stale_promoted, next_branch, reason)`:

- `kind` values:
  - `live`: the checkout is on a `commit_policy` branch_shape name (`^[0-9]{4}-[0-9]+$`) with an OPEN PR.
  - `no-pr`: on such a branch, and it has no PR yet.
  - `merged`: on such a branch, and its newest PR is MERGED with none open.
  - `on-main`: on main with no live branch.
  - `off-loop`: any other branch, detached HEAD, or not the console.
  - `unreadable`: the PR read failed.
- `plans`: for `live`, the body's own `Plan:` values (`plan_gate.body_plans(plan_gate.own_text(body))`). If the body names none yet, `(plan_gate.queue_head(root),)`, the value refresh_pr_body will write. A multi-plan body with `Operational-Reason:` scopes to every plan it names. For `no-pr`, `merged` and `on-main`: empty.
- `plans` WITH PREREQUISITES (ruling 7): the set above is closed over unfinished prerequisites using the existing dependency graph, `wl_plandeps.Graph.load(root)` with `resolve` for each `Depends-On:` edge and task ref and `is_complete` to drop a finished one (all boxes ticked, or a finished Status). A held prerequisite stays in. The tuple is ordered prerequisites first (a deepest-first walk), the same rule `wl_planqueue` uses when it pulls a prerequisite to the rank of what needs it. `Graph.cycles()` and an unresolvable dependency are carried in `reason` with the offending path and reported in the block, never dropped. `prereqs` names the members that are not the PR's own `Plan:` plans.
- `epic_items`: the union of `covers` of every epic whose new `plan` field is in `plans` (section 3), prerequisites included.
- `next_plan`: the first `plan_gate.queue(root)` entry that exists, is not in `plans`, and has `plan_gate.open_boxes(...)[0] > 0`. This is the same reader the merge gate and P-A1 use, so the three cannot disagree.
- `stale_promoted`: set when `queue_head` exists but has zero open boxes (a merged Promoted entry nobody removed by hand). refresh_pr_body would write it as the next PR's `Plan:`, so the loop-next block names its removal.
- `next_branch`: `commit_policy.next_branch_name(root, today, gh=True)` with the same UTC date `block_second_branch` uses. Empty when gh is down; the message then prints the step-7 computation.

There is ONE PR read. `wl_ci.pr_link(root, worklist, session_id, branch)` is a single GraphQL query, `pullRequests(headRefName, states:[OPEN,MERGED,CLOSED], first:5, orderBy UPDATED_AT DESC){number state body mergedAt closedAt}`, cached for `wl_standdown.FOCUS_PR_TTL_S` per branch. `focus_pr_end` is rewritten on top of it, so focus and the loop read the same node. This is not a second reader.

### 2. Item scope inside `classify_items`, not after it

`classify_items(..., in_scope=None)` takes a predicate over the record. In production it is `rec["id"] in state.epic_items`. An open record that fails the predicate goes to a new fifth return value `queued` instead of `open_items`. Two exceptions stay in `open_items` whatever the predicate says, because a dead claim is a loop duty (ruling 1d): a fail-closed lease (`.claude/hooks/stop/wl_store.py:1453`) and a worker:lead item with nothing live. `in_scope=None` means everything is in scope, which is the state for `off-loop`.

Every consumer of `open_items` (open-items, idle-stall, unblocked-claim, solo-grind, remaining_lines, actionable_remains, the guide) is therefore scoped by construction, with no per-check filter. `guided_slice` gets the same predicate and lists in-scope items only, then ends with the queued line.

### 3. Epics carry their plan

An epic record gains `plan` (`agent/plans/PLAN-<slug>.md`). The verbs are `--epic <me> new [--plan <rel>] <title>` and `--epic <me> plan <epic-id> <rel>`; `list` prints the plan. A rel that does not exist under `agent/plans/` is refused. Titles are never parsed (clean break): an epic without `plan` belongs to no plan until it is given one, and SC12 gives them.

### 4. A third keep-list profile: `PR_LOOP`

`PR_LOOP` is added to `wl_standdown`. It is applied when neither FOCUS nor CAP_WAIT holds and `kind != off-loop`. FOCUS keeps governing a declared wind-down, and CAP_WAIT a saturated roster, because both are narrower declarations. Because it is a keep-list, a check added later stands down by default, which is the literal "blocks only on". Keeps:

- `CORE`, by reference: hook integrity, unread reports, the findings ledger (`completion`, `found-not-fixed`, `deferred-finding`, `deflected-finding`), the roster's dead, silent and unleased writers, and `commit-review`.
- `_FOCUS_ONLY`, by reference: `ci-red`, `ci-unreadable`, `pr-unreadable`, `pr-stale`, `diverged`, `bg-report`, `pr-review`. `focus-pr-items` is inert outside focus.
- `_PR_FINISH`.
- `COMPACTION_KEYS` as full keeps (STATE.md freshness at any band, ruling 1d).
- `_PR_LOOP_ONLY = {"open-items", "idle-stall", "unblocked-claim", "plan-unimplemented", "plan-adopted", "loop-next", "defer-expired"}`.

Each literal still appears once in the file.

Dropped keys reuse focus mode's parking. Their bases are counted in `state_doc["prscope"]["parked"]`. `focus_ended_line`'s ranking and cap are lifted into one `parked_line(counts, cap)` helper that both profiles call. The result is ONE line, `M.N_PR_SCOPE`, appended to the guide on every stop. The guide is not rotated, so the line cannot be starved:

With prerequisites in scope the line names them: `PR #N works PLAN-a.md (+ PLAN-b.md, a prerequisite). Queued, not blocking: ...`. Without:

`PR #592 works PLAN-github-pr-review-restore.md. Queued, not blocking: 37 item(s) outside its epic, 39 other plan(s) in QUEUE.md (next: PLAN-plan-preflight.md); stood down: solo-grind, no-remaining, plan-drift. See worklist.py --list --open d778be9d.`

CI is armed from the live branch. For `kind == live`, the `ref` passed to `pr_body_freshness`, `wl_civerdict.note` and `ci_trouble` is `state.branch` when focus has not set one. `owned=True` when the PR's plan `Owner:` is this session (`C.owned_by_me`), which keeps the multi-session skip for a peer's PR. `WORKLIST_PUBLISH_REF` is not touched (see Open decisions).

### 5. Plan pushes scoped to the PR's plan

- **plan-adopted and plan-tasks:** the `_pf_rows` loop skips rows whose rel is not in `state.plans`. Other plans fall into the queued line's plan count.
- **plan-unimplemented:** `wl_planenforce.evaluate(..., scope=state.plans)`. Rows are restricted to the PR's plans, and there is no ceiling, matching P-A1's 2026-09-26 ruling ("no threshold"). It blocks while the PR's plan has an open box AND no background task of this session is live. With a writer or `ci-trace --wait` running, the same body rides the queue as an advisory. The block names the first open box (`first_box`) of the first plan in `state.plans`, which is the deepest unfinished prerequisite when one exists. The `plan-clock` warn advisory and the hook's calls to `assess` are removed. `load_clock`, `ceiling` and `CLOCK_KEYS` stay exported because `.ci/scripts/quality/check_plan_implementation.py:86` imports them.
- **plan-backlog:** `wl_backlog.next_plan` is replaced by a QUEUE.md read. It names `state.next_plan` with its position ("Promoted 2" / "Generated 1"), its first open box and its rank tag, and it is never a vadd. The ownership filter, the mtime order and the `backlog_nominated` cap are deleted. `_open_boxes` and `_dead_peer` stay, because wl_planenforce imports them.

### 6. Held plans after unheld ones (#93798daa)

- `wl_planqueue.live_plans` keys become `(held, tier, op, ai, rel)`. A prerequisite inherits the least-held value of everything that needs it, the way it already inherits tier, so a held prerequisite of an unheld plan still comes first.
- `OrderCtx.plan_key` becomes `(blocked, held, op, ai)`. The unlinked rank becomes `(0, 0, *UNLINKED_RANK)`, and `wl_planorder._tag` unpacks four values.
- QUEUE.md's header prose changes from "does not change the order" to "held plans after unheld ones, prerequisites excepted". The Generated block is regenerated.

### 7. The post-merge state: `loop-next`

One T_MISSION key, `loop-next`, is computed from `LoopState` after the CI read. It never fires on an empty queue (`next_plan == ""` and, for `live`, no open box). It downgrades to an advisory while a background task of this session is live (a `ci-trace --wait`, a pr-merge watch), because a waited-on step is not a stall. Arms:

| kind | condition | the block names |
|---|---|---|
| `merged` | queue has `next_plan` | PR #n merged. Then pr-merge step 7 verbatim: `git switch main && git pull --ff-only`, `git push origin --delete <b>` only while `origin/<b>` exists, `git fetch origin --prune`, `git branch -D <b>`, `git switch -c <next_branch>`. Then `stale_promoted` removal if set, then "work <next_plan>'s first box: <text>". |
| `on-main` | queue has `next_plan`, no live branch | `git switch -c <next_branch>` (`block_second_branch` admits exactly this name), then the plan and first box. |
| `no-pr` | queue has `next_plan` or the branch carries commits | No commits ahead of origin/main: work `queue_head`'s first box. Otherwise: the ci:quick receipt, the push, then `gh pr create --draft --base main --head <b>` (refresh_pr_body writes `Plan:`). |
| `live` | every box of every plan in `plans`, prerequisites included, ticked | `/pr-merge` (the finish condition), unless `pr-finish` already fired this stop. A PR whose own plan is ticked while a prerequisite has an open box never gets `/pr-merge`; the block names the prerequisite's first open box. |
| `unreadable` | the PR read failed | The failing read, bounded like ci-red: at most `wl_ci.CI_MAX_BLOCKS` stops per error signature, then an advisory. |

`stale_promoted` set with `kind == live` adds nothing: the PR's own `Plan:` line governs.

After a merge, `next_plan` skips a queued plan whose prerequisites are unfinished unless the first unfinished prerequisite is itself the next queue entry; when it is skipped, the prerequisite is the next plan, so the loop never starts a plan whose dependency is open.

### 8. One plan set for the hook, the CI gate and the merge gate (ruling 7)

Today `check_plan_implementation.clock_scope` (P-A1) clocks the queue head plus the plans the branch ticked, and `plan_gate.plan_merge_refusal` reads the body's `Plan:` lines. Neither counts prerequisites. If only the hook did, the hook would block on a prerequisite that CI and the merge gate let through, or the merge would land with a prerequisite open while the hook still pointed at it. So both gates take the same closure: `plan_gate` gains one `pr_plan_set(root, body)` (Plan: lines, or the queue head, closed over unfinished prerequisites through `wl_plandeps.Graph`), and `wl_prscope.loop_state`, `plan_merge_refusal` and `clock_scope` all call it. One function, three readers (SC14).

- **Held reordering moves the Generated queue.** The Promoted list wins and is untouched.
