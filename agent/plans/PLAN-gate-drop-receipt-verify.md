## Problem

On 2026-10-03 `npm run ci:quick` DROPPED `check:ci-plan-record`, a slow gate the diff touched (`agent/INDEX.md` matches its `paths`, scripts/ci-runner/manifest.ts:2056), because it writes the tree. The receipt (`.ci/cache/prepush-receipt.json`) said nothing about the drop, `block_unverified_push` allowed the push, and CI run 37129843955 went red on exactly that gate (R8: `agent/INDEX.md` not equal to its render).

A second cause on the same push: the push clone's branch tracked `origin/0930-1` (an already merged branch), so quick-select diffed against that merge-base (244 files) without saying it had chosen a ref named for another branch.

## Root causes

R1. **The drop list is printed and then lost.** `admitWithinBudget` builds `dropped` with reasons (scripts/ci-runner/quick-select.ts:260-293; tree writers at :263-266, before pricing). `quickDiffAdmit` prints each drop (scripts/ci-runner/run.ts:749-752) and returns only `verdict.admitted` (:757). `Selection` has no slot for it (scripts/ci-runner/run.ts:448-454) and `select()` copies only `slowAdmitted` (:670-674), so the receipt written at scripts/ci-runner/run.ts:2060-2102 (interface :1712-1759) cannot name the drops.

R2. **The guard has nothing to refuse on.** It checks the tree (.claude/rediacc_hooks/guards/block_unverified_push.py:782), `whole` (:789-792), red-or-carried (:800-815), and only warns on `blocked` (:820-826). A drop does not narrow the lane (`narrowingFlags` covers only `--only/--skip/--changed`, scripts/ci-runner/run.ts:1791-1797), so the receipt says `whole: true`. The suggested re-run (`run.ts --only <id>`, scripts/ci-runner/run.ts:751) writes no receipt (receipts are written only under `opts.quick && !opts.manifest`, scripts/ci-runner/run.ts:2058), and a narrowed run never replaces a whole receipt (scripts/ci-runner/run.ts:1823-1830). A dropped gate cannot be proven run, and the guard never asks.

R3. **`check:ci-plan-record` is a tree writer only because of its census append.** It is declared `mutex: ['tree:repo']` + `writesTree` (scripts/ci-runner/manifest.ts:2049-2051; scripts/ci-runner/gates.lock.json:2129) because `census_append` appends to the tracked `agent/ledgers/census-plan-record.jsonl` (.ci/scripts/quality/check_plan_record.py:906-912), called on every real-tree run (:1845). The census was a two-week advisory measurement (.ci/scripts/quality/check_plan_record.py:60), and `--census-report` already reads `span 26.46 day(s) of 14 -- window ELAPSED` (376 rows). The verdict itself (R1-R9, RB, RQ) writes nothing without `--update`.

R4. **"The last push" trusts an upstream named for another branch.** `resolvePushBase` tries `@{push}`, `@{upstream}`, `origin/<branch>`, `origin/main` (scripts/ci-runner/quick-select.ts:314-320) and returns the first that resolves (:322-329) without comparing its name (:327) to `branch`. The result is inclusive, so nothing was missed, but it is wider than it should be (more budget drops) and silent.

## Design

**D1. Record touched-but-dropped gates.** `quickDiffAdmit` returns `{ admitted, droppedTouched, pushBase }`. Each `droppedTouched` entry is `{ id, why, reason, kind: 'tree'|'budget'|'unpriced', run }`, where `why` is the touch reason from `touchedSlow` (scripts/ci-runner/run.ts:744) and `run` is the exact command, carrying `--receipt-out <same path>` when this run had one. `kind` comes from `admitWithinBudget` (`BudgetVerdict.dropped`, scripts/ci-runner/quick-select.ts:229; set at :265 tree, :270 unpriced, :285 budget). `Selection` gains `droppedTouched?` and `pushBase?`. The receipt gains `droppedTouched: DroppedTouched[]` (always written, `[]` when nothing dropped), `droppedVerified: Record<id, {exitCode, headTree, finishedAt, judgedRoot, stable}>` (starts `{}`), and `pushBase: {ref, via, mergeBase, warnings}`. The guard reads only the first two. Untouched deferrals stay out of `droppedTouched`.

**D2. The guard refuses outstanding drops; a narrowed run can clear them.**
- Runner: a `--only` run MERGES into a whole receipt (never replaces it) when the receipt at `receiptPathFor(opts)` is `whole: true`, its `headTree` equals this run's `receiptTree(start, end)`, and every selected id is in its `droppedTouched`. Each result lands in `droppedVerified`, failures append to `failed`, findings merge, `exitCode` takes the worst. The `opts.quick` condition (scripts/ci-runner/run.ts:2058) is lifted for this merge only; every other narrowed run keeps today's "kept" behaviour (scripts/ci-runner/run.ts:1833-1837).
- Guard: after the `whole` check (:789), before the carried check (:800), `outstanding` = ids in `droppedTouched` with no `droppedVerified` entry at the same tree and exitCode 0. Non-empty refuses, naming each id with its `reason` and `run`. A missing `droppedTouched` refuses (fail closed, as `whole` does, header :20). A failed re-run is already in `failed`, which `carried_verdict` handles unchanged.
- One file, not a per-gate receipt: the guard's stated cost is one `git rev-parse` and one file read (:7), and a second file needs its own tree keying and pruning.
- Addition: in a clean, disposable clone (`opts.receiptOut` resolves outside `REPO_ROOT` and `git status --porcelain` is empty at selection), tree-writing gates are admitted inside the budget. `treeWriteRefusal` (scripts/ci-runner/run.ts:527-532) takes a `disposable` flag and prints `+ SELECTED <id> (tree writer; disposable clone, receipt -> <path>)`. The stable-tree warning (scripts/ci-runner/run.ts:2050-2055) names the admitted writers rather than hiding them. This alone is not enough: the main checkout and budget drops still need the guard clause.

**D3. The census append becomes opt-in, so `check:ci-plan-record` stops writing the tree.** Split `census_append` (.ci/scripts/quality/check_plan_record.py:843): floors 1-2 (:867-881) become a pure `census_check` that runs on every invocation; floors 3-4, the append and its read-back (:883-930), run only under `--census`. `gate_tree_writes` then classifies the append as MODE-GATED (.ci/rediacc_ci/quality/gate_tree_writes.py:14). Drop `mutex: ['tree:repo']` and `writesTree` from scripts/ci-runner/manifest.ts:2049-2051 together and regenerate the lock (the registration is checked both ways, .ci/rediacc_ci/quality/gate_tree_writes.py:22). `PLAN_RECORD_CENSUS_EVERY_RUN` (:886) stays, honoured only under `--census`; its registrations (`.ci/config/env-manifest.json:574`, `.ci/config/python-env-registry.json:1760`) stay valid. After this the 2026-10-03 diff would have SELECTED the gate (about 40 s wall, scripts/ci-runner/manifest.ts:2042, against a 90 s ceiling).

**D4. The push base names this branch, or says it does not.** Order becomes `@{push}`, `origin/<branch>`, `@{upstream}`, `origin/main`. `@{push}` and `@{upstream}` count only when their `--abbrev-ref` name (scripts/ci-runner/quick-select.ts:327), remote prefix stripped, equals `branch`; a mismatch is skipped and recorded in a new `BaseResolution.warnings` (e.g. `@{upstream} is origin/0930-1, not origin/<branch>; ignored`). `changedSinceLastPush` (scripts/ci-runner/run.ts:482-508) adds the warnings to `label`, and `quickDiffAdmit` prints them on a `WARNING` line. Nothing matching falls to `origin/main`, still inclusive.
