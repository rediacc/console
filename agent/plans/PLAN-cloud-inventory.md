## Design

**The registry is a tracked JSON file, `.ci/config/cloud-inventory.json`, not an append-only ledger.** A resource has a lifecycle (registered, expired, deleted), and the gate must read the current set at a tree; a ledger would need a fold on every read and could not be reviewed in a diff. Each row: `kind` (script, d1, bucket, queue, container, do, pages), `name` (or a `pattern` for name families such as `pr-<n>`), `owner` (the code path or plan that creates it), `purpose`, `created_at` (UTC, from `date -u`), `ttl_hours` (or `permanent` for a row a deploy config carries), and `class` (`test|drill|preview|lab`). The file is written only by `.ci/rediacc_ci/housekeeping/cf_inventory.py` (`register`, `expire`, `forget`), never by hand.

**The create helper** (`cf_inventory.create(kind, name, owner, purpose, ttl_hours)`) registers first and then runs the wrangler or API create, so a crash between the two leaves a registered row the reaper can expire, never an unregistered resource. Test, drill and preview code calls it; production deploy code keeps its wrangler configs, which the gate already reads as the carrying set.

**Company resources are never reaped by inference.** A name shaped like a company (the enterprise naming in names.py) is masked in output and excluded from the reaper unless a row registers it with `class: test` or `lab`.

### The gate, its baseline, the hook and the Stop-hook report

**The gate.** `.ci/rediacc_ci/quality/deploy_inventory.py`, the deploy-inventory check whose package.json name DI2 sets and DI3 registers (reuse kind `network`, so PLAN-ciquick-gate-contract.md K2 places it beside INV2's leftovers check in the preflight). Rules: M1 a required cell missing from a row; M2 a capability whose consumer does not read the inventory; M3 a reference that resolves to nothing, a non-template wrangler config with no row, a cron string or `schedule:` entry with no cron row, or a row naming a config that does not exist; M4 a literal tuple of every regions.json id in tracked non-test source outside the reader. The static half always runs; the company half reads the control D1 through registry.py under `bws_env exec --profile deploy-workers`, and an unreadable company listing is UNCHECKED, exit 2, after the static verdict prints. Zero target rows, zero regions read or zero capabilities parsed is CANNOT RUN, never green. Every run writes `.ci/cache/deploy-inventory/last.json` for the Stop hook and prints its shape (rows per kind, cells judged, cells baselined, companies judged).

**The control comes first.** `--selftest` and the test file plant, before any rule is written: a `shared-region` row lacking `probe` (red, naming row and capability); a cron string added to a scratch wrangler config with no cron row (red); a company with no coverage (red, printed masked); a consumer that iterates its own list (M2 red); each plant removed (green).

**The baseline.** `.ci/policy/deploy-inventory-baseline.json`, shrink-only, seeded from the first real run with every row printed in the box evidence. Ids hash the row id and the capability (a company row hashes its opaque id), never a line number. A new missing cell fails, a baselined cell that turns green fails until drained, and every drain diffs the old and new sets and asserts the added side is empty (the composition trap in .claude/agents/gate-author.md).

**The hook.** Two guards, `block_deploy_target_without_row.py` (chain `pre-edit`) and `block_deploy_target_without_row_shell.py` (chain `pre-bash`), each with its own `test-` suite. The pre-edit guard refuses a new non-template `workers/*/wrangler*.toml` or `private/account/wrangler*.toml`, a new `crons` string in a wrangler config and a new `schedule:` entry in a workflow when no inventory row names it, and prints the cf_inventory.py verb that adds the row. The pre-bash guard refuses the same writes made through the shell, and `enterprise add` (.ci/rediacc_ci/enterprise/cli.py:604) while the `enterprise-company` family row is missing or lacks a declaration for a capability of its kind. A new company still turns its cells red in the gate until its coverage exists, which is the order's first proof. The guards are disjoint from INV5's `block_cf_create_outside_inventory.py`, which watches test-resource creates.

**The Stop-hook report.** `.claude/hooks/stop/wl_deployinv.py` reads `.ci/cache/deploy-inventory/last.json` and the static half (no network on a stop) and prints the missing cells grouped by row, companies masked, with the verb or plan box that closes each. Effort key `deploy-inventory`: advise at `low`, block at `high` when a missing cell is not in the baseline. The wl_checks.py block and the effort.json key are lead edits (DI8), because those files belong to PLAN-preprod-simulation.md and PLAN-ciquick-gate-contract.md.
