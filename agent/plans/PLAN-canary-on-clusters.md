Cluster install puts `rediacc-router` on the cluster machine and points it at the cluster's kubeconfig, so `rdc repo canary` works on cluster repos. Proof first on a lab cluster, then a real Linode run started from the operator's shell.

## Ask

`rdc repo canary create|weight` applies a canary Service carrying `rediacc.canary_of` and `rediacc.weight` to a cluster repo, and the router's `applyCanaryWeights` would turn those into a Traefik weighted split. Two halves are missing: no `rediacc-router` is started on cluster machines, and the router's kubeconfig glob predates the named-datastore layout, so it finds no cluster at all. This plan closes both, proves the split on a lab cluster with a new e2e assertion, then on a Linode cluster with zero billable survivors after teardown.

## Design

**D1. One router per cluster, on the control node.** Only `servers[0]` holds the admin kubeconfig (Context 3), Traefik and the router share host networking, and `cluster_spans_machines=false` already anchors routes on one machine. Agents need no router in v1. A router per node (the `cluster_spans_machines=true` flip, with a read-only ServiceAccount kubeconfig copied to agents) is out of scope and stays in issue #523 as the multi-node follow-up.

**D2. Discovery reads the one live layout.** `DefaultKubeconfigPattern` becomes `/mnt/rediacc-ds/ds-control-*/.rediacc/k3s/kubeconfig.yaml`. Clean break: the old glob matches nothing (Context 2), so it is replaced, not kept beside. Fork clusters attached on the same machine have their own `ds-control-<fork>` and their own cluster label, so their routes do not collide. No explicit config file: the datastore name is already the registry, and a second source would drift.

**D3. `renet kube install --role server` ensures the router.** After k3s and CSI succeed, a new `ensureClusterRouter` (in `cmd/renet/kube_install_router.go`) calls `proxy.Manager.IsRouterServiceInstalled`; when absent it runs `InstallRouterService` and `StartRouterService`; when present and inactive it starts it; when active it does nothing, since the router re-globs on every refresh tick (`--refresh-interval=3`). The JSON output gains `"router": "installed"|"started"|"present"`. A router failure fails the install with the unit status in the message; it is not a warning, because a cluster with no router silently loses every route. `kube uninstall` leaves the router alone: it also serves docker repos.

**D4. Proof of the split, not just of the config.** The e2e reads `/routes.json` for the weighted service, then sends N=200 requests through Traefik with the route's Host header against the control node and counts which backend answered (each Deployment echoes its own name). Weight 30 must land 30% plus or minus 10 points; weight 100 must land 200 of 200 on the canary.

**D5. Linode leg is operator-run.** A new `canary` phase in `linode_cluster_validation.py` runs between `provision` and `destroy`: `rdc repo up` of a two-Deployment fixture, `rdc repo canary create --weight 30`, the D4 count against the control node's public IP with the Host header (no DNS or certificate needed), then `weight 100`, then `remove`. `idempotency` gains the phase. Billable phases stay behind `--yes`, and the run starts from the operator's shell because `rdc cluster create/destroy` needs `REDIACC_ALLOW_CLUSTER_OPS` set in the launching shell (ancestry-verified).

## Risks

- **A router installed where the operator did not want one.** A cluster control node with no infra push gets a router serving `renet.local` routes on port 7111 and nothing else. That is inert until Traefik runs, which is the intended cost of D3.
- **Router install on a machine whose router runs a different binary.** `InstallRouterService` re-renders the unit from the running renet; on a machine with an active router D3 does nothing, so it never restarts a live router mid-install.
- **The split window is statistical.** 200 requests at 30% give a standard deviation near 3.2 points, so a 10-point window fails by chance about once in 10^4 runs.
- **Lab collision.** VM 11 and 21-23 belong to other work (Context 12); C0 and C4 must pick a VM no session holds, or wait.
- **Linode cost and leftovers.** C6 is billable; `verify` runs after `destroy` in the same invocation, and a non-zero survivor count is exit 4, which the operator resolves before ticking.
