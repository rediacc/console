## Ask

The stop hook's regression-gate cap (operator ruling 2026-09-05) turns the eighth and later gate demands on a branch into a `debt` record instead of a block. The design (`git show 687dd4b63bfe7725667ff76f0a23cde9f613bd56`, sections Q2-Q4 and 8) had three more steps: materialize each due debt as a real worklist item, a CI gate that fails while a debt stays unpaid, and docs naming the exception. None of them landed, and the compacted record says "implementation is deployed", which is wrong for steps 4-6. This plan builds the missing half and imports the 103 existing debts without flooding the worklist.

## Design

**D1. Due means "not the live branch" or "past grace".** The one-branch rule (CLAUDE.md section 1) means a ledger whose branch is not `C.git_branch(root)` belongs to a branch that landed or was abandoned; either way it is due. `branch_merged` is replaced by `debt_due(record, live_branch, now)`: true when `record.br != live_branch` or `at + REGGATE_DEBT_GRACE_MIN <= now`. `main.jsonl` debts are due by grace alone. Clean break: `branch_merged` and its HEAD probe are deleted; `budget_state` resets the counter when the ledger's branch is not the live one.

**D2. The cap gets its cap.** `REGGATE_MAX_DEBTS` (env `WORKLIST_REGGATE_MAX_DEBTS`, default 5, floor 1). Past five outstanding debts on the live branch, the cap stops deferring and the demand blocks normally, as design Q4.2 specified. The missing `root=root` on `charge` is fixed in the same edit.

**D3. Materialize once.** On every full stop the hook folds every `agent/reggate/<branch>.jsonl` (skipping `*.*.jsonl`). For each debt that is due, undischarged, unretired and has no `materialize` record, it calls `S.add_items` once (one append under one lock), then appends `{"kind":"materialize","sig":...,"item":<id>}`. The item text is `reggate-debt:<sig8> (<me8>) <blind_spot verbatim> -- branch <br>, surface <surface>, named artifact <artifact>`. A debt on the live branch is attached to the live PR plan's epic, so it blocks like any open item there. A debt on any other branch is attached to one backlog epic carrying this plan (`worklist.py --epic <me> new --plan agent/plans/PLAN-reggate-debt-collection.md "reggate debt backlog"`), so it is one queued line until this plan is the live PR's plan.

**D4. Discharge is artifact-only and hook-only.** `discharge_scan` tries each undischarged debt's candidate paths: the debt's own `artifact`, plus any `artifact:<path>` token in the item's update notes. A candidate proves the debt when the path exists, changed after the debt's `at` (dirty in this tree, or touched by a commit whose committer date is later than `at`, from `git log -1 --format=%cI -- <path>`), and, when it matches `CHECK_SCRIPT_GLOBS`, is reachable through `gate_reachable`. On proof the hook appends `{"kind":"discharge","sig","artifact","proof"}` and ticks the item with `discharge:<sig8> <artifact>`. A hand tick writes nothing to the ledger, so the gate still fails. There is no CLI verb that writes `discharge`. The commit-date branch is weaker than the dirty-tree proof, and says so in the record's `proof` text: it shows a case was written after the debt, not that it fails on the defect.

**D5. Retire needs an operator minute.** A debt whose subject is gone (for example 25 hooks-surface debts name `.claude/hooks/test-hooks.sh`, which no longer exists) cannot be paid by an artifact. `worklist.py --reggate-retire <me> <sig8> ASKED:<YYYY-MM-DDTHH:MM>Z <reason>` appends `retire` only when that minute matches an operator answer in the transcript, the same check `--review-mark waived` uses. The gate counts `retire` as paid only with that stamp. This is the one escape, named here and in suppressions.md.

**D6. The CI gate.** `.ci/scripts/quality/check_reggate_debt.py`, Python rather than the design's `scripts/check-reggate-debt.ts` because `.ci` is Python (language ruling 7) and the gate must fold ledgers with the same `wl_reggate` reader the hook uses (one fold, no twin). It runs its `--selftest` first in-process and exits 1 if a control cannot fire. Findings:
- RD1 a due debt with no `discharge` and no stamped `retire`, not listed in the legacy baseline;
- RD2 more than `REGGATE_MAX_DEBTS` outstanding on one branch, outside the baseline;
- RD3 a `discharge` or `retire` whose sig has no `debt`;
- RD4 a malformed ledger line (`read_ledger` `forgot`);
- RD5 a debt with a `blind_spot` under 12 characters (the substantive-reason bar);
- RD6 baseline drift: a baseline sig that is now paid (stale entry, remove it), or a sig added since the merge-base;
- RD7 vacuity: zero debt ledgers parsed is CANNOT RUN, exit 77.

**D7. Bulk import of the 103.** The legacy set is frozen in `.ci/policy/reggate-debt-legacy.json` (shape `{"reason": "BLOCKER: ...", "sigs": [<103 sigs>]}`, the reason citing this plan), shrink-only through RD6. The first stop after D3 lands materializes all due debts in one `add_items` append: 75 on landed branches into the backlog epic, the 28 on 1104-1 into the live PR plan's epic. The stop guide prints one line `REGGATE DEBT: <n> open (<m> legacy), oldest <date>` on every stop, never latched (design Q4.7). A sonnet triage writer then drains the backlog grouped by surface: each debt is classified as paid (a named artifact changed after `at`; the hook discharges it on the next stop), owed (a writer builds the case) or retire-candidate (subject gone; batched into one operator ask). The last box empties the baseline file and deletes it.

**Out of scope.** The design's "stale debt" finding (artifact exists, wired and green, never discharged) is subsumed by D4: the hook discharges such a debt on its next stop. The cap value (7, against the design's recommended 3) is the operator's 2026-09-05 number and stays.

## Risks

- **A flood on the first stop.** 103 items appear at once. Bounded by D3: 75 go to the backlog epic, which blocks nothing until this plan is the live PR's plan, and one status line carries the count. The 28 on 1104-1 do block that PR, which is the design's intent (they are past grace).
- **CI red on day one.** Without the legacy baseline RD1 would fail every PR. The baseline is shrink-only and expires with R10, so it cannot become a permanent hatch.
- **The commit-date proof is weak.** A commit touching the named path after the debt does not prove the case catches the defect. The `proof` text says which proof applied, and the triage writer reads the case before calling it paid.
- **Ledgers stay uncommitted.** The hook writes the live branch's ledger and nothing commits it (Context 9). R1 fixes today's two; the batch commit before each push must include `agent/reggate/<live>.jsonl`, already admitted by `.ci/policy/record-paths.json` glob `agent/reggate/*.jsonl`.
- **Bootstrapping recursion (design R5).** Writing the gate trips the regression-gate judge on its own fix-set. Land R2-R6 in one wave and accept one CI round.
