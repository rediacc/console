## Design

### Departures from a verbatim restore, each forced by today's tree

1. **Python only.** The restored executor is `rediacc_ci.review.claude_review_gate` from eb932d04d^ (arms: default decision, `--post-report`, `--post-findings`, `--mark`). Differential tests become fake-gh tests pinning argv and outputs. DEFECT 1 is fixed: an unreadable marker yields `go=false` with a named reason. The prompts move into the package (`.ci/rediacc_ci/review/prompts/`) and resolve by `__file__`, so the module imported from `.review-scripts` reads main's prompts; the `CLAUDE_REVIEW_GATE_SCRIPT_DIR` seam goes. `review_status` imports `MARKER_PREFIX` and `ATTEMPT_PREFIX` from `claude_review_gate` instead of parsing them out of the deleted .sh.
2. **One workflow file, no reusable.** The reusable existed only for the account and renet callers, and the registry is `callers: []`. The `review` job folds into `claude-review.yml`; the `.review-scripts` checkout targets `${{ github.repository }}`@main. Security properties stay verbatim: checkout order (PR repo first, tooling second), `persist-credentials: false` with the extraheader tripwire, `TRACK_PROGRESS: 'false'`, `--disallowed-tools Task,Agent`, scripts staged to `$RUNNER_TEMP` before the action runs, the `review-target` artifact handoff, fork guards.
3. **No epic split.** discover_epics, epic_context and the epic-context permission are not restored; the flat `[""]` case is the whole-PR review the operator asked for.
4. **No labels from the PR review.** `--apply-labels`, `extract_labels_fence`, the managed-label constants and prompt step 7 (`json:pr-labels`) are dropped; `pr-labels` stays the single bump decision, and a test asserts the gate never writes `<!-- claude-labels:`.
5. **The review builds on the per-commit records.** Both prompts gain one paragraph: the records for every commit are under `agent/reviews/{{HEAD_REF_SLUG}}/` with findings and resolutions; read them first, do not re-raise a settled finding unless the PR's final state contradicts the resolution, and spend the budget on what a single-commit diff cannot show (cross-commit interactions, integration, the whole-PR result). `HEAD_REF_SLUG` uses `pr_labels.branch_slug`.
6. **Review Complete returns as a REQUIRED check (operator /ask 2026-10-03, worklist #ef8db572, superseding the advisory draft of this item).** The ruling: "Required check again, but the AI system should investigate and fix automatically if there is an error; the only exception is LLM outage." The reporter posts `failure` for `stale` (head unreviewed), `failed-run` (the review run failed for a non-outage reason; the summary starts "investigate and fix:") and `hygiene` (reviewed, findings or threads unanswered); `success` for `current`, the pass-with-warning `capped` and `exhausted`, and `outage` (the current head's last attempt class is in `OUTAGE_CLASSES`, `api_error_429/500/502/503/504/529`, recorded by `claude_review_gate --mark` from the result record's `api_error_status`); `neutral` for `draft`. `Review Complete` blocks the CI verdict in wl_ci and ci_diagnose; `Review Status` and `Claude Review` stay non-blocking, and all three stay out of the watchdog and timing lists (the review observes a Console CI run, it is not part of one). The loop treats a `failed-run` or `hygiene` as work: investigate the Claude Review run and fix it, or answer the findings with `wl_prreview.py`; a timeout never lets a PR merge. The history that argued for advisory (#553, a `workflow_run` that did not fire) is answered by that automatic investigation and by the `workflow_dispatch` re-run, not by excusing the check.
7. **Submodule callers are not restored.** account and renet have no PR CI, their reviews died repeatedly on caller-tree assumptions (lines 83-155 of the reusable at 6566f46aa^), their commits already get per-commit records in the console's directory, and `external-callers.yml` stays empty.

### Answering the review automatically (the Review Gate interplay)

- **Rule change (GR6).** A summary whose `json:review-findings` fence parses to an empty array needs no reply. An unparseable fence still needs one (fail closed). No finding loses its gate.
- **Reply tool (GR7).** `python3 .claude/hooks/stop/wl_prreview.py`:
  - `--status [--pr N]`: the newest summary id, its head, its findings, inline finding threads and whether each is answered.
  - `--wait [--timeout 2100]`: waits until Review Complete on the head carries a terminal token (`current`, `capped`, `exhausted`, `failed-run`) or the timeout passes; exit 0 reviewed, 3 timeout or no review; one wait per command, in the background.
  - `--draft`: a dispositions file, one line per finding.
  - `--answer <file>`: validates dispositions in the per-commit grammar (`fixed <sha40>` an ancestor of local HEAD; `not-a-bug | <evidence>` passing `wl_review._citation_ok`, `.claude/hooks/stop/wl_review.py:1443`; `deferred #<item>` an existing worklist item), then posts one top-level reply citing `#issuecomment-<id>` with a per-finding table, an in-thread reply to each inline finding, and a `resolveReviewThread` per thread.
  - `--check`: 0 when no summary exists or the newest is answered or empty, 1 when unanswered, 2 when the API cannot be read.
  - It reads no environment variables and posts under the session's gh identity, a different author from github-actions[bot].
- **Ordering rule.** Answer before pushing: a fix push with an unanswered summary fails Review Gate and the watchdog cancels the run. Commit the fix, `--answer` citing the local sha, then push.
- **Loop wiring (GR8).** After the ready flip, `/pr-merge` step 3 runs `wl_prreview.py --wait`, triages findings (fix, not-a-bug with evidence, deferral), `--answer`s and pushes fixes, lets the follow-up review repeat the cycle, and merges once `--check` is rc 0. The review budget (`core.review_budget` cap tiers) bounds passes, the wait is bounded at 35 minutes, and rc 3 or `--check` rc 2 proceeds with a DECISIONS entry: the review never wedges the loop. A review arriving after the merge is caught by step 7 (`wl_prreview.py --status --pr <merged>`), its findings filed as worklist items.
- **Stop hook (GR9).** When CI is green on the PR head and `--check` is rc 1, the hook prints one line naming `wl_prreview.py --draft`.

### Showing the per-commit records on GitHub (GR5)

- **Where.** A new module `rediacc_ci.review.review_table` runs as a second step of the existing `pr-labels` job, which already checks out `agent/reviews`, holds `pull-requests: write` and `issues: write`, runs once per green head and is exempt from aggregation (`.ci/rediacc_ci/quality/ci_job_aggregation.py:106`). It renders the committed records; no model call.
- **Output.** One upserted PR comment starting `<!-- per-commit-reviews: <head40> -->` (the leading `<!--` keeps the Review Gate from selecting it), mirrored to `$GITHUB_STEP_SUMMARY`.
- **Content.** A header with the PR's bump label as `pr_labels.aggregate` computes it (imported, naming the commit that earned it); one row per console PR commit (short sha linked to its record at the head sha, subject, verdict, findings by severity, resolutions fixed / not-a-bug / deferred / open, per-commit `Labels:`, coverage); a section for submodule records; PR commits with no record (`chore(reviews): record reviews` commits marked "review records only, not reviewed by design"); records not in the PR's commit list as "superseded (rebased)"; a collapsed details block per finding (id, severity, path:line, claim clipped to 300 characters, resolution); a link to `agent/reviews/<slug>/` at the head.
- **Limits.** The body stays under GitHub's 65,536 characters (details truncated first, then the table, with a pointer to the directory); `pulls/<n>/commits` returns at most 250 commits, past which the table says coverage is unknown.
- **Parsing.** A parser mirrors the record grammar; a contract test renders with `wl_review.render` and parses back.
- **Failure handling.** Advisory: every failure logs and the step exits 0.

## Risks

- **The Python port never ran in production.** Mitigation: GR1's fake-gh tests per arm, DEFECT 1 fixed, GR11's real run with the dispatch escape hatch.
- **Merge-first chicken-and-egg.** Workflow and tooling resolve from main, so a broken arm surfaces on the next PR. The review is advisory and its job names non-blocking, so a failure costs a review, never a merge.
- **Auto-merge racing the review.** Mitigations: GR8's bounded wait and the step-7 late-review sweep.
- **Review Gate instant cancel.** Mitigations: the answer-before-push rule (GR8) and GR9's nudge.
- **Shrink-only baselines.** GR1 and GR2 rewrite docstrings and types clean instead of copying them.
- **Cost and quota.** Each pass is a model run on the OAuth token; the cap tiers bound passes per PR, and an outage degrades to `neutral` plus a timeout.
- **Duplicated effort.** The prompt points the reviewer at the per-commit records; the table only renders them.
- **Table limits.** 250 commits, 65,536 characters, an upserted comment keeping its timeline position; each named in the output.
- **Advisory ambiguity.** `neutral` can read as "fine"; the title token states the reason, and the loop acts on `wl_prreview --check`, not the colour.
- **Security.** The job reads PR-authored content with write permissions; the tripwire, tooling from main, `--disallowed-tools Task,Agent` and fork guards return verbatim, and any edit to them in GR3 is a reviewer-visible diff against 6566f46aa^.
