## Problem

On hostinger the repo `hermes` held 277 overlay2 directories, 20.5 GB of them referenced by no image and no container. `docker system df` reported about 4.8 GB; `docker builder prune` freed 5.185 GB and the mount stayed at 88%. A hand-run script then deleted 216 directories missing from every image and container GraphDriver. Its layerdb read was wrong: `cat` over `layerdb/sha256/*/cache-id` files, which carry no trailing newline, ran the IDs together so they matched nothing. Afterwards 18 layerdb layer entries and 87 `layerdb/mounts` entries pointed at removed directories, so at least 105 of the 216 were still referenced and the hand cleanup damaged the repository. fstrim returned 23.4 GiB to the btrfs pool and hermes was retired. 35 of the 216 had BuildKit snapshot-key names (e.g. `m132kdjjl6r9g3vy6fqkyqx93`), not 64-hex. A corrected survey found 0 orphans in the other 10 repos and 4 directories (4 MB) in one.

**1. No existing path reads the Docker data-root.**
- `renet repository prune` (private/renet/cmd/renet/repository_prune.go:16-34) removes datastore leftovers of deleted repositories (pkg/prune/datastore.go:366-380); it reaches the CLI as `repository_prune` (pkg/functions/commands/repository.go:309-317) through `rdc machine prune` (packages/cli/src/commands/machine/prune.ts:45-56).
- `renet prune` (cmd/renet/prune_commands.go:19-33) removes orphaned networks, IPs and units.
- `renet repository trim --docker` (cmd/renet/repository_trim.go:14-51) calls `prune.DockerReclaim` (pkg/prune/docker.go:57), which runs ContainersPrune, ImagesPrune with `dangling=true` only, and BuildCachePrune{All:true} (docker.go:104-120); tagged images are never pruned (docker.go:47-53). The trim pass then fstrims behind the backup guards (pkg/trim/trim_linux.go:169-189). CLI: `rdc repo trim [ref] --docker` (packages/cli/src/commands/repo-trim.ts:67-121).
- The maintain timer runs `trim.Run` without the Docker pre-pass (cmd/renet/repository_maintain.go:401-403).
- The per-repo daemon.json (pkg/daemon/systemd.go:584-625) has no BuildKit `builder.gc` block, deliberately (systemd.go:574-578).
- The API gate classifies only create, update, exec, start, checkpoint, volume create, build, plugin and swarm POSTs (pkg/dockerproxy/intercept.go:91-118); prune endpoints and `GET /system/df` pass.

**2. The lifecycle resets Docker runtime state on every `repo up`.** `SafeStartup` calls `daemon.CleanDockerRuntimeState` (pkg/orchestration/workflows.go:139-150) and `SetupDaemon` calls it again (pkg/daemon/setup.go:140-144). It wipes every `containers/<id>/` through `removeStaleContainers` (setup.go:603, 689-707), deletes `buildkit/*.db` (setup.go:665-671), `volumes/metadata.db` and `engine-id`, and empties `tmp/` (setup.go:621-630); it leaves `image/` and `overlay2/` alone (setup.go:551-555). Its doc says it also runs against an already-running daemon (setup.go:582-586). A plain systemd restart does not run it (start_foreground.go:631). `live-restore` is false for this flavor (systemd.go:541).

**3. Ranked hypotheses.**
- **H1 (most likely): the BuildKit index reset orphans every graphdriver directory BuildKit created.** setup.go:665-671 removes `snapshots.db`, `cache.db` and `metadata_v2.db` on every setup; dockerd's embedded BuildKit tracks its key-named directories only there, so afterwards `builder prune` cannot release them and `system df` does not count them. Evidence: hermes builds images (`.rediacc-buildx` exists only where `renet compose` built, pkg/compose/exec.go:310-321); 35 directories carry BuildKit names; `builder prune` freed 5.185 of about 25 GB; pull-only repos survey clean. L0 confirms the moby naming on a VM.
- **H2 (likely, invisible to the corrected survey): the containers/ wipe leaks each wiped container's read-write layer.** `removeStaleContainers` deletes `containers/<id>/` but leaves `layerdb/mounts/<id>/` and the `overlay2/<mount-id>` and `-init` directories. It happens whenever a daemon stops with containers present and the next `repo up` wipes them (up_down_workflows.go:136-140: `down()` only "typically" runs `compose down`), and on every fork. Evidence: 87 mounts entries on hermes had no container. These directories are known to layerdb, so the class E below exists to see them.
- **H3 (possible, low volume): a crash mid-pull, mid-build or mid-delete** leaves a driver directory created before its layerdb commit; the 4 MB in one other repo fits.
- **H4 ruled out:** `.rediacc-buildx` only sets `BUILDX_CONFIG` for the default docker driver (exec.go:98-111), so builds run on dockerd's embedded BuildKit, which is H1.
- **H5 ruled out:** `storage-driver` is pinned to overlay2 (systemd.go:552-558, 593).
- **Amplifier:** `repo fork` CoW-clones the data-root, orphans included, and the fork's first setup applies H1 and H2 again (setup.go:651-664).

**4. How rdc reaches a repository's daemon.** `executeRepoFunction` (packages/cli/src/utils/repo-executor.ts:79-120); `term connect` exports `DOCKER_HOST` (packages/cli/src/services/machine/ssh-connection.ts:104-119); the public socket is `/var/run/rediacc/net-<N>/docker-<N>.sock` (pkg/runpaths/runpaths.go:64-66) and dockerd listens on the internal one (systemd.go:461-463); renet finds a repo's daemon through `daemon.DiscoverSocketFiles` and `GetNetworkFromSocket` (pkg/daemon/discovery.go:248-271).

**5. Serialization.** `acquireRepoLock` (cmd/renet/repo_lock.go:48) takes the exclusive non-blocking flock that backup push holds shared; `coldbackup.RunningPath(guid)` (pkg/coldbackup/sidecar.go:71) marks a cold backup; `daemon.StopService` waits for inactive (systemd.go:344-367); `StartService` and `WaitForDaemonSocket` (systemd.go:311, discovery.go:165) start the daemon without `SafeStartup`.

## Design

1. **A pure classifier: `pkg/dockerstore` (R1).** `Scan(dataRoot, opts) (*Inventory, error)` reads, without following symlinks, `image/overlay2/layerdb/sha256/<chain>/cache-id`, `image/overlay2/layerdb/mounts/<cid>/{mount-id,init-id}`, `containers/<cid>/`, `overlay2/<dir>/` with its `link`, and `overlay2/l/<short>`.
   - Newline-safe reads: each ID file alone with `os.ReadFile` and `strings.TrimSpace`, then shape-checked (64 lowercase hex; init-id 64 hex plus `-init`, or empty). Nothing is concatenated.
   - Fail closed: an unreadable or misshapen ID file marks the inventory `Unsafe` with its path; every apply refuses an unsafe inventory.
   - Classes, each with count, bytes and paths: D orphan overlay2 directories (64-hex or `-init` names unknown to layerdb); G BuildKit snapshot directories (the same, other names); E container-less read-write layers (a `layerdb/mounts/<cid>` with no `containers/<cid>/config.v2.json`, plus its directories); F1 stale layer entries (cache-id directory missing); F2 stale mounts entries (mount-id directory missing); L dangling `l/` links; Q a leftover quarantine.
   - Bytes are allocated blocks, counted once per (dev, inode). `opts.MinAge` excludes entries younger than the floor (30 minutes for an online dry run, 0 inside the offline window). Pure Go, no build tag.
2. **Online classes through the daemon's API (R2).** `prune.ReportDaemon(ctx, socket)` reads `DiskUsage` into A unused images (dangling, and tagged with no container), B build cache not in use, C stopped containers. `prune.ReclaimDaemonFor(ctx, socket, ReclaimOptions{AllImages})` runs the existing three calls and, with `AllImages`, removes unused tagged images one by one, skipping any image a container uses. `DockerReclaim` stays as it is, so `trim --docker` does not change. Both dial the public socket.
3. **The offline window; no online removal of D, E, F, G or L (R3).** No online path is provably safe: BuildKit's live `snapshots.db` is the only record of key-named directories in use, and pulls create directories before committing to layerdb. `dockerstore.RunOffline(ctx, Window{...})`, with the repository lock held by the verb:
   1. Refuse before any change: repo not mounted; network ID 0 or at least `HubDaemonNetworkIDBase` (discovery.go:303); a cold-backup sidecar; an unsafe pre-scan.
   2. With `--apply`, Design 2's reclaim; record running container IDs and the image list.
   3. Print the downtime notice, then `daemon.StopService`; if the unit stays active, refuse.
   4. Rescan with `MinAge: 0`; an unsafe rescan starts the daemon again and refuses.
   5. Quarantine, never delete: `rename(2)` every D, E, G and L path and the E and F2 mounts entries into `<repo>/.rediacc/docker/prune-quarantine-<unix>/` on the same filesystem; when any G directory moves, `buildkit/*.db` moves with it (renet's own precedent, setup.go:648-671).
   6. An F1 entry still listed by an image is repaired by removing that image through the API (`ImageRemove`, force) in the API pass; only the rest is quarantined.
   7. `daemon.StartService` and `WaitForDaemonSocket`, deliberately not `SafeStartup`; start any recorded container that did not return under its restart policy.
   8. Verify: image count equals the recorded list minus deliberate removals; `ImageInspect` succeeds on every image with its GraphDriver directories present; every recorded container runs.
   9. On a start or verify failure: stop, rename the quarantine back, start, report exit 1.
   10. On success: remove the quarantine, release the repository lock, then `trim.Run{RepoName: guid}` and `trim.TrimDatastore`. The lock goes first because trim's `IsRepoBackupActive` probes the same lock file (pkg/prune/datastore.go:344-346); `trim.Run` with a repo name skips the datastore fstrim (trim_linux.go:54), so the verb calls `TrimDatastore` (:70).
4. **The renet verb and function (R4).** `renet repository docker-prune --datastore <d> --name <guid> [--apply] [--offline] [--all-images] [--no-trim] [--output json]`: a dry run unless `--apply`; `--offline` requires `--apply`; an empty `--name` refuses (repository_trim.go:61-67); `--apply` takes `acquireRepoLock` and turns `RepoBusyError` into a named refusal. The JSON record carries one entry per class (count, bytes, up to 50 sample paths), `estimate`, `unsafe`, `downtime_seconds`, API-reclaimed, quarantined, `trimmed_bytes`, `datastore_trimmed_bytes` and `errors`. A Linux file and an `_other.go` stub. FunctionDef `repository_docker_prune` (name, apply, offline, all_images, no_trim) beside `repository_trim` (pkg/functions/commands/repository.go:350-363), Build appending `--output json`; tiermap `TierNone` (pkg/license/tiermap.go:242); contract regenerated.
5. **The CLI verb `rdc repo prune` (R5).** `rdc repo prune <ref> [--apply] [--offline] [--all-images] [--no-trim] [-y] [--debug]`; `rdc repo prune -m <machine>` without a ref surveys every mounted repository as a dry run and refuses `--apply`. `--offline` without `-y` prints the downtime notice and asks; in an agent environment `--offline` requires `-y`, and `CMD.REPO_PRUNE` carries `REPO_DOWN`'s guard metadata (packages/cli/src/utils/command-policy.ts:41-44). Resolution as repo-trim.ts:74-88; execution through `getExecutor().execute({functionName: 'repository_docker_prune', captureOutput: true})`. Output: a table of class, count, bytes and an estimate footer; JSON passes the record through. `RENET_FUNCTION_ACCESS` row `provision`. Registered beside `registerRepoTrimCommand` (repo-extended.ts:230); named `prune`, not added to `trim`, because trim runs from the maintain timer and must never stop a daemon.
6. **Root-cause fix in the reset (F1).** `cleanDockerRuntimeState` keeps its signature, so workflows.go is untouched.
   - In-use guard: before touching `containers/`, `buildkit/*.db` or `volumes/metadata.db`, probe `LOCK_EX|LOCK_NB` on `volumes/metadata.db` and each `buildkit/*.db` (bbolt files a running dockerd holds). If any is held, skip those three wipes and handle only `network/`, `plugins/`, `runtimes/`, `swarm/` and `tmp/`. A fork's cloned files are held by nobody, so the fork path still wipes, and `RemoveForeignProjectContainers` (workflows.go:147-148) still covers a running fork.
   - Leak-free wipe when stopped: `removeStaleContainers` releases each wiped container's layer (its `layerdb/mounts/<cid>`, mount-id and init-id directories and `l/` links, through `dockerstore`'s readers); the `buildkit/*.db` reset also removes the class G directories of a fresh `dockerstore.Scan`. Both skip when the scan is `Unsafe`, and log what they removed.

## Alternatives rejected

- Extending `repo trim --docker`: trim runs from the maintain timer, where a daemon stop has no place.
- `docker system prune -a` and `docker builder prune -a` alone: hermes proved they cannot see directories outside the daemon's indexes.
- Online orphan removal behind an age floor: BuildKit's live index is the only record of key-named directories, and pulls create directories before committing.
- Reading BuildKit's `snapshots.db` with bbolt: a new dependency under the release-age gate and moby's internal schema.
- Loading moby's `layer` package offline: graphdriver code in renet and version skew against the machine's dockerd.
- Resetting the whole data-root and pulling again: long downtime and loss of locally built images; it stays the manual fallback for a repository damaged the way hermes was.
- Only the F1 fix, no tool: existing repositories keep their orphans, and nothing reports them.
- Direct deletion instead of a quarantine: a same-filesystem rename costs nothing and is the only rollback if dockerd refuses to start.
