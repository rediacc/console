Hook facts the design depends on:
- pre_push (.claude/rediacc_hooks/git/githooks.py:510-600) runs the session-link scan first (:526-544) for every remote. It judges only `refs/heads/*` lines after that (:559, :604-605), so today a `refs/backup/*` push to ANY remote, `origin` (public GitHub) included, passes unjudged.
- There is no secret scan in pre-push. The repo's scanner is `wl_store.secret_shapes_in` (.claude/hooks/stop/wl_store.py:1862), already used by the live-proof recorder.

## Rulings (operator, 2026-11-11, /ask)
- R1: refs/backup/<branch>/live fast-forwarded on every commit by a background, non-blocking post-commit hook that retries next time on failure. Before a history rewrite the old live tip is kept as immutable refs/backup/<branch>/pre-rewrite-<UTC stamp> and live restarts. One immutable refs/backup/<branch>/daily-<YYYY-MM-DD> per day. Never a force push. Submodules get the same refs on their own GitLab remotes. Force-mirror and bundles rejected: "There could be cases where we need force push".

Not CLI-once, not parallel teardown, not two-worker sharding.

## Design G: GitLab backup refs
- **Worker** `.ci/rediacc_ci/dev/backup_ref.py`, run as `./run.sh backup-ref sync|list|restore|prune|status`. One flock per repository. Pushes the checked-out `MMDD-N` branch (never `main`, which the mirror covers) with `GIT_TERMINAL_PROMPT=0` and no `--force`/`+`. Each step goes to `.git/rediacc-backup/log`.
  - It reads the remote live tip with `git ls-remote gitlab refs/backup/<b>/live`, never through a remote-tracking ref.
  - Tip descends from live: `git push gitlab <tip>:refs/backup/<b>/live`.
  - Otherwise (a rewrite): fetch the old object into FETCH_HEAD when it is missing locally. Then `git push --atomic gitlab <old>:refs/backup/<b>/pre-rewrite-<YYYYMMDDTHHMMZ> :refs/backup/<b>/live`, then create live at the tip. This is a delete and two creates, never a force.
  - The first sync of a UTC day also creates `daily-<YYYY-MM-DD>` at the tip and runs `prune`.
- **Trigger.** post-commit, post-rewrite and post-merge shims spawn the worker detached (`start_new_session=True`, stdio to the log, return at once) in the console and each submodule that has a pinned remote. A lease tree spawns nothing, because a lease never pushes (.claude/rediacc_hooks/git/githooks.py:521-523). A failed push is retried by the next trigger, since the worker always pushes the current tip rather than the triggering commit.
- **pre-push admission** (`backup_ref_refusal`, beside the mirror helpers, shared by file-load with the guards):
  - `refs/backup/**` goes only to the pinned GitLab URL of that repository (console pin plus a submodule pin map). Any other remote, `origin` included, is refused.
  - A push to `refs/backup/**` carries no other ref.
  - `live`: create, fast-forward, or a delete only inside an atomic push that creates a `pre-rewrite-*` at the same old oid.
  - `daily-*` and `pre-rewrite-*`: create only, delete only when the name's stamp is past retention (daily 90 days, pre-rewrite 30 days).
  - No receipt is asked (R1).
  - The session-link scan stays, and a secret scan (`secret_shapes_in` over added patch lines) is added. Both judge `<tips> --not --remotes --not <the line's remote old oid>`, so each sync scans only the new commits.
- **Restore.** `list [--repo console|renet|account|elite]` prints every snapshot with its date and tip. `restore <ref>` fetches into a local `refs/backup-restored/<name>`, which is not a branch and not a remote ref, so the one-live-branch rule and `--remotes` stay sound, and prints `git worktree add --detach <dir> refs/backup-restored/<name>`. `--lease <id>` or `--as-branch <name>` is the operator's call; `--as-branch` still meets `reference-transaction`.
- **Lag.** `status` exits 1 when live trails the tip by more than 50 commits or 6 h. A Stop-hook check `backup-lag` surfaces it.

## Design V: vm:check speed (R3 only; receipts unchanged, R4)
- **K1.6 cache** at `.ci/cache/vm-check/renet-main/<key>/renet` plus `manifest.json`. The key is sha256 of the main-pointer commit, the licence-key sha256, `go version`, and the sha256 of `git show <commit>:embed-assets.lock.json`. A cached binary is reused only after `go version -m` reports `vcs.revision == commit`; otherwise it is rebuilt. Writes go to a temp path and are renamed. The 3 newest keys are kept.
- **A1 concurrent.** `_battery` starts `a1_suites` in a worker thread before `p0_lock`; the thread collects results without recording. The thread is joined after `p3_leftovers` and before A2, and the rows are recorded in ACCOUNT_SUITES order with the same ids and fields. A red suite ends the run FAILED at the join, and T tears down. SIGINT/SIGTERM kill the suite's process group. The `--only` path is unchanged. The docstring at :15 and the comment at :2179 are restated.
