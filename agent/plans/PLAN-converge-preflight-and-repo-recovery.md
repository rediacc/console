## Why

On 2026-10-24 a converge onto the per-repo isolated runtime layout (renet 41ff7b0 deployed on hostinger; d98a317 is on the branch) restarted repos without checking their compose against the gates the new layout enforces. Each restart runs `SetupDaemon`, whose `cleanDockerRuntimeState` (private/renet/pkg/daemon/setup.go:144, defined at :593) wipes every `containers/<id>/` directory (`removeStaleContainers`, :681) before compose recreates them. When compose or the Docker API gate then refuses a service, nothing is left running:

- mail (network 3264): containers/ emptied at 16:47, zero containers since; image and its one volume intact. Compose bind validation refuses traefik-certs-dumper's `/opt/rediacc/proxy/letsencrypt:/traefik:ro` as a soft refusal (private/renet/pkg/dockerpolicy/policy.go:882-884); only /etc/localtime, /etc/timezone and /etc/ssl/certs are built-in read-only exceptions (private/renet/pkg/dockerpolicy/policy.go:565-569). mail-server itself reads its certificate from `./data/tls/mail.rediacc.io/` inside the repo.
- observability (network 3136): containers/ emptied at 16:50, zero containers; images and 332 volumes intact. alloy uses `pid: host` and /proc, /sys binds, which are hard refusals no grant relaxes (private/renet/pkg/dockerpolicy/policy.go:342-343, kernelHostPaths at :573, refused at :816-820); `--unsafe` relaxes only the soft tier (private/renet/pkg/compose/validate.go:19-26).
- nextcloud (network 2880): 5 of 9 containers left "Created". Collabora's `cap_add: MKNOD` is outside the gate's fixed capability allowlist (private/renet/pkg/dockerpolicy/policy.go:57-61, checked at private/renet/pkg/dockerpolicy/policy.go:355-361). The compose validator builds a HostConfig with only privileged and the pid/ipc/uts modes (private/renet/pkg/compose/validate.go:166-173), never cap_add, devices, security_opt or runtime, so compose passed and the gate refused at container create. The rediacc-autostart-reconcile timer retries every ~180s (private/renet/pkg/daemon/reconcile_timer.go:31-51).
- erpnext, gitlab, marketing, mautic and demo-stackoverflow came back; miscellaneous was skipped as a hub.

Two reporting defects hid it: `machine setup` printed "Plan: 0 of 0 repositories stale ... Converged 0" while repos were in fact restarted, and no converge-last.json was written. The converge `--dry-run` uploaded renet to the machine before planning (#358e097d).

What already exists and is reused: the operator grant `renet daemon grant --network-id N --bind-root PATH[:ro]` (private/renet/cmd/renet/daemon_grant.go:38-53, `Grant.Policy` at private/renet/pkg/dockergrant/grant.go:93), honoured by compose and the gate; every repo dockerd sandbox already sees /opt/rediacc/proxy read-only (private/renet/cmd/renet/daemon_containerd_exec.go:289-296); the machine Traefik issues every certificate through Cloudflare DNS-01 into one acme.json (private/renet/pkg/proxy/infra.go:209-214); router labels map routes to repos (`ParseTraefikLabels`, private/renet/pkg/router/labels.go:106); the gate itself evaluates through `dockerpolicy.Evaluate` (private/renet/pkg/dockerpolicy/policy.go:310) plus symlink denials (private/renet/pkg/dockerproxy/intercept.go:135).

## Decisions (operator, ASKED:2026-10-24T17:45Z; no real customers, hours or a night of downtime acceptable)

1. Order: converge preflight first, then the fixes, then vm:check, then deploy through `machine setup` from the branch, then recovery.
2. Preflight: before stopping a repo, converge evaluates every service's container config with the same `dockerpolicy.Evaluate` the gate uses, reading the repo's grants, and skips a repo that would be refused (old layout kept, refusal named in the report and converge-last.json). GPU requests are their own category, "needs a device grant", for a later gpu-device-grants plan. The compose validator gains parity with the gate. Converge health fails when a repo's prior containers do not come back. machine setup's converge summary reports what actually ran. converge-last.json is always written. A `--dry-run` never uploads renet.
3. Mail: renet exports a repo's own certificates from the proxy's acme.json into the repo mount, on issue and renewal; the dumper is dropped; no grant of the cert store.
4. Observability: a machine-level host metrics exporter that renet installs and owns, like the proxy, on a declared endpoint the observability repo scrapes; alloy's `pid: host` and /proc, /sys lines are dropped; a collector slot is left for GPU metrics.
5. Nextcloud: Collabora runs without capabilities; the same fix lands in every nextcloud template the product ships; the reconcile timer is paused during manual recovery; then repo up and 9/9 verified.

## Design

- D1. One evaluator, two callers. New `pkg/convergeguard`: `Preflight(ctx, repo) Result` builds the repo's `dockerpolicy.Scope` (NetID, own mount, immovable folder, datastore) and loads `OperatorOpt` and `Delegations` from the grant store (`dockergrant.Store.Load`), then evaluates two inputs: (a) every service of the rendered compose (`docker compose config --format json` under the repo's env, converted by D2's `ServiceHostConfig`), and (b) every container that exists right now on the repo's running daemon (old or new socket, the same probe order as `snapshotContainers` in cmd/renet/runtime_commands.go), through `docker inspect`'s HostConfig. Input (b) is what catches containers a service creates through the API at runtime (nextcloud-aio's mastercontainer creates Collabora that way), which no compose file shows. Each input goes through `dockerpolicy.Evaluate` plus the gate's symlink denials, factored out of pkg/dockerproxy so preflight and gate cannot drift. Result: `allowed | refused{service, field, tier, message}[] | needs_device_grant{service}[]`, where a denial on `DeviceRequests` (private/renet/pkg/dockerpolicy/policy.go:374) or a non-runc `Runtime` naming nvidia is classified `needs_device_grant` instead of `refused`. The CRIU and WireGuard capabilities the compose wrapper injects are applied to (a) before evaluation, so a wrapper-injected cap is never reported.
- D2. Compose/gate parity. New `pkg/compose/hostconfig.go`: `ServiceHostConfig(service ServiceConfig) *container.HostConfig` maps privileged, pid, ipc, uts, cap_add, cap_drop, devices, device_cgroup_rules, `deploy.resources.reservations.devices` and `gpus` (DeviceRequests), security_opt, runtime, isolation, sysctls, oom_score_adj, oom_kill_disable, cgroup_parent, network_mode, volumes (Binds and Mounts) and tmpfs. `collectServiceErrors` (private/renet/pkg/compose/validate.go:166) feeds that whole HostConfig to Evaluate with the repo's grant (`OperatorOpt` from the grant, not the zero value it passes today, so a granted unsafe-binds repo validates the way the gate decides). A table test asserts every HostConfig field Evaluate reads is either mapped or listed as compose-inexpressible, so a new gate field without a compose mapping fails the test.
- D3. Where preflight runs. (1) `runtime converge`: in `classifyRepo`, after staleness is judged, a stale repo whose preflight is not `allowed` becomes `skipped` with reason `gate_refused` or `needs_device_grant` and the denial list in the plan entry and the result; it is never restarted and its containers keep running. (2) The restart path a converge does not own: the `repository up` workflow (private/renet/pkg/orchestration/workflows.go, the `SetupDaemon` call) runs the same preflight when the daemon is active and the unit rewrite would cross layouts (the `ensureSystemdUnit` condition, private/renet/pkg/daemon/setup.go:735), before `CleanDockerRuntimeState`; a refusal fails the up with the denial list and touches nothing, so a reconcile tick cannot reproduce tonight either. A first-time up (daemon not active) keeps the existing compose and gate refusals.
- D4. Health, summary, report. `convergeHealthProblem` already compares running names; the defect is upstream: the `before` snapshot must be taken while the old daemon still answers and must fail the repo (not pass it) when the snapshot is empty but the repo's containers/ directory was non-empty, and `containers_missing` must also count containers left `Created`. P3 first reproduces "Plan: 0 of 0 ... Converged 0" against tonight's facts (the plan was empty, so the restarts came through a path that never reached `planConverge`; the root cause is stated in the box tick), then fixes it. `writeConvergeReports` writes converge-last.json for every pass including a dry run (as `converge-last-dryrun.json`, so a dry run never overwrites a real pass) and an aborted or erroring pass (a deferred write, so an early return still records the plan and the error). The CLI summary (`renderConvergeReport` in packages/cli/src/services/renet/runtime-converge.ts) counts from `results`, prints skipped repos with their reason and denials, and prints `would converge` separately from `converged`.
- D5. Dry run uploads nothing. `rdc machine converge --dry-run` runs against the renet already on the machine: the executor request carries a no-provision flag that skips `acquireRemoteRenet`'s upload (packages/cli/src/services/renet/renet-execution.ts:351); when the machine has no renet, or its hash differs from the local build, the dry run says so in one line and plans with the machine's binary (a hash difference is printed, never fixed).
- D6. Certificate export (mail). New `renet cert export` and `pkg/certexport`, run as root at machine level. Ownership: a domain belongs to a repo only when a router route for that exact host, read from the labels of a container on that repo's daemon (`ParseTraefikLabels`), names it; a domain claimed by two repos, or by none, is never exported, and a wildcard certificate is exported only to a repo that routes a host under it. For each owned domain it reads the certificate and key from /opt/rediacc/proxy/letsencrypt/acme.json (the resolver named `letsencrypt`, private/renet/pkg/proxy/infra.go:213) and writes `<repo mount>/data/tls/<domain>/cert.pem` (0644) and `key.pem` (0600), owned by the repo mount's owner, atomically (temp file and rename), and only when the content changed. Triggers: after every router refresh (the router already reads every repo's labels) and a renet-owned timer that compares acme.json's mtime, so renewal reaches the repo within one tick; a repo opts in with the label `rediacc.cert_export=true` on the routed service, so nothing is written into a repo that did not ask. mail-server keeps `SSL_TYPE=manual` and its existing path; the dumper service is dropped from mail's compose. Docs: the per-repo dumping section of packages/www/src/content/docs/en/networking.md (line 207 onward) and private/account/docs/infra/mail-server.md describe the export instead of the dumper; the 12 derived locales follow through the i18n pipeline.
- D7. Host metrics exporter (observability). `renet host-metrics serve`, supervised by a `rediacc-host-metrics` systemd unit that renet installs and refreshes beside `rediacc-router` (the `InstallRouterService` pattern, private/renet/pkg/proxy/install.go:71), so no new binary is downloaded and no pin is added. Collectors: the set the observability repo's dashboards and alerts actually query (O1 inventories the metric names first; the inventory is the oracle), built on procfs readers with Prometheus text exposition, plus a registered-but-empty `gpu` collector slot. Endpoint: a machine-reserved loopback address outside every repo's /26, on a fixed port declared in /etc/rediacc/host-metrics.env, serving `/metrics` behind a bearer token; the token is materialised into the secrets directory of each repo the operator grants (`renet daemon grant --network-id N --host-metrics`, a new grant kind in pkg/dockergrant), so a repo without the grant gets 401. O1's tests prove reachability from a granted repo's container under the repo network isolation and refusal from an ungranted one. alloy's `pid: host` and /proc, /sys binds are dropped and it scrapes the endpoint instead.
- D8. Collabora without capabilities (nextcloud). Collabora's kit can run without MKNOD and the other chroot capabilities in its no-capabilities mode (coolwsd's `security.capabilities` set false, passed as `extra_params=--o:security.capabilities=false`; N1 verifies the exact option name against the coolwsd.xml of the image tag hostinger runs before anything is changed). Where Collabora comes from decides where the fix goes: a compose service (drop `cap_add`, set the option), or nextcloud-aio's mastercontainer (the API-created container carries AIO's own capability list; then the AIO Collabora toggle is turned off and a standalone Collabora service with the option is added to the compose). N1 settles which one hostinger runs. The shipped template packages/json/templates/platforms/nextcloud-aio gets the same treatment, and N1 searches packages/www solutions, packages/json templates and private/* for every other Collabora definition.

## Risks

- Preflight over live containers (D1 b) can refuse a repo whose stale container definition the next compose up would replace with a compliant one; the denial names the container, and the operator removes it or fixes the compose, which is the intended direction (fail before the wipe, not after).
- The empty-plan root cause (P3) may sit in a path not yet read; until the tick names it, P5's guard on the up path is what stops a repeat, which is why P5 is a box rather than a note.
- Certificate export writes a private key into a repo mount: the ownership rule (exact routed host, single claimant, opt-in label) is the whole safety argument, and M1's negative tests are the acceptance, not the happy path.
- A reserved loopback endpoint may be unreachable under the repo network isolation; O1 must prove reachability from a granted container before H3, or switch the endpoint (the design choice is O1's to settle with the test as evidence).
- Collabora's no-capabilities mode costs per-document jail isolation inside its own container; acceptable inside a per-repo daemon, recorded here so it is a decision rather than a surprise.
- The in-flight uncommitted edit of cmd/renet/runtime_converge.go in private/renet belongs to work already under way; P1, P3 and P4 start from its committed state.
