## Design

- **Make the ratchet real first (G1).** `--update-baseline` is replaced by `--prune-baseline`, which writes the baseline minus its stale entries and never adds one. A ceiling constant in `pkg/i18n/baseline_ceiling.go` must EQUAL the entry count (a Go test), so every batch lowers it in the same commit and any growth needs a visible raise that the per-commit review catches. The gate's remedy line stops offering an exemption; the only remedy for a new finding is a catalogue key.
- **Narrow the extractor only where the string is not language (G2).** Unit suffixes after a verb (`%dB`, `%dKiB`, `%dGiB`, `%.1f%%`) and strings that are wholly an identifier path become non-prose, each with a positive and a negative test. Error text is NOT exempted: renet errors reach the operator through rdc output, so they are user-facing and get keys. No inline ignore marker is added; a string is either language (catalogue) or not (extractor rule).
- **Batches by package, one at a time (B01-B12).** Each batch: convert every baseline entry of its packages to `i18n.T`/`i18n.Tf` with a key in the file's existing namespace, add the English value to `en.go`, naturalize the 12 locales through an `i18n-guardian` writer (sonnet, per the operator's 2026-09-26 routing for locale writers), regenerate the catalogues and `hashes.json`, prune the baseline and lower the ceiling. The batch accept is `make i18n-check` plus the touched packages' tests. A batch that finds a string which is not user-facing at all (a debug-only format) deletes or rewrites the line rather than translating it.
- **Delete the mechanism at zero (D1).** With no entries left, `baseline.json`, the ceiling, `--baseline`, `--prune-baseline`, `FilterAgainstBaseline`, `StaleBaselineEntries` and the stale-entry block of `i18n.sh` go; `renet i18n extract` exits non-zero on any finding. `.claude/agents/pr-babysitter.md:217`'s note about the extractor gate is updated to the zero-tolerance form.
- **Out of scope:** the 85 `bridge.*` keys still named after the old namespace (#518); `locale_quality_baseline.json`, which `i18n-guardian.md` already holds at empty; the www, CLI and account trees.

## Risks

- Volume: about 2900 new keys across 13 catalogues is roughly 35,000 locale values. Writer cost is real; batches of about 250 keys keep each writer inside one context, and the locale-quality tests (untranslated, English mash, own-script, duplicate clusters) are the oracle for each batch rather than a reviewer reading 3000 values.
- Every renet plan that edits a call site in a batch's package collides with that batch. Batches are small and land in a day each; a colliding plan rebases onto the landed batch, and the batch writer leaves strings added after its survey to the gate (which now refuses them).
- Translated error text changes what scripts match. Code that tests an error by its English text (`strings.Contains(err.Error(), "...")`) breaks under a non-English locale; each batch greps its packages and the CLI's `packages/cli/src/services/renet` parsers for matches on the strings it moves, and switches those to typed errors or error codes in the same batch.
- The ceiling-equals-count test makes every unrelated renet commit that removes a baselined line lower the ceiling too. That is the intended friction: a drained entry is recorded in the commit that drained it.
