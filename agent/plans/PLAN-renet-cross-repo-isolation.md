## The breach

Every repo's dockerd and containerd run in a mount-namespace sandbox built by `renet daemon containerd-exec`. Its read-write allowlist binds the whole host directory `/var/run/rediacc` (`private/renet/cmd/renet/daemon_containerd_exec.go:168`), recursively, at the same path. That directory holds every network's runtime files side by side:

- the Docker socket and pid file of every repo, `docker-<N>.sock` and `docker-<N>.pid` (daemon.json, `private/renet/pkg/daemon/systemd.go:552-554`);
- every containerd socket, debug socket and pid file (`private/renet/pkg/daemon/containerd_config.go:60-62`, `private/renet/cmd/renet/daemon_containerd_exec.go:95`);
- every dockerd exec-root `docker-<N>/` (`private/renet/cmd/renet/daemon_containerd_exec.go:153`) and every containerd state directory `containerd-<N>/state`;
- every repo's file-mode secrets, `secrets/<N>/<NAME>` (`private/renet/pkg/orchestration/secret_files.go:19`).

The per-repo dockerd resolves a container's bind source inside that sandbox. A container that holds its own repo's Docker socket (the supported `${DOCKER_SOCKET}` bind) can ask its daemon for a second container binding `/var/run/rediacc/docker-<M>.sock` or `/var/run/rediacc/secrets/<M>/`, and receives repo M's daemon or secrets. The compose validator refuses those binds in compose files (`private/renet/pkg/compose/validate.go:272-283`, `private/renet/pkg/compose/validate.go:66-71`), but a request through the Docker API never meets the validator. Verified on ops-worker on 2026-10-23: a container started through repo 8256's API reported repo 7104's daemon id. `private/renet/docs/DOCKERD_SANDBOX.md` names this as known limitation 5.

It is the same class as the host `/run` breach closed in private/renet 3c3e1f5 (`agent/plans/PLAN-renet-run-docker-sock-isolation.md`, T1 result): a sandbox bind wider than the one network it serves.

## Design

### D1. One directory per network, holding everything that network writes at runtime

Every per-network runtime path moves under `/var/run/rediacc/net-<N>/`. The rule is a prefix insertion that keeps today's basenames, so every parser that reads a basename (`docker-(\d+)\.sock` in `private/renet/pkg/router/docker.go:22`, `GetNetworkFromSocket` in `private/renet/pkg/daemon/discovery.go:233-245`) keeps working unchanged:

| Today | After |
|---|---|
| `/var/run/rediacc/docker-<N>.sock` | `/var/run/rediacc/net-<N>/docker-<N>.sock` |
| `/var/run/rediacc/docker-<N>.pid` | `/var/run/rediacc/net-<N>/docker-<N>.pid` |
| `/var/run/rediacc/docker-<N>/` (dockerd exec-root) | `/var/run/rediacc/net-<N>/docker-<N>/` |
| `/var/run/rediacc/containerd-<N>.sock`, `.sock.ttrpc`, `-debug.sock`, `.pid` | the same names under `/var/run/rediacc/net-<N>/` |
| `/var/run/rediacc/containerd-<N>/state` | `/var/run/rediacc/net-<N>/containerd-<N>/state` |
| `/var/run/rediacc/containerd-<N>/s` (bound at `/run/containerd/s`) | `/var/run/rediacc/net-<N>/containerd-<N>/s` |
| `/var/run/rediacc/secrets/<N>/<NAME>` | `/var/run/rediacc/net-<N>/secrets/<NAME>` |

Host-only files stay where they are, because no sandbox needs them and after D2 no sandbox sees them: `storage-maintain.lock` (`private/renet/cmd/renet/repository_maintain.go:33`), `reconcile.lock` (`private/renet/cmd/renet/repository_reconcile.go:29`) and the cold-backup sidecars (`private/renet/pkg/coldbackup/sidecar.go:33`). The startup lock is already outside, at `/var/lock` (`private/renet/pkg/daemon/lock.go:5`).

Secrets move into the network directory rather than being bound as a second directory. `RemoveSecretFiles` deletes the whole per-network secrets directory on `repo down --unmount` (`private/renet/pkg/orchestration/secret_files.go:144-152`) and `WriteSecretFiles` recreates it (`private/renet/pkg/orchestration/secret_files.go:103`). A bind of the secrets directory itself would keep pointing at the deleted inode after that cycle, and a daemon that outlived it would see no secrets. Bound through its parent `net-<N>`, a recreated `secrets/` is visible at once.

Path length: the longest new unix socket is `/var/run/rediacc/net-<N>/containerd-<N>-debug.sock`, under 60 bytes for a five-digit id, well inside the 108-byte `sun_path` limit; dockerd's sockets under the exec-root grow by the length of `net-<N>/`. T9 confirms on a real daemon.

### D2. The sandbox binds only its own network directory

`buildContainerdSandboxConfig` replaces the `/var/run/rediacc` entry and the separate exec-root entry (`private/renet/cmd/renet/daemon_containerd_exec.go:153-168`) with the single directory `/var/run/rediacc/net-<N>`, bound read-write at the same path. The shim socket bind keeps its target `/run/containerd/s` and takes its source from the new location (`private/renet/cmd/renet/daemon_containerd_exec.go:241-244`, `private/renet/cmd/renet/daemon_containerd_exec.go:267`). Inside the sandbox `/var/run/rediacc/` then holds one entry, so a bind of another network's socket or secrets finds no source. dockerd then creates an empty directory on the sandbox tmpfs, exactly as the private `/run` does for `/run/docker.sock` today (`private/renet/docs/DOCKERD_SANDBOX.md`, section *Private `/run` and host daemon sockets*).

`bindDir` skips a missing source with a warning (`private/renet/pkg/daemon/mount_sandbox_linux.go:213-219`), so `runDaemonContainerdExec` creates `net-<N>/`, `net-<N>/secrets/` and the shim directory before it enters the sandbox, as it already does for the shim directory and the iptables lock (`private/renet/cmd/renet/daemon_containerd_exec.go:104-114`). The pid file write moves to `net-<N>/containerd-<N>.pid` (`private/renet/cmd/renet/daemon_containerd_exec.go:95-101`), and `dockerd-exec` reads it there (`private/renet/cmd/renet/daemon_dockerd_exec.go:69`).

The four Landlock grants that still name `/var/run/rediacc` whole get the same narrowing, since they are the same class on the process side: the `renet compose` sandbox (`private/renet/cmd/renet/main.go:1241`), the function executor (`private/renet/pkg/functions/executor_ssh.go:430`), the terminal and VS Code gateway (`private/renet/cmd/renet/sandbox_gateway.go:189`) and the kube sandbox (`private/renet/pkg/kube/sandbox.go:27`). Each grants read-only access to `net-<N>/secrets` only, as the Rediaccfile sandbox already does (`private/renet/pkg/orchestration/up_down_workflows.go:422-430`); the own socket keeps arriving through `opts.DockerSocket`. The kube sandbox has no network id where it is built today, so T2 either threads one through or records in this plan why kubectl needs no `/var/run/rediacc` grant at all.

### D3. One source of truth per language

A new leaf Go package `private/renet/pkg/runpaths` (standard library only, so `pkg/compose` can import it without the cycle `private/renet/pkg/compose/validate.go:41-45` works around) owns every per-network runtime path: `NetDir`, `DockerSocket`, `DockerHost`, `DockerPid`, `DockerExecRoot`, `ContainerdSocket`, `ContainerdPid`, `ContainerdDebugSocket`, `ContainerdStateDir`, `ShimSocketDir`, `SecretsDir`, the discovery glob `DockerSocketGlob = "/var/run/rediacc/net-*/docker-*.sock"`, and the secrets placeholder form `/var/run/rediacc/net-${REDIACC_NETWORK_ID}/secrets/`. The existing helpers become thin calls into it or are deleted: `orchestration.DockerSocketPath` and `SecretsDir` (`private/renet/pkg/orchestration/secret_files.go:69-81`), `daemon.GetNetworkSocketPath` (`private/renet/pkg/daemon/discovery.go:300-301`), `DockerHostForNetworkID` (`private/renet/cmd/renet/docker_command.go:12-13`), and the `containerdStateRoot` test seam (`private/renet/pkg/daemon/containerd_config.go:16`) becomes a `runpaths` root override for tests.

The CLI gets the mirror in `packages/shared/src/config/runtime-paths.ts` (`repoNetDir`, `repoDockerSocketPath`, `repoSecretsDir`), built on `WK_RUNTIME_DIR` (`packages/shared/src/config/well-known.generated.ts:27`). Both sides pin the same literal in a test (T8), `/var/run/rediacc/net-7104/docker-7104.sock`, so a drift between Go and TypeScript fails a test on each side.

### D4. The DOCKER_SOCKET contract

`DOCKER_SOCKET` and `DOCKER_HOST` keep their names and change value to `runpaths.DockerSocket(N)`. They are set for the Rediaccfile in `private/renet/pkg/orchestration/up_down_workflows.go:222` and `private/renet/pkg/orchestration/up_down_workflows.go:358`, for compose in `private/renet/pkg/compose/wrapper.go:31`, and by the CLI for terminals and VS Code (T4). A compose file that writes `${DOCKER_SOCKET}` keeps working with no edit. The validator's own-socket allowance (`private/renet/pkg/compose/validate.go:272-283`) accepts the new resolved form and its `${REDIACC_NETWORK_ID}` spelling, and the old `/var/run/rediacc/docker-<N>.sock` form falls into the existing hard refusal of host runtime paths, with a message that names `${DOCKER_SOCKET}`. File-mode secrets get the same treatment: the documented `secrets: file:` prefix becomes `/var/run/rediacc/net-${REDIACC_NETWORK_ID}/secrets/`, and the old prefix is refused with a message naming the new one (`private/renet/pkg/compose/validate.go:497-528`).

### D5. Migration: the first `repo up` or daemon restart on the new renet moves a repo, with no dual paths

Nothing reads the old layout after the change. The new layout takes effect per network when its daemon restarts, because `start-foreground` rewrites daemon.json and containerd.toml on every start (`private/renet/pkg/daemon/start_foreground.go:341-383`), and because the socket unit text changes (`private/renet/pkg/daemon/systemd.go:193`), so `ensureSystemdUnit` sees `changed` and restarts a running daemon (`private/renet/pkg/daemon/setup.go:687-707`).

A trap sits in that gate. It restarts only when `isDaemonSocketResponding` answers (`private/renet/pkg/daemon/setup.go:695`), and that probe looks at the socket path the new code computes (`private/renet/pkg/daemon/discovery.go:188-189`). An old daemon listens on the old path, so the probe says "not running", the restart is skipped, the old daemon keeps the old layout, and the repo's next step finds no socket at `DOCKER_SOCKET`. T1 gates the restart on `IsServiceActive` (`private/renet/pkg/daemon/systemd.go:412`), the systemd truth, instead of on a socket path.

Teardown has the same blind spot: it stops a live-restore daemon's containers through the computed socket path (`private/renet/pkg/daemon/setup.go:259`). For the one restart that crosses layouts, the running daemon's real socket is the `hosts` entry of the daemon.json it was started with, and `SetupDaemon` rewrites that file before the unit check (`private/renet/pkg/daemon/setup.go:189`). T1 reads the pre-rewrite `hosts` value and stops containers through it, so a hub daemon (`live-restore: true`, `private/renet/pkg/daemon/systemd.go:535-538`) does not leave orphaned containers holding its ports. This reads the actual configuration of a running process; it is not a second layout.

Leftover old files are deleted, never read. `removeStaleRuntimeFiles` (`private/renet/pkg/daemon/start_foreground.go:314-327`) also removes this network's old-layout files: the five old socket and pid paths, the old `containerd-<N>/` and `docker-<N>/` directories (after `unmountAllBelow`, as `RemoveNetworkDirectories` does at `private/renet/pkg/daemon/systemd.go:822-830`), and `secrets/<N>/`, plus `secrets/` once empty. Secrets are plaintext on tmpfs, so they must not linger until a reboot.

The router finds daemons by glob. Its unit bakes the old pattern in (`private/renet/pkg/proxy/install.go:48`, `private/renet/daemon-setup/rediacc-router.service:14`), and the default sits at `private/renet/pkg/router/types.go:29`. T1 drops the flag from the unit so the binary's default rules. The CLI's post-update router restart (`packages/cli/src/services/renet/renet-execution.ts:200-229`) re-renders the unit through `renet proxy install` before restarting, so an upgraded machine stops passing the old glob. `ReadOnlyPaths=/var/run/rediacc` in the router unit (`private/renet/pkg/proxy/install.go:65`) still covers the new sockets.

**The one-time cost, stated.** Per machine, on the first `repo up` (or reconcile, or reboot) after the renet upgrade, each repo:

1. restarts its dockerd and containerd once;
2. loses its running containers once. containerd's state and shim sockets move, so tasks started under the old layout cannot be reattached, as with the private `/run` upgrade note in `private/renet/docs/DOCKERD_SANDBOX.md`. The Rediaccfile `up()` starts them again in the same `repo up`;
3. has every container that binds `${DOCKER_SOCKET}` (Traefik and certs-dumper patterns) recreated by compose, because the resolved bind source changed. A restart-policy container that dockerd starts before compose runs sees an empty directory at its old socket bind until that recreate;
4. is missing from the router between the router restart (which follows the renet upgrade) and its own `repo up`. On a machine with several repos, `renet repository up-all` (`private/renet/cmd/renet/repository_up_all.go`) right after the upgrade shrinks that window to one pass. T9 measures it on ops-worker.

A compose file that names the old socket path or the old secrets prefix literally fails validation with a message naming the replacement. A compose file that uses `${DOCKER_SOCKET}` needs no edit.

### D6. Folded-in findings from the docker-sock writer

- **containerd 2.x still loads its CRI plugins.** The generated config disables only `io.containerd.grpc.v1.cri` (`private/renet/pkg/daemon/containerd_config.go:86`). containerd 2.x splits CRI into further plugins (the image and runtime services), which that id does not cover, so CRI's mounts and goroutines still start in every per-repo containerd. This is a hypothesis about unread upstream code until T5's first step lists the plugins on ops-worker and records the output here. The fix disables every CRI-family id the listing shows as loaded. T5 must prove the oldest containerd in the vm:check matrix still starts with the added ids.
- **The CRIU dump log is read from a path that no longer exists.** `readCRIUDumpLog` reads `/run/containerd/io.containerd.runtime.v2.task/moby/<id>/criu-dump.log` on the host (`private/renet/cmd/renet/checkpoint_commands.go:1366-1383`). The per-repo containerd's task bundles live under its own state dir, so after D1 the log is at `runpaths.ContainerdStateDir(N)/io.containerd.runtime.v2.task/moby/<id>/criu-dump.log`. The caller at `private/renet/cmd/renet/checkpoint_commands.go:1233` passes the network id instead of the docker host string.
- **Regression test for the sandbox allowlist.** `TestBuildContainerdSandboxConfigRWBaseline` asserts that `/var/run/rediacc` IS bound (`private/renet/cmd/renet/daemon_containerd_exec_test.go:34-46`), which pins the breach in place. T8 inverts it.

### D7. Sibling exposures in the same allowlist

Sweeping the allowlist for other binds wider than one network finds two more:

- `/tmp` is bound read-write from the host (`private/renet/cmd/renet/daemon_containerd_exec.go:173`). It is one directory shared by the host and every repo's sandbox, so it is a cross-repo channel. It also holds whatever sockets the host keeps there (root tmux, forwarded ssh-agent sockets), reachable the same way the breach reached `docker-7104.sock`.
- `/var/lib` is bound read-only whole (`private/renet/cmd/renet/daemon_containerd_exec.go:202-206`). That includes other networks' `/var/lib/rediacc/docker-<M>/` state, the system Docker's `/var/lib/docker`, and kubelet pod volumes when a cluster runs on the machine.

T7 replaces `/tmp` with a per-network directory inside the repo mount, bound at `/tmp`, so build scratch is counted against the repo quota. It narrows `/var/lib` to the paths dockerd and containerd are measured to read. Each removed path is proven unneeded by the vm:check matrix (T10), not assumed.

### Finding outside these boxes, for triage

The compose validator refuses `privileged` and `pid: host` (`private/renet/pkg/compose/validate.go:128-140`), but nothing refuses them on the Docker API, which is the same door the breach used. If the repo daemon accepts `docker run --privileged --pid=host` through `${DOCKER_SOCKET}`, a container reaches host root with `nsenter -t 1`, and every boundary in this plan is moot for a repo that chooses to cross it. T9 records whether the daemon accepts that request. The lead triages the result (`worklist.py --triage`) into its own plan, because an API-layer gate is a design question (`private/renet/docs/DOCKERD_SANDBOX.md` rejects authorization plugins for a reason that D2 partly changes).
