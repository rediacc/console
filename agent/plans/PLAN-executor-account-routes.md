## Design

1. **One allow-list table, read in three places.** `packages/shared/src/subscription/executor-account-routes.ts` exports `EXECUTOR_ACCOUNT_ROUTES`, one entry per served call: `method`, `inner` (the path template under `/account/api/v1`, segments typed `lineage`, `snapshot`, `machine` or `uuid` with the patterns of Context 5 and a machine pattern taken from the account schema narrowed to what provision.ts sends), `query` (the exact parameter names admitted, empty for none) and `scope`. The entries: `GET backups/usage`, `GET backups/status`, `GET backups/manifests` {lineage, limit, before, includeDeleted}, `GET backups/snapshots/resolve` {lineage, anchorSnapshotId, anyStream, storeId, at, needIndex, includeDeleted}, `GET backups/retention` {lineage}, `GET backups/retention/preview` {lineage}, `GET backups/immutability`, `GET backups/stores/lineage/:lineage`, `POST backups/verify`, `POST backups/snapshots/:snapshot/verification`, `POST backups/snapshots/:snapshot/undelete`, `POST backups/chunks/repair`, `POST backups/reconcile`, `POST backups/lineages/:lineage/orphan`, `DELETE backups/lineages/:lineage`, `GET licenses/report`, `POST licenses/machines/:machine/deactivate`, and PL1's three folded in as `POST licenses/activate-repo`, `POST licenses/activate-repo-batch`, `POST licenses/repos/:uuid/retire`. The executor path of an entry is `/account/api/v1/proxy/account/<inner>`. The CLI refuses an unlisted call before sending it, the egress forwards only listed pairs, and the account router answers 404 for anything unlisted.
2. **Why not a generic pass-through.** A single `POST /proxy/account` carrying the inner route in its body is the tunnel again: the egress cannot see the route, so its allow-list becomes vacuous. A prefix mirror `/proxy/account/*` with no table would hand every `apiTokenAuth` route (token CRUD, config storage, delegation issue, forensics) to anything a served command runs, with scopes derived from the person's role. So the mirror is generic in mechanism and closed in reach: the handlers are reused, the routes are enumerated, and the egress list is literal.
3. **Reuse the CLI handlers through a token-auth parameter.** `backupsRoute`, `backupStoresRoute` and `licenseRoute` take an optional `{ tokenAuth }` (default `apiTokenAuth`) and call `tokenAuth(scope)` where they call `apiTokenAuth(scope)` today; the existing mounts in routes/index.ts and routes/on-premise-index.ts pass nothing and keep their behaviour. `private/account/src/routes/executor-account.ts` builds a second instance of each with `tokenAuth: executorOnBehalfAuth` behind a gate middleware that matches `METHOD path` (and the query names) against the table and answers the plain router 404 for anything else, so the session-authenticated backup routes and every unlisted CLI route are unreachable on the executor mount. It is mounted with one line, `app.route('/proxy/account', executorAccountRoute())`. This is not PL1's refused shape of two authentication models in one handler: each mount is built with exactly one auth middleware, chosen at construction, and no request value can switch it.
4. **`executorOnBehalfAuth(scope)`** lives in `private/account/src/middleware/executor-on-behalf.ts`, beside PL1's `resolvePrincipal` hoisted there unchanged in its rules. It authenticates the bearer as an issued executor token holding `proxy:exec`, reads the principal from the `X-Rediacc-On-Behalf-Of` header (a GET carries no body, so the header is the one transport for every entry, PL1's routes included), resolves it, derives the principal's effective scopes with `loginScopesFor(orgRole, totpEnabled)` (extracted from private/account/src/services/device-code.service.ts:423-436 into `private/account/src/services/login-scopes.ts` and called by both), and refuses 403 `ON_BEHALF_SCOPE_FORBIDDEN` when `scope` (or, for the scope-less reconcile, the handler's own check) is not in that set. On success it sets the five context values of Context 7 to the principal's token id, subscription, team, effective scopes and creator, and `executorTokenId` to the caller, so the handler scopes by the principal's team, runs `requireManagerCreator` against the principal's creator, and logs the person. Refusal codes stay as PL1 defined them (`EXECUTOR_TOKEN_REQUIRED`, `ON_BEHALF_REQUIRED`, `ON_BEHALF_TOKEN_FORBIDDEN`), with the scope refusal added; every unknown, foreign or dead principal answers the same `ON_BEHALF_TOKEN_FORBIDDEN`.
5. **Fold PL1.** `proxy-licenses.ts`, its mount, and the `executorIssueRepoLicense*`/`executorRetireRepoLicense` twins in types/subscription.ts are removed; the three licence entries of the table reach the CLI handlers in license.ts through the same middleware. PL1's integration cases move into the new test file with the principal sent in the header. One executor router replaces the bespoke one, with no compatibility path, since the only caller is the CLI of the same release.
6. **The egress.** `BEARER_ROUTES` keeps its six non-licence pairs; the two licence pairs and `PROXY_LICENSE_RETIRE_RE` give way to `EXECUTOR_ACCOUNT_PAIRS`, a literal list in egress.ts of `{ method, pattern, query }` covering exactly the table, classed `bearer`; `classifyEgress` checks the request's query names against the entry's set (a name outside it, or a repeated name, is `query-not-allowed`). The tunnel stays refused. The proxy worker does not import packages/shared at runtime, so a parity test imports the shared table and asserts the egress list matches it entry for entry. The workers/proxy/src/egress.ts:14 paragraph is rewritten to name the router and the table.
7. **The CLI: one helper, and it is `accountServerFetch`.** Inside a container dispatch (the executor-principal store PL3 sets), `accountServerFetch` (packages/cli/src/services/account/account-client.ts:343) matches the call's method, path and query against the table; a match goes plain to `<serverUrl>/account/api/v1/proxy/account/<inner>` with `Authorization: Bearer <REDIACC_TOKEN>` (the placeholder) and `X-Rediacc-On-Behalf-Of: <tokenId>`, and an unlisted call throws a named error saying the call is not served in a container, before any network. Outside a dispatch, and in `--mode daemon`, it is the tunnel exactly as today. The error object carries the same `status`, `code` and `details` the tunnel path produces, and a 202 body is returned like a 200, so the callers' 404 and `code` branches (packages/cli/src/commands/backup-restore-chunk.ts:57-59, packages/cli/src/services/tofu/provision.ts:313-314, packages/cli/src/services/backup/backup-store-pick.ts:74) and the delayed-delete reads behave alike on both paths. `licenceFetch` is removed and license.ts, license-batch.ts and license-retire.ts call `accountServerFetch` with their inner paths again. The branch sits in the shared helper rather than a second helper the callers must remember: the twelve fatal callers and the four degraders then need no edit, and a future served caller fails loud and named in a container instead of meeting a bare egress refusal. To avoid an import cycle, executor-principal.ts keeps only the store and no longer imports account-client.ts.

## Risks

- The executor can now cause backup deletions (`DELETE backups/lineages`, `chunks/repair`, non-dry-run reconcile) on a principal's behalf. Each still needs a live same-org principal whose creator is an owner or admin with TOTP today, the same bar a CLI login meets at mint and `requireManagerCreator` re-checks at use, and the executor policy document has already admitted the command for that person.
- A principal token lives five minutes for a console session (PL plan Risks); a long restore or purge whose last call lands after expiry is refused `ON_BEHALF_TOKEN_FORBIDDEN`, and EA-L1 records whether the bench run meets it.
- `machineId` is 1-200 free characters on the account side (private/account/src/routes/license.ts:311); the egress pattern follows what packages/cli/src/services/tofu/provision.ts actually sends, so a machine id outside that shape is refused at the egress and EA3 must name the shape it chose.
- egress.ts is shared with PLAN-rmcp-writeback and the route factories with any plan editing backups.ts or license.ts; parallel writers meet as a cherry-pick conflict at landing.
