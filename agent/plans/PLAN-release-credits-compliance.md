## Design

- **Surface: keep `rdc credits`, add no `rdc license`.** `license` already means the Rediacc licence across the CLI (subscription, `server licence`, `machine status --licenses`); a second meaning would mislead. `rdc credits` stays the inventory and `rdc credits --licenses` the full text; the changes are to what they print. `Mirror: <url> (planned)` becomes `Mirror: <url>` once the field is a real mirror (the field is renamed `mirrorUrl`, clean break, no alias). The Node.js row prints `process.version`, which in a SEA is the embedded runtime, so the version is exact by construction and the inventory carries no Node version at all.
- **One source for the Go report: the build that compiled renet.** `build_renet` runs a pinned `go-licenses report ./... --ignore github.com/rediacc/renet` and writes `private/bin/renet-go-licenses.csv` beside the binaries; `ci-build-renet.yml` uploads it in the same `renet-binaries-<sha>` artifact that `ci-build-cli.yml` already downloads into `private/bin/`. The generator reads the CSV; with neither the CSV nor the submodule it emits the placeholder, and the release path refuses a placeholder (next bullet). This avoids checking out a private submodule in six SEA legs. The go-licenses version is pinned through `.ci/config/pins.json` like every other tool, never `@latest`.
- **Release builds fail closed.** `prepare_cli_assets` gains `--release` (set by `build_cli_executables` whenever the version is not `0.0.0-dev`): any `NOT GENERATED` section, any SPDX id with no committed text, or a missing Node LICENSE fails the build. Dev builds keep the placeholder.
- **npm report from the bundle.** `bundle.mjs` writes an esbuild metafile; the generator maps each bundled `node_modules/<pkg>` input to its version and licence from the lockfile, so the list is exactly what the bundle contains. The Node runtime's own notices come from the `LICENSE` file of the exact Node release that builds the SEA (`https://raw.githubusercontent.com/nodejs/node/<process.version>/LICENSE`, fetched at build time with a recorded sha256 in the output).
- **Canonical texts committed.** One file per SPDX id under `packages/cli/src/data/third-party-licenses/`, copied byte-exact from the SPDX license-list-data release pinned in `pins.json`, covering every id in the inventory and in both reports. The generator appends each text once.
- **The mirror.** `rediacc_ci.deploy.mirror_third_party_src` reads `embed-assets.lock.json`, downloads each embedded component's upstream source, verifies a `sourceSha256` recorded in the lockfile (new field; rsync's already exists as `RSYNC_SHA256`), and uploads write-once to `third-party-src/` (HEAD first; an existing object with a different sha256 is a hard failure, never an overwrite). For the binaries Rediacc compiles (CRIU, rsync) it also uploads the build recipe (the Dockerfile builder stages, extracted verbatim) as `<name>-<ver>-build.txt`, and for the static rsync the Debian/Ubuntu source packages of each statically linked library at the exact versions the builder stage installed, recorded by a `dpkg-query` manifest the stage writes. It runs as a STEPS entry after `upload-cli-r2` in `release/local.py` and as the matching step in `cd-stage.yml`, so the mirror always matches the release that conveys the binaries.
- **Out of scope:** a `renet credits --licenses` full text on machines (renet reaches a machine only through rdc, whose notices cover it); company-ring release notes; `server:stable` or any channel logic.

## Risks

- The written offer is a legal statement. The plan changes its facts (mirror live, recipe included) but not its wording beyond the mirror sentence moving from "will additionally mirror" to "mirrors"; any further wording change belongs to the operator.
- Mirroring Ubuntu source packages for the static rsync adds a few hundred MB per rsync or Ubuntu bump to a bucket already trimmed for size (`.ci/rediacc_ci/housekeeping/cleanup_versions.py:161`). Write-once keys under `third-party-src/` are outside the release-folder retention, so they stay as long as any conveyed binary needs them; a bump adds objects and removes none.
- Failing release builds on an incomplete notice can block a release over a network blip (go-licenses or the Node LICENSE fetch). That is the intended trade: a release without its notices is the defect this plan fixes. The local release path can retry the step.
- go-licenses misclassifies some modules as `Unknown`. C2's ignore list covers renet's own packages only; any other `Unknown` row fails C1's SPDX-text check and needs a named override in the generator, never a blanket skip.
