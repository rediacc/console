## Ask

`rdc mcp serve` and the hosted MCP Worker expose the same tools with the same names, input schemas, annotations and error codes (D18). Both run MCP SDK v2 against spec 2026-07-28 (D12). A tool call returns within about 60 s; longer work returns a job handle (D15). Every MCP tool is either proxy-capable (served remotely) or marked local-only with a stated reason, and a gate keeps it that way.

## Decisions

- D12: SDK v2 for the local stdio server and the remote Worker.
- D15: a tool call returns within about 60 s; long work returns a job handle plus status and wait tools.
- D57: every one of the 44 non-proxy-capable tools is remote-capable by default, moved onto the executor against the session config; `local` needs a written reason (it reads the caller's own disk, or it needs a terminal).
- D18: local and remote expose identical tools.
- D21: `needs_confirmation` from `decide()` maps to MCP elicitation where the client declares it, else a confirm argument on the retry. This plan implements the stdio half; the Worker half is PLAN-rmcp-remote-worker.md.
- D49, D50: the stdio server is proved against an on-premise config with the same scenarios as eu-bench.
- Clean break: the v1 server and its code paths are deleted, not kept beside v2.

## Design

1. **One registry, generated, shared.** `packages/cli/scripts/generate-mcp-registry.ts` reads the contract and `COMMAND_METADATA` and writes `packages/shared/src/mcp/tools.generated.json`: per tool its name, description, JSON input schema, annotations, `surface` (`proxy` or `local`), `localReason`, timeout class and attach-window flag. `packages/shared/src/mcp/registry.ts` exposes typed accessors and the error-code enum (`REDIACC_GRANT_EXPIRED`, `REDIACC_GRANT_REVOKED`, `REDIACC_KEY_ROTATED`, `POLICY_DENIED`, `NEEDS_CONFIRMATION`, `BUSY`, the contract exit codes). The local server and the Worker both build `tools/list` from it; the Worker filters to `surface === 'proxy'`. The three custom tools move into metadata or into the registry as hand-declared entries with the same fields.
2. **Explicit surface marker.** `CommandMeta` gains `mcpSurface: { kind: 'proxy' } | { kind: 'local', reason: string }`. The generator refuses a tool whose marker disagrees with the contract (`proxy` on a command whose `proxyCapable` is false).
3. **The surface table (LM2, D57).** The default verdict is `executor` or `in-memory`; `local` is allowed only with a written reason that the tool reads the caller's own disk or needs a terminal, and the coverage test refuses any other reason. Each of the 44 non-proxy-capable tools gets one verdict with a reason, written to `.ci/config/mcp-surface.json`: `executor` (make it run on the executor; the command change is listed for the owning plan), `in-memory` (re-implement against the granted config the executor already holds, e.g. `config show` redacted, `machine list`, `repo secret list`), or `local` (meaningless remotely, e.g. `version`, `legal`, `config current`). Config-plane writes (`machine add`, `machine provider add`) become `executor` only once PLAN-rmcp-writeback.md lands, and keep the knowledge gates.
4. **Honest annotations.** `readOnlyHint` comes from a contract read flag (or `timeout: 'read'` where no flag exists), `destructiveHint` from `mcp.destructive`, `idempotentHint` from `mcp.idempotent`, `openWorldHint: true`. A table test pins each of the three classes.
5. **`job_wait`.** A new tool takes a job id and blocks up to 50 s, returning the terminal result or the latest state plus a `nextPollSeconds` hint. Marked read-only and idempotent.
6. **Result paging.** Results above 100,000 characters return the first page plus a `cursor`; a `page` argument on `job_logs`, `repo logs` and `config audit log` fetches the next one. The ceiling stays under the claude.ai 150k-character cap.
7. **Guards out, decide() in (LM4).** `tools.ts` keeps no guard. The child `rdc` process reaches `decide()` at dispatch; the MCP layer maps a `deny` to `isError: true` with `structuredContent { code, reason, next }`, and `needs_confirmation` to elicitation (form mode) when the client declared it, else to an error naming the `confirm` argument.
8. **Parity snapshot.** `packages/shared/src/mcp/__tests__/tools-list.snapshot.json` is the canonical `tools/list` for the proxy surface. The local test asserts the stdio server's list filtered to proxy tools equals it; PLAN-rmcp-remote-worker.md asserts the Worker's list equals it.
9. **On-premise suite.** `.ci/rediacc_ci/testrun/onprem_suites/local_mcp.py` spawns `rdc mcp serve --config <on-premise config>` with the SDK v2 client over stdio and runs the LM9 scenarios (read, fork write, refused grand-repo write without the opt-in, admitted write with the opt-in and the policy allowing it), plus `tools/list` equal to the parity snapshot of Design 8; `--compare bench` holds the verdicts and codes equal to the eu-bench run.
