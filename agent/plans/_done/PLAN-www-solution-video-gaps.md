# PLAN: solution-page video coverage in packages/www
Status: done
Owner: e580532b
Updated: 2026-08-31

Investigation dispatched as a Plan agent, findings verified by hand, implementation done same session per operator authorization.

## Ask

1. Gap analysis: which of the 26 video-catalog slugs are missing from
   `packages/www` pages, or have a page that doesn't embed the video.
2. Confirm/refute whether teaser videos are used anywhere on the site.
3. Verify the fix live with `agent-browser`, not just source inspection.
4. Live URL for the operator to review.

## Findings

**Source of truth**: `packages/www/src/data/video-manifest.json`'s `solutions` key (currently agrees with `private/growth/video_pipeline/processing/*`, 26 slugs both places).

**Gap confirmed**: `packages/www/scripts/check-solution-videos.ts` only derives its "should have video" set from `src/config/solution-pages.ts` (21 entries), so it structurally cannot see persona pages or the homepage. Reading the actual templates directly:

- `SolutionPage.astro` (21 pages): fully wired, `has('video')` gates an
  `SPSolutionVideo` slotted into `SPHero`. Zero gaps.
- `PersonaPage.astro` (`for-devops`, `for-ctos`, `for-ceos`, `for-ai-agents`):
  had a live page, a complete manifest entry, correct slug — but the template never imported `SPSolutionVideo` and `persona-pages.ts` never listed `'video'` in `sections`. The video was published and unreachable.
- `SPHomePage.astro` / `SPHomeHero.astro` (`home`): same story, no video
  component referenced anywhere.

All 5 gap slugs were manifest-complete only for `en` (1 locale vs. 13 for every other slug) — because nothing consumed them, they were never published past the initial one-off `en` publish.

**Teaser claim confirmed true**: zero references to `.teaser.` anywhere in `packages/www/src`. `video-manifest.json`'s schema has no `teaser` field. Traced upstream: `private/growth/video_pipeline/publish.py`'s `publish_slug()` uploads only `mp4` and `vertical` — the teaser file is generated by `step8000_teaser.py` and never referenced anywhere else in `publish.py`. It's structurally unreachable from the site, not a component oversight. Per the operator, this stays informational only this round.

## Implementation (done this session)

1. `packages/www/src/config/persona-pages.ts` — added `'video'` right after
   `'hero'` in all 4 persona entries' `sections` arrays.
2. `packages/www/src/components/solution-pages/PersonaPage.astro` — imported
   `SPSolutionVideo`, mirrored `SolutionPage.astro`'s exact hero/video ternary (`has('video')` gates passing `SPSolutionVideo` as `SPHero`'s child). Also added the `<script src="../../scripts/tutorial-video-hydrate.ts">` tag `SolutionPage.astro` carries and this file never did — without it the video mount div renders with correct data attributes but never becomes a real player (caught live by the agent-browser pass, see Verification).
3. `packages/www/src/components/solution-pages/SPHomeVideo.astro` — **new**
   component. The homepage hero (`SPHomeHero.astro`) is deliberately minimal per its own documented operator decisions (L5: no simulated terminal; n6: no CTA buttons in any hero), so the video was NOT slotted into it — that would undo a decision already made. Instead it's its own section, placed right after the hero and before the solution constellation, reusing the `.sp-hero-media` CSS class (for the video-toolbar dark-theme fix and mobile width cap) without the `.sp-hero-split` two-column grid it's normally paired with.
4. `packages/www/src/components/solution-pages/SPHomePage.astro` — wired in
   `SPHomeVideo`, and added the same hydrator `<script src>` tag as step 2.
5. `packages/www/src/components/solution-pages/SPHero.astro` — corrected a
   comment that had gone stale the moment step 2 landed ("PersonaPage does not [pass children]").
6. Published all 5 slugs to R2 across all 13 locales (already fully rendered
   by the video pipeline; this was a publish-only step, not a new render) via `private/growth/video_pipeline/run.sh --publish-www --slug <name>`, which also merges the missing 12 locale entries into `video-manifest.json` through its own safe per-file merge path (`generate-video-manifest.ts`'s destructive full-rescan is deliberately never called by this flow).

## Verification

- `npx tsc --noEmit --project packages/www/tsconfig.json`: zero new errors
  (pre-existing `window.plausible`/`window.openRegionPicker` errors unrelated, none in any file this change touched).
- `npm run build -w @rediacc/www`: clean, "1814 page(s) built... Complete!".
- Live dev server (`./run.sh account dev` inside the devbox,
  `http://0827-1-account.localhost:8090/`): confirmed via raw HTML that `/en/for-devops`, `/en/for-ai-agents`, `/en/for-ceos`, `/en/for-ctos`, and `/en` (home) all now emit a `video-player-mount` element with correct `data-video-src`/`data-vertical-src`/`data-poster-src` pointing at real, existing local asset files.
- `agent-browser` pass against a clean `npm run build` + `astro preview`
  (the live devbox dev server has a pre-existing, unrelated Vite-HMR-through-proxy hydration failure affecting the whole site, not just this change — confirmed by the same failure on `ContactModal.tsx`/`NewsletterReturnPopup.tsx`; the preview build has no such issue). All 8 pages confirmed with a real, loaded `<video readyState=4>` element: `for-devops`, `for-ai-agents`, `for-ceos`, `for-ctos`, `home` (the 5 gap pages) plus `environment-cloning`, `ai-pentesting`, `kubernetes-cluster-mobility` (3 solution-page controls across distinct `sections` shapes). `home`'s video additionally confirmed actually PLAYING (`v.play()`, then `paused: false, currentTime: 0.7s`), not merely present.
- This surfaced a SECOND real gap beyond the template wiring: `SolutionPage.astro`
  loads `scripts/tutorial-video-hydrate.ts` (the script that mounts the actual Plyr player onto the `.video-player-mount` placeholder div), but neither `PersonaPage.astro` nor `SPHomePage.astro` did — so before this fix the video mount div would have rendered in the HTML with correct `data-*` attributes but never become a real, playable video. Fixed by adding the same `<script src>` tag to both.

## What's deliberately not done this round

- No og:video/social-meta or hover-preview surface built for teaser videos —
  operator said informational only.
- No change to `check-solution-videos.ts`'s scope (it still only covers the
  21 `SOLUTION_PAGES` slugs) — the 5 gap slugs are fixed at the template level; widening that gate's scope to also assert persona/home coverage is a reasonable follow-up but was not part of this ask.
