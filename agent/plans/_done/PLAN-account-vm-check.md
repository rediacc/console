## Why

The operator asked that private/account changes be gated before a push the way renet changes are. The ruling settles how: one trigger module, one runner, one receipt and one guard, with no separate account:check.

Today `CONSOLE_PATHS` and `RENET_PATHS` are the whole trigger (.ci/rediacc_ci/drills/vm_check_trigger.py:20-31). Only `private/renet` is diffed inside the submodule when its gitlink moves (:110-179). A `private/account` gitlink move fires nothing, and the push guard admits it untouched (.claude/rediacc_hooks/guards/block_vm_unverified_push.py:487-499 and 708-710).

`RENET_PATHS` names four prefixes: `cmd/renet/sandbox_`, `pkg/sandbox/`, `pkg/orchestration/` and `pkg/reporuntime/` (.ci/rediacc_ci/drills/vm_check_trigger.py:26-31). Every other non-test Go file under `cmd/` and `pkg/` is also built into the renet binary that `./rdc.sh` deploys to the worker. From 2026-10-01 to 2026-10-15 renet had 80 non-test commits under cmd/, pkg/, go.mod, go.sum and embed-assets.lock.json; the four prefixes saw 24 of them, so 56 deployed-code commits passed the guard untouched.

The receipt digest covers the console trigger blobs plus the renet gitlink only (.ci/rediacc_ci/drills/vm_check_trigger.py:241-258 and 282-299), so a receipt says nothing about the account pointer.

The dev gateway does not hot-reload (.claude/agents/account-dev.md:18). A gateway reused after an account change serves the old code, so account drills run against it would prove nothing; the runner must show that the gateway is newer than the account inputs before it reuses it.

The license drill cannot run its legs c, d and e on the basic fleet today. They need a licensed repo on the worker, and only leg a creates one (.ci/rediacc_ci/drills/license.py:356-368). Leg a needs Ceph (:398-411) and leg b needs .12 (:390-396). vm:check uses the basic fleet (.1 + .11).

### ci:quick finding: refuted, no paths added

The session report said ci:quick does not select check:ci-account-server and check:ci-test-account-web on an account gitlink move. Neither gate declares `paths` (scripts/ci-runner/manifest.ts:3552-3567 and 3636-3651), and rule 4 of `touchedSlow` selects a gate with no paths on every non-empty change set (scripts/ci-runner/quick-select.ts:205-210). A live `npx tsx scripts/ci-runner/run.ts --quick --list` printed `+ SELECTED check:ci-account-server` and `+ SELECTED check:ci-test-account-web: it declares no paths, so any change may reach what it reads (the --changed fail-open rule)`.

Decision: add no `paths`. private/account imports `@rediacc/shared` 148 times (`file:../../packages/shared`, private/account/package.json:46 and private/account/web/package.json:18), so a `paths` list that left out packages/shared/** would drop both suites on a shared-package change.

## Design

### 1. Trigger (vm_check_trigger.py)

There are two sides, `SIDE_RENET = "renet"` and `SIDE_ACCOUNT = "account"`. `Changed` gains `sides: frozenset[str]`: a renet hit or unknown renet range adds the renet side, an account hit or unknown account range adds the account side, and a console path adds the sides it is mapped to. `touched` keeps its meaning.

`RENET_PATHS` becomes `("cmd/", "pkg/", "go.mod", "go.sum", "embed-assets.lock.json")`, the deployed renet binary's inputs. Every non-test `//go:embed` source sits under `cmd/` or `pkg/` (cmd/renet/gpu_keys, pkg/embed/{proxy,datastore,assets}, pkg/ebpf/*.o, pkg/kube/csidriver/crds, pkg/infra/cephpkg/keys, pkg/compose/*.tmpl), and `embed-assets.lock.json` fixes which third-party binaries `build.sh` stages into pkg/embed/assets. `build.sh`, the Makefile and the Dockerfiles stay out: vm:check deploys the `./rdc.sh` build, not a Docker image.

`ACCOUNT_SUBMODULE = "private/account"`. `ACCOUNT_PATHS`, relative to it: `src/`, `web/`, `drizzle/`, `scripts/`, `package.json`, `package-lock.json`, `tsconfig.json`, `wrangler.toml`, `dev.defaults.env`, `docker-compose.yml`, `Dockerfile`. Left out: tests/, e2e/, docs/, *.md, test-results/, .claude/.

The shared exclusion widens to suffixes `_test.go`, `.test.ts`, `.test.tsx`, `.spec.ts`, `.spec.tsx` and fragments `/__tests__/`, `/testdata/`, `/tests/`, `/e2e/`. Test-only changes leave both the deployed binary and the served code unchanged (D2 of PLAN-vm-check.md).

`CONSOLE_PATHS` becomes a mapping from path to sides: `packages/cli/src/remote/` and `packages/cli/src/services/repo/repo-key-deployment.ts` map to {renet}; `.ci/rediacc_ci/drills/license.py`, `universe.py` and `transfer.py` map to {account}; `.ci/rediacc_ci/drills/vm_check.py` and `.ci/rediacc_ci/drills/lib.py` map to {renet, account}.

`_renet_range` and `_renet_worktree_moved` become `_submodule_range(root, sub, old, new, mode)` and `_submodule_worktree_moved(root, sub, old, changed)`, run once per submodule. An unknown range is reported as `"<sub> <sha>: <why>"` so the guard can name the side.

The digest moves to version 2, hashing a leading `v2` line, the sorted console trigger blob lines (all sides), then `private/renet <ptr or none>` and `private/account <ptr or none>`. In `inputs_of_tree` the pointers are the tree's gitlinks; in `inputs_of_worktree` each submodule's HEAD. The version line keeps a version 1 digest from matching a version 2 one.

New helpers: `account_modified(root) -> bool | None` (true when `git -C private/account status --porcelain -- <ACCOUNT_PATHS>` lists a non-excluded entry, None when unreadable) and `account_worktree_digest(root) -> str | None` (hash of `git -C private/account ls-files -s -- <ACCOUNT_PATHS>` plus `hash-object` of every modified or untracked trigger file), the gateway freshness key of Design 3.

### 2. Receipt (vm_check_receipt.py)

`SCHEMA = 2`, a clean break: `validate` rejects `schema != 2`, `_load` returns None for such a file (.ci/rediacc_ci/drills/vm_check_receipt.py:124-129), and `admit` reports `no-receipt` when only old receipts exist. The guard's `vm-unavailable` escape reads receipts through the same `_load`, so an old NOT_VERIFIED receipt cannot back an escape. Old files in `.ci/cache/vm-check/` stay (gitignored, unread); the runner prints one line saying earlier receipts no longer count.

New required fields: `phases` (`{"renet": {"required": bool, "ran": bool}, "account": {...}}`) and `account` (`{"pointer", "checkout", "modified": bool | null, "gateway": {"mode": "reused" | "started" | "restarted" | null, "port", "started": int | null}}`). `trigger` gains `sides`. `validate` requires both objects, the booleans per phase, and for VERIFIED at least one phase ran and every required phase ran.

`admit(root, tree, inputs_digest, sides)`. `_judge` keeps its order and appends after `modified-build`: `phase-missing` (a side in `sides` whose phase did not run; names the side and `npm run vm:check -- --changed`), `account-mismatch` (account side and `account.checkout != account.pointer`), `modified-account` (account side and `account.modified is not False`).

### 3. Runner (vm_check.py)

Phase selection: with `--changed`, `sides` from `changed_paths`; with no `--changed` or an unresolved push base, both phases. Recorded in `phases.*.required` and `trigger.sides`.

Step order:
1. A1 (account only, before P0, so the fleet lock is not held for the suites; a FAILED A1 stops before any VM is touched): A1.1 `npm run check:ci-account-server`, A1.2 `npm run check:ci-test-account-web`, A1.3 `npm --prefix private/account run typecheck`, A1.4 `npm --prefix private/account run typecheck:web`. One assertion row each with rc and ms; a non-zero rc is FAILED with the last three output lines as evidence.
2. P0 lock.
3. P1 renet build check (always: the license drill also deploys renet and `admit` checks `renet.built == renet.pointer`).
4. A0 (account only): dev gateway freshness, below.
5. P4 token. 6. P2 fleet. 7. P3 keys.
8. A2 (account only), against .11: A2.1 `python3 -m rediacc_ci.drills.universe --no-restart`, A2.2 `python3 -m rediacc_ci.drills.transfer --no-restart`, A2.3 `python3 -m rediacc_ci.drills.license --legs c,d,e,f --no-restart --seed-repo --vm <worker_ip>`.
9. P5 and V1.1-V1.7 (renet phase only).
10. T teardown.

A2 runs before P5: the license drill rebuilds bin/renet with `RDC_RENET_LICENSE=1` and `machine setup` deploys that enforcing flavor to .11 (.ci/rediacc_ci/drills/license.py:451-461, 538-555); the first plain `./rdc.sh` of P5 redeploys the default flavor of the same commit before the V-steps.

A0: a record `.ci/cache/vm-check/gateway.json` holds `{port, started, account}` for the last gateway this runner started. Reuse only when the gateway is healthy, `.account-state`'s `started=` and `gateway_port=` equal the record, and `account_worktree_digest` equals the record's `account`. Otherwise `lib.Drill.restart_gateway(log_path=.ci/cache/vm-check/gateway.log)`, write the record (mode `started` or `restarted`), then `Drill.detach_gateway()` so teardown leaves it running for the next run. A start failure is NOT_VERIFIED `account-gateway` with the log tail. The restart is printed with a note that dev passwords rotated and the port may have moved.

A2 classification reads the drill's summary line `%d assertions: %d passed, %d failed` (.ci/rediacc_ci/drills/lib.py:420-423): failed > 0 is FAILED naming the drill; rc 0 with a positive count and `PASSED` is ok; a `SKIPPED` line or rc 0 with 0 assertions is NOT_VERIFIED `account-drill-skipped`; a non-zero rc with no summary is NOT_VERIFIED `account-drill-setup` (a preflight `SystemExit`, e.g. transfer's missing keyring, .ci/rediacc_ci/drills/transfer.py:95-100).

Drill and suite children run under `self.environ` with `REDIACC_TOKEN`, `REDIACC_ACCOUNT_SERVER`, `RDC_DEV` and `DRILL_EXPECT_NO_KEYRING` removed, never `child_env()`, so a declared keyring skip cannot turn into a pass and the minted token never reaches a drill.

`verdict()` gains, after `reason` and before `no-assertions`: a required phase with `ran` false is NOT_VERIFIED `phase-not-run`. `phases.<side>.ran` is true only when every row of that phase was ok. `account.pointer` comes from `HEAD^{tree}:private/account`, `checkout` from the submodule HEAD, `modified` from `account_modified`.

### 4. lib.py and license.py

`Drill.gateway_port()` returns the last `gateway_port=` line, matching rdc.sh:115 (landed in 2cb380349). `Drill.restart_gateway(log_path=None)` writes to `log_path` when given, so a detached gateway's log survives the work directory. `Drill.detach_gateway()` sets `gateway_proc = None` without stopping it.

license.py gains `--seed-repo`: when legs a and b are off and `ensure_repo_present` finds no licensed repo on `--vm`, it runs `repo create drill-repo -m drill-lic-1 --size 1G` (leg a's issuance step, .ci/rediacc_ci/drills/license.py:740-756) and asserts rc 0, only on a worker on the ops VM network (the `is_ops_vm_ip` predicate); any other worker keeps the current refusal. The docstring records this as a Rule T difference.

### 5. Guard (block_vm_unverified_push.py)

`_hits` also returns `changed.sides`, each unknown range spelled with its submodule. The judge loop calls `receipt_mod.admit(root_path, tree, digest, sides)`; the REFUSAL names the sides and each phase's cost. `world()` gains a real `private/account` gitlink. New FIXTURES: `vmc-account-src`, `vmc-account-tests-only`, `vmc-account-renet-receipt`, `vmc-account-verified`, `vmc-account-missing-old`, `vmc-renet-wide` (pkg/license/x.go), `vmc-renet-gomod`, `vmc-schema-1`. `plant_receipt` writes schema 2. Docstring: line 1 names the three surfaces; WHAT IS TOUCHED says both submodules are diffed and each side counts on its own; THE RECEIPT adds the phase rule, `account-mismatch`, `modified-account` and the schema 1 break; THE ESCAPE keeps its kinds (`vm-unavailable` names a NOT_VERIFIED receipt such as `account-gateway`; `not-runtime` names the account or renet files).

## Decisions taken with defaults (veto any)

1. D1 (typecheck scope): A1.3 and A1.4 run private/account's own `typecheck` and `typecheck:web`, not the root `npm run typecheck` (113.8 s, mostly CLI, www and scripts, which ci:quick already gates).
2. D2 (packages/shared): not an account trigger path although private/account imports it; adding it would charge the account phase on most CLI pushes, and CI's `check:ci-account-server` still covers it.
3. D3 (license legs): c, d, e and f on the basic fleet with `--seed-repo`; legs a (Ceph) and b (.12) stay the full-cluster drill's job.
4. D4 (gateway lifetime): a gateway vm:check starts is left running and recorded for reuse; one owned by another writer is restarted once, which rotates dev passwords.
5. D5 (runner and harness files are triggers): `vm_check.py` and `lib.py` select both phases; `license.py`, `universe.py` and `transfer.py` select the account phase.
6. D6 (no `--phases` flag): `--changed` selects the phases and a bare run does both.
7. D7 (ci:quick): no `paths` added to the two account gates (see the ci:quick finding).

## Risks

- The `account-vitest` mutex holds only inside one ci-runner process, so A1 beside another session's ci:quick account suites can contend; the receipt records ms per row.
- After an account-only run the worker keeps the enforcing renet the license drill deployed until the next plain `./rdc.sh` call.
- Restarting the gateway can move its port; configs pinned to the old port lose their writes (.claude/agents/account-dev.md:15). A0 prints the new port.
- Leg c needs the gateway reachable from .11 at the bridge address (.ci/rediacc_ci/drills/license.py:463-475); a host firewall blocking it fails A2.3 as an assertion.
- `drill-repo` persists on .11 after `--seed-repo`; P5 sweeps only `vmc-` forks.
- Widening the renet trigger brings 80 renet commits in 15 days into scope against 24 before; the digest carry-over still spares commits outside the trigger.
