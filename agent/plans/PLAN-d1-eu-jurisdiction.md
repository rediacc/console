## Design

1. **Naming.** No rename exists and the old database stays 30 days, so the new databases take a lasting new name: `account-eu` -> `account-eu-j`, `account-bench` -> `account-bench-j`, `control-bench-eu` -> `control-bench-eu-j`, `control-bench-us` -> `control-bench-us-j`. regions.json gains `d1.jurisdiction` (eu `"eu"`, us/asia `null`); the gate pattern becomes `account-<r>` plus `-j` exactly when `d1.jurisdiction` is set. Bench R2 buckets keep their names (`configs-bench`, `backups-bench`), recreated in jurisdiction eu.
2. **Write freeze: a fence row in the database, enforced at the D1 handle.** `workers/account/src/d1-fence.ts` wraps `env.DB` at every entry (fetch, scheduled, queue in workers/account/src/index.ts; the DO constructor in backup-replicator.ts). Reads pass (`SELECT`, `WITH ... SELECT`, read-only `PRAGMA`); any other statement throws `WRITES_FROZEN` while table `_write_fence(id INTEGER PRIMARY KEY CHECK (id = 1), reason TEXT, set_at TEXT)` holds a row (new migration; 10 s per-isolate cache). HTTP answers 503 `WRITES_FROZEN` with `Retry-After: 120`; the replicate queue retries with 300 s delay; crons skip; DO alarms reschedule. The fence lives in the old database, so any Worker version still bound to it refuses writes: no split brain. After `fence on` the verb waits 2xTTL + 30 s and checks live leases.
3. **The relocate verb `rediacc_ci.ops.d1_relocate`** (the one path): `plan` (read-only sizes, jurisdictions, live leases), `create` (`wrangler d1 create <to> --jurisdiction eu`, then the API must report eu), `fence --on|--off`, `bookmark` (deploy_record.d1_bookmark into the run record), `copy` (fenced source required; export, strip `_write_fence` and `_cf_*`, import, then `verify`). `verify` checks per table row count and canonical sha256 ordered by primary key, `d1_migrations` equal, `PRAGMA foreign_key_check` with a failed call = exit 1, and nothing pending. `record` writes `.ci/state/d1-relocate/<from>.json`; `reverse` is the rollback after thaw; `retire` runs only at >= 30 days, with no toml or regions.json naming it, a final export present, and `--yes-delete <from>` typed exactly. Without `--write` every subcommand prints and changes nothing. Credentials: `deploy-workers` (production), `deploy-bench` (bench).
4. **R2 relocate:** `r2_bucket_copy --relocate --from B --from-jurisdiction default --to B --to-jurisdiction eu` streams GetObject to PutObject across endpoints, keeping metadata, re-runnable; `--verify --deep` compares sha256 per key. Bucket settings (CORS, lifecycle, notifications) are copied and asserted equal.
5. **Cutover order** (bench identical with deploy_bench): ship the fence; `plan`, `create`; `fence --on <old>`, drain; `bookmark`, `copy` + `verify`; repoint on the pushed branch (toml, regions.json); `release:local --branch-release --regions eu`; smoke reads while the old one is fenced; writes resume on the new database (no fence row); smoke writes; the repoint rides the open PR; the old database stays fenced.
6. **Rollback:** before writes resume, revert the repoint, redeploy, `fence --off <old>` (lossless). After writes resume, fence the new one, `reverse`, repoint back, redeploy, unfence the old one. Last resort: the old database's Time Travel bookmark (30 days).
7. **Smoke:** `verify_edge_endpoints` server-info, `portal_health --target edge --region eu`, the proxy `/v1/ready`, and a new `rediacc_ci.ops.region_smoke --region eu|bench` (headless login with a probe account, `rdc config pull`, content hash equal to the pre-freeze baseline), plus `region_consistency_live`.
8. **Retention:** old D1s and the old default-jurisdiction bench buckets stay 30 days, then `retire` after a final `backup_d1` export.
9. **Residuals listed, not moved:** bench queues, Analytics Engine, DO namespace (DO jurisdiction is chosen in code). Out of scope and listed for the operator: `control-eu` and every eu enterprise company `account-<c>` D1 (created with `--location` only); W3 makes future creation pass `--jurisdiction`.
