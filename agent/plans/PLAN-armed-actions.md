## Design

1. **Event model (the store is the only truth).** Four events, written through `append_events`. `aid` is 8 hex of sha256 over item id, arm stamp and `when`, so every re-arm is a new generation, and the fold ignores an event naming a stale `aid`.
   - `{"ev":"arm","id":<item>,"at":<Z>,"by":<me8>,"aid":<8hex>,"when":[<token>,...],"run":<path or "">,"cmd":<line or "">,"sha":<12hex of brief or "">,"lease":<lease-id or "">,"exp":<Z>}`
   - `{"ev":"armfire","id":..,"at":..,"by":..,"aid":..,"v":"fired|expired|void","why":<evidence>}`, written by the Stop hook only; the latch. `why` names the artifact and the field values read.
   - `{"ev":"armstart","id":..,"at":..,"by":..,"aid":..}`, which consumes the action.
   - `{"ev":"disarm","id":..,"at":..,"by":..,"aid":..,"why":<text>}`.

   The fold keeps `rec["arm"] = {aid, when, run, cmd, sha, lease, exp, at, by, fired_at, verdict, why, started_at}`. A second `armfire` for the same `aid` is a no-op (first wins). An item in `x` or `~` makes its arm inert. The compaction builder emits `"am": rec["arm"]` on the item's `add` event while the arm is armed or fired, and `_fold_events` reads it back.
2. **Trigger grammar.** `--when` may repeat; conditions combine with AND.
   - `NOT-BEFORE:<ISO8601Z>`: the `[?]` regex and `parse_stamp`; the 7-day cap applies with the arm stamp as base; an instant at or before now is refused. Fired when `utcnow() >= instant`.
   - `REPORTED:<agent-id>` or `REPORTED:#<item>` (resolved at arm time to the item's lease worker): fired when an `index.jsonl` row with `source == "hook"` names that agent with `at` after the arm stamp. An agent with no meta in this session at arm time is refused.
   - `EXIT:<task-id>`: must be listed running in the last-event file at arm time. Fired when the current Stop event no longer lists it running, no `/proc` pid writes `tasks/<id>.output`, and the hook's state doc saw it running on at least one stop after the arm.
   - `CI-QUICK:done`: `.ci/cache/prepush-receipt.json` parses, `whole is True`, `exitCode` is an int, and `finishedAt` is after the arm stamp, whatever the exit code.
   - `CI-QUICK:verified`: the push guard's reading, factored out of `green_receipt_on_unpushed_head` as `receipt_green_for_head(root)`.
   - `VM-CHECK:done`: `.ci/cache/vm-check/receipt.json` validates through `vm_tier.validate` and `finishedAt` is after the arm stamp. `VM-CHECK:verified`: `wl_boxready.vmcheck_admits(root)`.
   - `BENCH:deployed` (`wl_boxready.bench_at_branch`) and `PUSHED:head` (`wl_boxready.head_pushed`).
   - `NEEDS:<value>`: sugar resolved at arm time (`bench-deploy` to `BENCH:deployed`, `verified-vmcheck` to `VM-CHECK:verified`, `pushed-head` to `PUSHED:head`; `none` refused).
   - `DEFER-CLOSED:#<id>`: the item must be `[?]` with a DEFAULT at arm time; fired when it is still `?` and the defer-expired predicate holds; `void` if it leaves `?` first.
   - `TICKED:#<id>`: fired when the folded state is `x`; `~` means `void`; an unknown id is refused.
   - `BOX:<plan-path>#<sig8>`: the sig must be open in the committed plan at arm time; fired when `git show HEAD:<plan-path>` parses with that sig ticked; a sig absent from HEAD's plan means `void`. The working tree, plan-boxes.json and the investigation ledger are not read.
3. **What fires, and when.** Event tokens are monotone; state tokens (`*:verified`, `BENCH:deployed`, `PUSHED:head`) are judged live at the stop. The arm fires on the first stop at which every token holds at once, and the hook appends one `armfire` with each token's evidence; from then on the block depends only on the latch. `exp` defaults to arm stamp + 24 h for event arms and latest `NOT-BEFORE` + 24 h for time arms; `--expires +<hours>` allows up to 168 h; an unfired arm at `exp` gets `armfire v=expired`. Expired and void arms block too (Design 4), so no arm lapses silently.
4. **`armed-action-due`** (wl_checks.py, its own segment `armed-actions`, registered in wl_stopregistry.py after `defer-expired`). For each item the session owns (`C.owned_by_me`) whose arm is armed or fired, it evaluates unfired arms, appends any latch, and blocks for every fired, expired or void arm with no `armstart`; before the fire it is silent. The block names the item, the trigger evidence and one next step: `worklist.py --armed-start <me> <id>` then `cat <run>`, or the stored `cmd` verbatim. A `cmd` containing `worktree land` while `green_receipt_on_unpushed_head` holds names `git push` first. Expired and void arms name `--disarm` and the re-arm form. The brief is re-checked at fire time: missing at HEAD or a sha differing from the arm's makes the block say so and name re-arm. effort.json: `"armed-action-due": {"block": "smart", "advise": "low"}`; tier T_MISSION beside `defer-expired`.
5. **Not in the FLOOR.** An armed action is the session's own held work, and at `quiet` (for example under /pause) starting a held landing would defy the pause. The floor-grade half, a missed wake-up, is closed by extending `wake-timer`: its condition becomes `(live_bg or unfired_arms) and not _wakers`.
6. **Stand-downs, only while the hold is legitimate.** An arm covers its item and optional `lease` while armed, unfired and unexpired; after a fire it covers only while `armed-action-due` blocks at the current effort level, so exactly one check blocks at every level.
   - **worktree-unlanded.** `wl_worktrees.survey(..., armed=None)` moves covered rows from `unlanded` to an `armed` list, reported in one advisory line; uncovered rows still block. `--arm --lease` refuses while a `.hold` record exists and names `./run.sh worktree unhold <id>`.
   - **roster-dead.** An item with a covering arm gets coverer `armed:<aid>`, only when its worker's final report is captured; a worker that died without a report stays `leased_dead`.
   - **The 45/90/120 ladder** skips items with a covering arm.
   - **defer-expired** drops items named by a fired `DEFER-CLOSED` arm with no `armstart`.
   - **worker:queue.** `--arm` refuses an item leased `worker:queue` and names the unlease.
7. **Verbs (wl_cli.py).** `--arm <me> <id> --when <token> [--when ...] (--run <agent/<me8>/armed/<id>.md> | --run-cmd "<line>") [--lease <lease-id>] [--expires +<h>]`, which validates every token, requires the run file to exist, prints the commit line when it is untracked, records its sha, and refuses a second live arm; `--disarm <me> <id> --why <text>`; `--armed-start <me> <id>`, refused before the fire; `--armed-list <me>`; `--arm-from-survey <me> <survey.md>`. All write only through `append_events`.
8. **Briefs and compaction.** A brief lives at `agent/<me8>/armed/<item-id>.md`, written and committed by the lead while the analysis is fresh; its first line is the `--armed-start` command. `agent_state_problems(body, owed, armed)` gains the verdict `unarmed`: while the session has live arms, STATE.md must hold a `## Armed` section naming each `#<id>`. `--state` and the stop-time read pass the arms.
9. **Ties to /writers-now.** The survey gains section 10, `## Armed`, one row per distinct blocker (`blocker | dependent sigs | trigger | brief draft path`): a CODE cluster "blocked behind <sig>" maps to `BOX:<plan>#<sig>`, a LIVE step maps through `NEEDS:<value>`, and drafts go to `/tmp/writers-now/<stamp>-armed/<blocker-sig>.md`. `--arm-from-survey` turns each row into one item, one committed brief and one arm, run in step 2's PRESENT batch. `collect_seeds` gains `armed_seeds(items, session, since)` as its first group (kind `armed`, `KIND_MAX` applies, `MORE_WHERE["armed"]` is `worklist.py --armed-list <me>`). `writers-now-due` is unchanged.
10. **Stand-down placement.** `armed-action-due` goes into `_BUILD_ONLY` with the reason "starts held development work the moment its trigger fires; the landing tree finishes and does not start (ruling B2), and it owns no development arms". PR_LOOP keeps it, and a test asserts this by name (AA3).
11. **Adversarial summary.** False fire: event tokens compare against the arm stamp, state tokens use the push guards' readers, boxes are read from HEAD, EXIT needs both the harness list and `/proc`. Double fire: one live arm per item, first-wins latch per `aid`, silence after `armstart`. Missed fire: arms are carried by compaction (`am`), the latch is a store event, `wake-timer` forces a waker, expiry turns a fire that cannot come into a block. Stale trigger: a new `aid` per generation, receipts older than the arm ignored, `void` for answered deferrals, tombstoned blockers and rewritten boxes. Forged trigger: report rows need `source == "hook"`, receipts pass the guards' validators, box ticks must be committed, the brief sha must match, roster-dead is covered only for reported workers, every cover is bounded by `exp`. Accepted residue: a hand-crafted `armfire` in the store is no more forgeable than any other store event, and an older checkout compacting a dead session's file drops `am` until AA1 is on main.
