## Design

D1. **Migration scaffolding goes, behaviour stays** (from DB16). Each test that imports a shadow driver or compares against a bash twin is salvaged: a case asserting the port's own observable behaviour (exit code, a stdout or stderr fact, a written file) becomes a plain assertion with the expected value inlined; a case that only asserts "port bytes equal twin bytes" is deleted. A `tests/gates/` file is never deleted whole, and its CONTROL cases stay byte for byte. The goldens keep their coverage under a snapshot name: `twin` becomes `snapshot`, `as_twin`, `twin_names`, `SHIMMED_TWINS` and `--source bash` go, and stale `source: bash` headers are reset. Docstrings citing a deleted path are re-pointed to `commit:<sha>` of the deleting commit.
"Twin" here means shadow twins only; the input-hash Python hasher (PLAN-ciquick-cpu.md W1.2) is a different thing and stays.

D2. **One declaration per gate.** The gate file's header (`step:`, `lane:`, `why:`, inputs, `slow`, `cores`) is the single declaration. One generator (`gen:gates --write`) emits the manifest entries, gates.lock.json, the workflow steps, the shard placement and the generated doc regions; the runner calls `python3 -m rediacc_ci.quality.<x>` directly, so the entry shim and its package.json key go. One check (`--check`) replaces gates-lock, gate-manifest, gate-bind, parity, doc-region-parity, step-env-parity and workflow-orphan-step-keys. manifest.ts shrinks to overrides (aggregates, slow and heavy tuning). Target: a new gate is 2-3 hand-kept files. Clean break: no alias for a retired gate id.

D3. **One environment registry.** env-manifest, python-env-registry and the WORKLIST_* registry merge into one file with one gate; `env:register` writes it. Open boxes of other plans whose Accept names a retired gate id get a correction line naming the new one, in the same commit.

D4. **Pattern-only families become tables** (from DB19 and DB20). A family becomes one gate with an `{arm, pattern, message}` table. Every member's control survives as an arm, so the CONTROL count before equals the count after; retired ids leave every registration and every textual reference; check:ci-gate-reachability-coverage stays green; a member that is not pattern-only stays separate. The pin gates fold into check:ci-pin-freshness; the six secret gates become one static and one live gate; aggregate and alias entries go, and the 12 `.control.ts` registrations fold into their gate's `--selftest`.

D5. **Hook guards share one analysis and one table.** `shellscan.writes(cmd, cwd) -> [(path, how)]` covers redirects, in-place edits, git operands and interpreter code, with the parse cached once per `hookio.Event`. The edit/shell twin pairs (review_file, live_proof_ledger, user_only_command, suppressions, protected_files, roundlog) become rows `{id, paths, tools, message, sanctioned}` read by one guard per chain. The push-receipt guards become rows of "a push needs receipt X": one row per receipt kind (ci:quick, vm:check, backup, renet), each a predicate over the pushed range plus a receipt reader, with the two-track R4 CI-receipt verifier as one more reader behind the same interface and an admit-line parity test enumerating the rows.
Embedded `EDGE_CASES` and `FIXTURES` move to fixture files; copied helpers move to one shared module.

D6. **A loop that measures and retires.** dispatch.run_chain times each guard and appends one line per chain run: `{chain, refused_by, rc, slow: [[stem, ms]] for guards over 20 ms, session}`, one O_APPEND write per call. Lifecycle members and Stop checks feed the same ledger (Stop timing comes from PLAN-tooling-speed.md SP3). wl_hookreport.py generalises wl_trapfires.py: guards with no fire in N days, rules that fire often and are never confirmed, twins whose fire sets overlap, gates with no failure and their cost, and slow test areas, surfaced through wl_retro and the stop-hook-retros ledger. Budgets in `.ci/policy/hook-exec-baseline.json` fail in both directions: processes per call, chain latency p50, Stop p50, lines and test seconds per guard.
A committed snapshot `.ci/config/hook-ledger.json` is registered in freshness.json. Retirement stays an operator decision; the report names candidates.

D7. **Agent data off the hot path.** Finished sessions' worklist logs are folded once into a snapshot and skipped by the per-stop fold; `plan-investigation.jsonl` reads go through one cache keyed on mtime and size.
