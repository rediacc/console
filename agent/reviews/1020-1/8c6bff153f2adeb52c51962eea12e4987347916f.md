Claim: `p.peers` is built from the target's full `peerDependencies`, which also lists optional peers (`peerDependenciesMeta.optional`). An out-of-range package whose optional peer q has an unmet range therefore folds q into the install, although the commit message says a fold happens only when the target's range requires it. No test covers an optional peer, so the extra exact `q@latest` in the install goes unchecked.
Resolution: not-a-bug | npm enforces an optional peer's range whenever the peer is installed, and every foldable q is a declared, installed dependency of the manifest, so an unmet optional range fails ERESOLVE like a required one and folding it is correct; documented at scripts/gates/check-deps.ts:1242 (commit fbe704931) | d778be9d 2026-10-22T08:08:34Z
