Claim: PR_SET_PDEATHSIG is per thread, and lingerAsRepoViewInit runs on whichever OS thread the goroutine is on (the init stage never calls LockOSThread). If the goroutine resumes on a thread other than the one that was forked with SIGKILL (the main thread, after the long blocking Wait4 in superviseRepoViewChild), that thread keeps Pdeathsig, and when the outer stage exits the kernel SIGKILLs init and the namespace, which is the failure this commit fixes. The test passes only because the goroutine usually stays on the main thread.
