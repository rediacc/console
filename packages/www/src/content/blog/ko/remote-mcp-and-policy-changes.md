> **요약.** 원격 MCP는 AI 에이전트에게 터미널 대신 URL을 줍니다. 설계의 질문은 에이전트를 어떻게 연결하느냐가 아니라, 연결된 뒤 무엇을 볼 수 있어야 하느냐였습니다. 답은 그랜트를 만든 사람이 보는 것과 똑같은 범위이고, 그 이상은 아닙니다.
>
> - 그랜트는 **하나의 config**에 닿고 **하나의 리전**에 속합니다.
> - 토큰은 액세스 **1시간**, 리프레시 **30일**을 넘지 않으며 그랜트 자체보다 오래 유지되지 않습니다.
> - 그랜트는 하나의 config 콘텐츠 키와 두 개의 **정책 읽기 키**를 지니며, config 스토어의 마스터 키는 지니지 않습니다.
> - 정책 레코드 형식이 바뀌었습니다. 이전 레코드는 거부되며 마이그레이션 경로는 없습니다.

## 로그인 셸이 아닌 URL

로컬 MCP 서버(`rdc mcp serve`)는 에이전트 옆에서 실행되며 그 머신의 접근 권한을 그대로 물려받습니다. 원격 서버는 다릅니다. 리전마다 MCP Worker 하나가 `mcp.<region>.rediacc.cloud`에서 동작하고, 각 에이전트는 그랜트 하나의 URL(`https://mcp.<region>.rediacc.cloud/g/<grantId>`)에 연결합니다. 도구 호출은 개발자 노트북이 아니라 조직의 실행기(executor)에서 실행됩니다.

claude.ai 같은 대화형 클라이언트는 PKCE를 쓰는 OAuth 2.1로 로그인합니다. 헤드리스 에이전트는 `rmcp_<grantId>.<secret>` 형태의 bearer를 보냅니다. 두 방식 모두 그랜트를 식별하며, URL의 id는 이름을 가리킬 뿐입니다.

## 경계는 그랜트 자체

그랜트는 작고 구체적인 객체입니다. config 하나, 만료 시각, 범위(읽기 전용 플래그, 허용 도구 목록, 머신과 저장소 이름 패턴)를 지정합니다.

이 구조에서 세 가지 규칙이 나옵니다.

- **config 하나.** 다른 config를 지정한 `tools/call`은 아무것도 실행되기 전에 `REDIACC_GRANT_SCOPE`로 거부됩니다. config가 셋이면 그랜트도 셋을 승인합니다.
- **리전 하나.** 그랜트 id는 리전으로 시작합니다. 잘못된 Worker에 도착한 요청은 올바른 URL과 함께 HTTP 421로 응답하며 전달되지 않습니다.
- **수명 하나.** 액세스 토큰은 1시간과 그랜트의 남은 시간 중 짧은 쪽만큼 유지됩니다. 리프레시 토큰은 30일과 그랜트의 남은 시간 중 짧은 쪽만큼 유지됩니다. 리프레시할 때마다 그랜트를 다시 조회하므로 폐기된 그랜트는 다음 교환에서 작동을 멈춥니다. 리프레시 토큰을 두 번 제시하면 그랜트가 폐기됩니다.

그랜트 URL은 기본 7일, 최대 30일 동안 유효합니다.

## 담당자와 같은 기준으로 판단

흥미로운 부분은 키 구성입니다. 그랜트는 분할된 비밀입니다. 브라우저가 무작위 값을 만들어 한 번만 보여 줍니다. 계정 서버는 거기서 파생한 태그의 해시만 저장하고, 실행기는 두 조각을 모두 가진 동안에만 슬롯 키를 파생합니다. 이 슬롯 키가 여는 것은 config 자체의 콘텐츠 키이며 조직의 마스터 키가 아닙니다.

같은 슬롯 키는 두 개의 **정책 키**도 엽니다. 정책, 즉 config 항목의 권한 부여 규칙은 이제 별도 레코드에 있으며, 스토어 키와 레코드 포인터(스토어, config, 팀, 키 세대)에서 파생한 키로 봉인됩니다. 그랜트는 자기 팀 config의 키와 조직 수준 config의 키를 지닙니다. 이 둘이 담당자가 읽는 두 정책 레코드이므로 실행기도 같은 두 개를 읽습니다.

그 결과 에이전트는 담당자와 같은 기준으로 판단됩니다. 상한은 팀 정책으로 좁혀진 조직 정책입니다. 에이전트는 사람의 동의와 그 상한이 모두 허용하는 곳에서만 동작합니다. 정책을 편집하거나 시크릿 값을 읽거나 자기 그랜트를 넓힐 수 없습니다. 조직이 잠근 키는 팀 정책에서 무시되며, 에이전트도 담당자와 같은 방식으로 그 결과를 마주합니다.

각 키를 포인터에 묶으면 짚어 둘 부수 효과가 생깁니다. 정책 키 하나를 가진 쪽은 그 포인터의 레코드를 그 키 세대에서만 열 수 있습니다. 다른 스토어, config, 팀을 위해 제공되었거나 다른 버전으로 재전송된 블롭은 무결성 태그 검증에 실패합니다.

## 기존 환경에서 달라지는 점

- **정책 레코드는 버전 2입니다.** 스토어 키 자체로 봉인된 버전 1 레코드는 열리지 않습니다. 의도한 깔끔한 단절입니다.
- **호스팅된 쓰기도 같은 정책을 따릅니다.** 호스팅 실행기를 통한 config 쓰기는 저장되기 전에 정책 상한과 대조됩니다.
- **로컬 에이전트도 같은 상한을 유지합니다.** `REDIACC_ALLOW_CONFIG_EDIT`는 지정한 포인터에 한해 에이전트의 config 편집을 허용하지만 정책이 허락하는 범위 안에서만 가능합니다.
- **만료되거나 교체된 그랜트는 분명하게 실패합니다.** `initialize`와 `tools/list`는 계속 응답하고, 각 호출은 `reauthUrl`과 함께 `REDIACC_GRANT_EXPIRED`, `REDIACC_GRANT_REVOKED`, `REDIACC_KEY_ROTATED` 중 하나를 반환합니다.

각 그랜트는 분당 60회 호출과 동시 5건까지 허용합니다.

## 유출된 URL로 할 수 있는 일

유출된 URL은 만료되거나 폐기될 때까지 해당 사용자로서 하나의 config에서만 동작합니다. 조직의 다른 config도, 해당 리전의 호스팅 실행기 밖의 어떤 것도 열지 못합니다. 다만 도구 출력은 사용자가 연결한 모델 제공자에게 전달됩니다. 그 제공자를 Rediacc가 고르지는 않습니다.

설정 가이드는 [MCP Server Setup](/ko/docs/ai-agents-mcp)이고, 키 구성은 [보안 모델](/ko/docs/security-model)에 있습니다.
