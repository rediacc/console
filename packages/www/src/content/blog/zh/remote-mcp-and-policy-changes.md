> **摘要。** 远程 MCP 给 AI 智能体的是一个 URL，而不是一个终端。设计上的问题从来不是怎样连接智能体，而是连接之后它可以看到什么。答案是：恰好等于创建授权的那个人能看到的内容，不多一分。
>
> - 一个授权只触达**一个 config**，只属于**一个区域**。
> - 令牌最长有效期为访问令牌 **1 小时**、刷新令牌 **30 天**，且不会超过授权本身。
> - 授权携带一个 config 的内容密钥和两把**策略读取密钥**，不携带 config 存储的主密钥。
> - 策略记录的格式变了。旧记录会被拒绝，没有迁移路径。

## 是 URL，而不是登录 Shell

本地 MCP 服务器（`rdc mcp serve`）运行在智能体旁边，继承所在机器的访问权限。远程服务器则不同。每个区域运行一个 MCP Worker，地址为 `mcp.<region>.rediacc.cloud`，每个智能体连接某一个授权的 URL：`https://mcp.<region>.rediacc.cloud/g/<grantId>`。工具调用在组织的执行器（executor）上运行，而不是在开发者的笔记本上。

claude.ai 这类交互式客户端通过带 PKCE 的 OAuth 2.1 登录。无界面的智能体发送形如 `rmcp_<grantId>.<secret>` 的 bearer。两种形式都用来识别授权，URL 里的 id 只是给它命名。

## 边界就是授权本身

授权是一个小而具体的对象。它指明一个 config、一个过期时间和一个范围：只读标志、工具允许列表，以及机器和仓库的名称模式。

由这个形状推出三条规则：

- **一个 config。** 指向其他 config 的 `tools/call` 会在任何内容运行之前被 `REDIACC_GRANT_SCOPE` 拒绝。有三个 config 的用户需要授权三个 grant。
- **一个区域。** 授权 id 以区域开头。到达错误 Worker 的请求会得到 HTTP 421 和正确的 URL，绝不会被转发。
- **一个有效期。** 访问令牌的有效期取 1 小时与授权剩余时间中较短的一个。刷新令牌的有效期取 30 天与授权剩余时间中较短的一个。每次刷新都会重新查询授权，所以被撤销的授权在下一次交换时就会失效。同一个刷新令牌出示两次，授权即被撤销。

授权 URL 默认有效 7 天，最长 30 天。

## 按其负责人的标准来判定

有意思的地方在于密钥材料。授权是一个拆分的秘密。浏览器生成一个随机值，只显示一次。账户服务器只保存由它派生出的标签的哈希，执行器只有同时持有两半时才能派生出槽位密钥。这把槽位密钥打开的是 config 自己的内容密钥，而不是组织的主密钥。

同一把槽位密钥还会打开两把**策略密钥**。策略，也就是 config 条目的授权规则，现在存放在独立的记录里，用由存储密钥和记录指针（存储、config、团队、密钥代数）派生的密钥封装。授权携带自己团队 config 的密钥和组织级 config 的密钥。这正是其负责人读取的两条策略记录，所以执行器读取的也是这两条。

结果是，智能体按其负责人的标准被判定。上限是被团队策略收窄后的组织策略。只有当人的授权同意和这个上限都允许时，智能体才会行动。它不能编辑策略、读取密文值或扩大自己的授权。组织锁定的键在团队策略中会被忽略，智能体遇到这个结果的方式与负责人相同。

把每把密钥绑定到指针上，有一个值得说明的副作用。持有某一把策略密钥的一方，只能在该密钥代数下打开该指针的记录，别的都打不开。为其他存储、config 或团队提供的数据块，或在其他版本下重放的数据块，都无法通过完整性标签校验。

## 对现有部署的变化

- **策略记录升级为版本 2。** 直接用存储密钥封装的版本 1 记录无法打开。这是有意为之的彻底切换。
- **托管写入遵循同一策略。** 通过托管执行器写入 config 时，会在保存之前对照策略上限进行检查。
- **本地智能体保持同一上限。** `REDIACC_ALLOW_CONFIG_EDIT` 仍可让智能体编辑它所指定指针的 config，但只能在策略允许的范围内。
- **过期和已轮换的授权会明确失败。** `initialize` 和 `tools/list` 仍然响应，每次调用则返回 `REDIACC_GRANT_EXPIRED`、`REDIACC_GRANT_REVOKED` 或 `REDIACC_KEY_ROTATED`，并附带 `reauthUrl`。

每个授权允许每分钟 60 次调用，同时最多 5 个在途调用。

## 泄露的 URL 能做什么

泄露的 URL 以该用户的身份只作用于它那一个 config，直到过期或被撤销。它打不开组织的其他 config，也触及不到所在区域托管执行器之外的任何东西。不过，工具输出确实会到达用户所连接的模型提供方。这个提供方不是 Rediacc 选的。
