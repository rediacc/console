# 取证

当仓库内运行的软件被入侵后，取证要回答两个问题：数据是何时被带走的，以及哪些数据被带走。Rediacc 无法修补第三方软件中的漏洞，因此该功能记录的是在入侵之后依然可信的证据。记录由机器上以 root 身份运行的采集器写入，位于仓库沙箱之外，并发送到客户管理员无法访问的存储桶中。

这些记录呈现的是流量、目的地和时间。流记录证明的是流量和目的地，而不是内容。[事件工作流](/zh/docs/incident-response)读取这些记录，[事件报告](/zh/docs/incident-reports)则把它们变成可提交给监管机构的签名文档。

## 记录的内容

采集以仓库为单位。仓库使用主机网络，因此流量按 cgroup（仓库自己的 slice）归属，而不是按 IP 地址。

| 记录 | 内容 |
|---|---|
| 网络流 | 时间、进程、目标地址和端口、协议、发出和接收的字节数、已知时的 DNS 名称，以及已知时目的地的 ASN 和国家或地区 |
| 文件打开 | 匹配敏感列表的路径的时间、进程和路径 |
| 心跳 | 每个批次中的一个签名标记，这样采集器停止时表现为一段空白，而不是一片寂静 |

默认敏感列表涵盖 `.env` 文件、密钥和证书文件（`*.pem`、`*.key`、`id_rsa*`、`id_ed25519*`）、密码数据库（`*.kdbx`）、数据库转储和文件（`*.sql`、`*.dump`、`*.bak`、`*.sqlite*`），以及 `pgdata` 这类数据库数据目录。仓库可以扩展该列表，也可以用自己的规则替换它。

数据包载荷和文件内容从不记录。

## 采集级别

每个仓库只有一个级别，默认是最低级别。更高的级别会记录较低级别记录的全部内容。

| 级别 | 记录内容 |
|---|---|
| `basic` | 每 5 分钟按目的地、端口和协议生成一次摘要，包含进出字节数 |
| `standard` | 每分钟一条流记录，包含进程和 DNS 名称 |
| `full` | Standard，外加敏感路径上的文件打开 |

级别按仓库设置：

```bash
rdc forensics level mail basic
rdc forensics level mail standard
rdc forensics level mail full
```

采集器会把级别限制在套餐所包含的范围内。套餐没有取证配额时，仓库不记录任何内容。

### 突增触发器

每个级别都会启用一个触发器。仓库被观察满 24 小时后，如果某一分钟的出站字节数超过其自身移动平均值的十倍（并且超过每分钟 50 MiB），该仓库会切换到 Full 并持续 24 小时。触发的那一分钟不会计入平均值，因此一次数据外泄无法抬高本应捕捉下一次外泄的基线。

## 套餐和配额

取证面向付费套餐，并且只在套餐已付费期间记录。升级后从零历史开始。

| 套餐 | 取证配额 |
|---|---|
| Free、Community | 0（不记录任何内容） |
| Professional | 25 GB |
| Business | 125 GB |
| Enterprise | 512 GB，或由 Rediacc 管理员设定的自定义配额 |

配额为套餐备份配额的四分之一，与备份计量分开。要获得更多配额，只能升级套餐。

配额已满时，最旧的记录最先被清除（FIFO）。最近 7 天的记录被锁定，永远不会被清除，因为存储桶会将它们锁定 7 天。如果仅锁定的字节就会超出配额，新的批次会被拒绝。如果预计的 7 天写入量放不下，级别会被限制为 Basic。所有者和管理员会在配额用到 80% 时、上限降为 Basic 时以及批次被拒绝时收到通知。

落在已声明事件范围内的记录，在事件关闭后 30 天内不会被清除。参见[事件响应](/zh/docs/incident-response)。

## 发送与完整性

采集器每 30 秒切出一个批次。每个批次用机器的 spool 密钥签名，并带有上一个批次的哈希，因此被删除或被修改的批次会使链断裂。批次通过仅允许创建的预签名 URL 上传，这些 URL 由机器的许可证 blob 生成，所以机器可以添加记录，却无法覆盖或删除。连接中断时，批次留在本地已签名的 spool 中，连接恢复后再发送。

夜间压缩会把批次合并为每个仓库一个日文件、每台机器一个头文件，头文件中列出每个已签名的头，并标出每一处空白。账户的审计日文件也以同样方式按组织和日期链接。

`rdc forensics verify` 和调查页面上的 Verify evidence 按钮会重新计算这些链。参见[事件响应](/zh/docs/incident-response)。

## 检测

异常检测会运行两次。机器上的统计检测器立即响应，把仓库切换到 Full。服务器在接收数据时运行自己的检测器，因此即使主机被入侵，检测依然有效。不会对每条日志记录运行 AI。

检测器分层，每个仓库都从自己的流量中学习：

| 检测器 | 查找内容 |
|---|---|
| 按一周中小时划分的基线 | 在该仓库该小时的常规节奏之外的字节数、连接数、不同目的地、新的 DNS 名称和新进程 |
| Half-Space Trees | 与以往所见流量都不相像的流 |
| ECOD 和 HBOS | 评分为离群值的流批次，以及推动评分的特征 |
| 首次出现 | 进程打开了它以前从未打开过的敏感文件 |

每条发现都带有产生它的各项特征原因，解释是用这些原因生成的模板。离线时没有语言模型。一条发现会变成账户通知，并发送电子邮件给所有者、管理员和安全联系人。机器离线时，它会立即在本地行动（Full 采集，并在已签名的 spool 中写入一条记录），连接恢复后再投递告警，并保留原始检测时间。

### 模型包

检测器参数以签名包的形式分发在 `data.rediacc.com/models/` 下，由发布任务上传（目前那里还没有发布任何通道）：内容寻址的文件、用内置于 renet 的离线 Ed25519 模型密钥签名的清单、最低 renet 版本，以及只增不减的版本号，因此降级会被拒绝。包在安装前会经过验证，并且可以恢复到上一个包。

```bash
renet models status
renet models update
renet models rollback
```

气隙环境的安装会在 `rdc server bundle` 中收到同一个签名包，除非传入 `--no-models`。

## 服务器能读取什么

账户服务器会读取这些记录，因为时间线、验证和服务器端检测器都需要它们：目的地、端口、进程名称、DNS 名称、字节计数和敏感文件路径。它不会接收数据包载荷或文件内容。

入站客户端地址在记录中被截断存储（IPv4 截到 /24，IPv6 截到 /48），完整地址存放在单独的部分中，30 天后删除。被删除部分的哈希保留在已签名的头中，因此链仍可验证，验证器会把该地址报告为已脱敏。出站目的地保持完整，因为它们就是证据。

客户通过调查来打开记录，这需要付费套餐、所有者或管理员角色以及最近一次重新认证，并且每次查看都会被审计。Rediacc 支持人员只有在客户签发的限时授权下才能看到取证数据。处理条款见[数据处理协议](/zh/data-processing-agreement)。
