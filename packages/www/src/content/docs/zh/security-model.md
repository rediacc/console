# 安全模型

本页说明配置存储保护什么、哪个密钥能打开什么，以及每类调用方能触及什么。设置步骤请参阅[配置存储](/zh/docs/config-storage)，会话和令牌请参阅[账户安全与API](/zh/docs/account-security)。

## 谁能看到什么

存储的配置分三层加密。SDK 层和组织口令层的密钥由服务器管理。中间一层是内容加密密钥（CEK），只有密钥槽持有者才能解开：保存在设备上的槽密钥与服务器持有的密钥组合后才能打开，任何一半单独都打不开。

| 攻击者掌握 | 能否看到配置内容 | 原因 |
|---|---|---|
| 仅有数据库副本 | 不能 | 配置数据块存放在对象存储中，而不是数据库里 |
| 数据库和对象存储 | 不能 | 组织口令层需要 Worker 密钥，CEK 层需要槽密钥 |
| 服务器被完全攻破 | 没有槽密钥就不能 | 服务器这几层会被攻破，但 CEK 仍受通行密钥 PRF 输出或 160 位恢复套件保护，二者都无法猜出 |
| 已移除成员的设备 | 只能看到已拉取的内容 | CEK 轮换之后的版本仍然无法打开 |
| 泄露的代理 URL | 以该用户身份访问一个配置 | 参见[代理与远程 MCP](#代理与远程-mcp) |

服务器仍能看到元数据（配置 id、团队、版本、时间戳、数据块大小），也可以拒绝、延迟或删除请求。提供恶意门户代码的运营方可以在浏览器中读取密钥。每个数据块都绑定到其存储、配置、团队和版本，因此服务器无法在不被发现的情况下调换或修改数据块，CLI 也会拒绝比已见过的版本更旧的版本。

## 密钥范围

- 每个组织一个配置存储，每个存储一个 CEK。团队是服务器端的访问控制，而不是密码学隔离：一个恢复套件或密钥槽即可打开整个组织的 CEK。
- 密钥槽按存储、用户和方式唯一，因此每个用户在每个组织中只有一个恢复套件。同时属于两个组织的用户持有两个套件，不存在团队套件。
- 机器密钥按机器和组织各一个，用于注册无浏览器的机器。
- 每个配置在 CEK 之下都有自己的内容密钥。代理授权只携带一个配置的内容密钥，因此无法用它打开组织的其他配置。
- 每个配置的授权策略是一条独立记录，位于由 CEK 和记录指针派生的密钥之下。持有某个策略密钥的人只能打开该指针下的记录。

## 代理与远程 MCP

代理授权是远程 MCP URL 背后的密钥持有者类型。它携带一个配置的内容密钥，以及该授权所属团队配置和组织级配置的策略密钥，但从不携带 CEK，因此代理读到的内容与其对应的用户完全一致。

- **有效期。** URL 默认有效 7 天，最长 30 天，之后过期或被撤销。已过期的授权会被拒绝，客户端需要重新授权。
- **范围。** 一个授权只能触及一个配置，并且属于一个区域（eu、us 或 asia）。向其他区域出示的 URL 会被拒绝并指出正确的区域，绝不会转发。本地部署（on-premise）为单一区域。
- **策略。** 代理只能在人工明确同意和策略上限都允许的范围内行动。上限是经团队策略收窄后的组织策略。代理不能编辑策略、读取密钥值，也不能扩大自己的授权。
- **影响范围。** 泄露的 URL 在过期或被撤销之前，以该用户身份操作其唯一的那个配置。它无法打开其所在区域托管执行器之外的任何内容。

工具输出会到达用户所连接的模型提供商，该提供商并非由 Rediacc 选择。

### 本地部署

链路中没有 Cloudflare。云端的 Worker 密钥变为客户主机上的环境变量或配置，因此主机访问权限取代了上表中 Worker 密钥这道边界，工具调用在客户自己的守护进程执行器上运行。

## 策略

策略是一条独立记录，按配置条目封存，并带有认证数据，绑定存储、配置、团队、版本和密钥代数。服务器无法读取它，重放或调换的记录无法通过其完整性标签校验。版本 1 的策略记录会被拒绝。

只有组织所有者或管理员能写入组织策略，只有团队管理员（或所有者、管理员）能写入该团队的策略。写入需要 2FA 和提升的会话；如果存储要求使用通行密钥，还需要已绑定的通行密钥。每位成员以及为其服务的每个执行器都会读取该策略。组织锁定的键在团队策略中会被忽略。

## 哪些内容可以恢复

| 情形 | 恢复方式 |
|---|---|
| 通行密钥丢失 | 用恢复套件解锁，然后注册新的通行密钥 |
| 套件丢失 | 用可用的通行密钥重新生成；旧的打印件随即失效 |
| 两者都丢失 | 所有者或管理员通过成员交接重新添加该成员 |
| 最后一位密钥持有者丢失两者 | 无法恢复，因此建议设置第二位密钥持有者 |
| 成员被移除 | 其密钥槽和令牌立即失效；CEK 轮换会让其保留的密钥无法打开之后的版本 |
| CEK 轮换 | 在新一代之下重新封装 CEK，并使所有恢复套件失效 |

如果删除密钥槽、移除成员或成员退出会使密钥持有者少于两位且没有恢复槽，服务器会拒绝该操作。每位成员在注册时都会收到一个必备的恢复套件，妥善保管它是成员自己的责任。
