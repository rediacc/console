Rediacc 欢迎各方报告其产品和服务中的安全漏洞。本政策说明哪些内容在适用范围内、如何报告，以及报告者可以获得哪些回应。机器可读的联系文件位于 `/.well-known/security.txt`（RFC 9116）。

## 适用范围

在范围内：

- `rdc` CLI 和 `renet` 机器编排器
- 账户服务器、其网页门户和 API
- `rediacc.com` 和 `rediacc.cloud` 下的 Rediacc 网站
- 发布产物：二进制文件、容器镜像和安装程序

不在范围内：

- 需要对机器进行物理访问的发现，或报告者本身已控制的被入侵终端
- 通过流量洪泛实施的拒绝服务、垃圾信息，或针对员工的社会工程
- 自动扫描器生成、且未证明实际影响的报告
- Rediacc 仅原样转发的第三方软件中的漏洞；这类漏洞应报告给上游项目，同时欢迎向这里抄送一份

## 如何报告

请将报告发送至 [security@rediacc.com](mailto:security@rediacc.com)，并包含：

- 受影响的产品和版本，或 URL
- 复现步骤或 proof of concept
- 报告者预期的影响
- 该问题是否已公开或正在被利用
- 用于后续联系的地址，以及是否希望获得署名

建议使用英文提交报告。报告中不要包含真实的客户数据：提供最低限度的访问证明即可。

## 安全港

对于依据本政策善意行事的报告者，Rediacc 不会追究或支持针对其采取的法律行动。善意行事是指报告者：

- 仅针对自己的账户、机器和数据，或 Rediacc 所拥有的资产进行测试
- 在证明问题存在之后即停止，不读取、修改、复制或删除属于他人的数据
- 不降低其他用户的服务质量
- 及时报告，并在下文所述的协调披露日期之前对细节保密

在这些限制范围内开展的工作视为已获授权，如有第三方询问，Rediacc 会如此说明。

## 响应时间

| 步骤 | 目标 |
|------|------|
| 确认收到报告 | 2 个工作日 |
| 初步评估并确定严重程度 | 5 个工作日 |
| 问题未关闭期间的状态更新 | 至少每 14 天一次 |
| 严重问题的修复或缓解 | 自评估起 14 天 |
| 其他已确认问题的修复或缓解 | 自评估起 90 天 |

这些目标是努力方向；若某份报告需要更多时间，我们会说明原因并给出新的日期。

## 协调披露

细节会与修复一同发布，通常在首次评估后 90 天内。希望提前或推迟发布的报告者可在报告中写明日期，双方协商确定一个日期。已在实际环境中被利用的漏洞按事件处理，详见[事件响应页面](/zh/docs/security-incident-response)。

## 致谢

经确认的报告会在发布说明或安全公告中，以报告者选择的姓名或昵称予以致谢。Rediacc 不设有偿漏洞赏金计划。
