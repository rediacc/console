# Реагирование на инциденты

Здесь под инцидентом понимается тот, что происходит внутри собственных репозиториев клиента. Страница расследования, команды `rdc incident` и средства чтения `rdc repo flows` и `rdc repo opens` работают с записями, описанными в разделе [криминалистика](/ru/docs/forensics). Инциденты в собственных системах Rediacc описаны в [реагировании на инциденты безопасности](/ru/docs/security-incident-response).

## Доступ

Для расследования нужны платный тариф и роль владельца или администратора. При открытии запрашивается недавняя повторная аутентификация, а открытое расследование остаётся действительным 60 минут. Каждый просмотр записывается в журнал аудита.

Поддержка Rediacc видит данные криминалистики только по разрешению поддержки, которое выдаёт клиент. Разрешение действует не более 7 дней и может быть отозвано в любой момент.

Для чтения через CLI нужен scope `forensics:read`, а для объявления и закрытия нужен `incident:manage`. Вход через CLI даёт оба владельцам и администраторам после повышенного подтверждения в браузере. Если команда отвечает, что нужно недавнее повышенное подтверждение, портал аккаунта запрашивает его, и команду можно запустить снова.

## Временная шкала

Страница Investigate объединяет одну область (репозиторий или машину) в единую временную шкалу с пятью видами строк: события аудита консоли, запуски, сетевые потоки, открытия файлов и аномалии. Изменения с момента последнего снимка можно сравнить с ним. Окно задаётся ползунком времени и охватывает не более 31 дня.

Участок без улик показывается строкой-пробелом с названием машины и причиной, а не пустым местом. Над строками находятся график исходящих байтов в минуту и список основных назначений.

Те же данные доступны из командной строки:

```bash
rdc repo flows mail --since 24h
rdc repo flows mail --since 2026-11-20T00:00:00Z --until 2026-11-21T00:00:00Z
rdc repo opens mail --since 7d
```

`--since` и `--until` принимают момент времени в формате ISO 8601 или интервал назад от текущего момента, например `90m`, `24h` или `7d`. По умолчанию берутся последние 24 часа. Строки потоков показывают время, процесс, назначение, байты на выход и на вход, а также ASN и страну, если известны. Строки открытий показывают время, процесс и путь, причём чувствительные пути помечены.

## Проверка улик

Verify evidence пересчитывает в браузере цепочку хешей дневных файлов аудита и цепочки подписанных пакетов записей криминалистики для выбранного окна и перечисляет каждый пробел и каждое изменение. Подписи пакетов проверяются ключами spool, которые сервер аккаунтов закрепил за каждой машиной. Ключу, записанному внутри самих улик, доверие не оказывается никогда. Результат проставляется в экспортируемые отчёты.

Улики объёмом свыше 2 ГиБ слишком велики для браузера. Тот же модуль запускается из командной строки:

```bash
rdc forensics verify --dir ./incident-evidence
rdc forensics verify --dir ./incident-evidence --since 7d --machine-key web-1=<public-key-hex>
```

Команда завершается с кодом 1, если найден любой пробел или изменение. `--machine-key <machine>=<64 hex characters>` передаёт ключ из-за пределов каталога и может повторяться. Машина без внешнего ключа не проходит проверку.

## Объявление инцидента

Объявление замораживает улики. Сначала создаётся запись в аккаунте, затем репозиторий готовится к расследованию:

1. Инцидент записывается с его окном, с указанием того, кто его объявил и когда организация узнала о нём.
2. Удерживающая блокировка вытеснения покрывает окно, а правила блокировки бакета распространяются на него, так что FIFO не может удалить эти дни.
3. Репозиторий форкается как криминалистический снимок с тегом `incident-<id>`.
4. Уровень захвата репозитория переключается на Full.

С момента осведомлённости стартуют три таймера. Этот момент можно задать раньше объявления, но не позже: раннее предупреждение подаётся через 24 часа после осведомлённости, уведомление через 72 часа, а итоговый отчёт через один календарный месяц после уведомления (отсчёт ведётся от срока уведомления, пока уведомление не зафиксировано). Страница показывает каждый таймер как ожидающий, истекающий в течение 6 часов, просроченный или выполненный.

```bash
rdc incident declare mail
rdc incident declare mail --since 48h --aware-at 2026-11-20T09:30:00Z
rdc incident status
rdc incident status <id>
```

Если шаг на машине завершился ошибкой, запись и её блокировка остаются на месте, команда завершается с кодом 1 и называет команду, которая повторяет только неудавшиеся шаги:

```bash
rdc incident declare mail --resume <id>
```

`--resume` сохраняет окно и момент осведомлённости исходного объявления, поэтому `--since`, `--until` и `--aware-at` с ним не сочетаются.

## Экспорт улик

`rdc incident export` записывает окно инцидента в каталог: запись об инциденте с её таймерами, объединённую временную шкалу, агрегаты исходящих байтов, исходный манифест цепочки и исходные файлы, которые он перечисляет. Если манифест перечисляет дневные файлы аудита или файлы заголовков криминалистики, цепочки проверяются по ходу дела, а результат попадает в `verification.json`. Команда завершается с кодом 1, если улики показывают пробел или изменение.

```bash
rdc incident export <id>
rdc incident export <id> --out ./incident-evidence
```

С `--stage` та же команда вместо этого записывает подписанный отчёт. См. [отчёты об инцидентах](/ru/docs/incident-reports).

## Закрытие инцидента

```bash
rdc incident close <id>
```

Ничего не освобождается сразу. Блокировка вытеснения и правила блокировки бакета снимаются через 30 дней после закрытия.

## Спросить ИИ

На странице расследования есть ассистент, который отвечает на вопросы об открытой области и окне. Он читает только эту область и это окно, по одноразовому тикету, выпущенному из открытого расследования и доступному для использования 15 минут. Вопрос и прочитанные строки уходят к собственному ИИ-провайдеру организации. Ассистент может выполнять приведённые выше команды `rdc` по тем же правилам разрешений, что и любая другая команда.

## Команды

| Команда | Назначение |
|---|---|
| `rdc repo flows <ref>` | Сетевые потоки репозитория за окно |
| `rdc repo opens <ref>` | Открытия чувствительных файлов репозитория за окно |
| `rdc forensics level <ref> <level>` | Задать уровень захвата |
| `rdc forensics verify` | Проверить каталог улик или подписанный отчёт |
| `rdc incident declare <ref>` | Зафиксировать инцидент, сделать форк репозитория и переключить на Full |
| `rdc incident status [id]` | Показать список инцидентов или один инцидент с его таймерами |
| `rdc incident export <id>` | Записать окно улик или, с `--stage`, подписанный отчёт |
| `rdc incident close <id>` | Закрыть инцидент |
