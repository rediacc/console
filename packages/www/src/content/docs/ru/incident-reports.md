# Отчёты об инцидентах

Объявленный инцидент ([реагирование на инциденты](/ru/docs/incident-response)) порождает три поэтапных отчёта, которые клиент подаёт регулятору. Rediacc формирует документы на основе улик. Является ли инцидент существенным или подлежащим уведомлению, остаётся решением клиента, и каждый отчёт это прямо указывает.

## Этапы

Каждый этап перечисляет нужные ему разделы и никаких других, поэтому раздел, который этапу не требуется, пропускается, а не остаётся пустым.

| Этап | Срок | Добавляет |
|---|---|---|
| Раннее предупреждение | 24 часа после осведомлённости | Заголовок, временная шкала, индикаторы компрометации, предполагаемое злонамеренное и трансграничное воздействие |
| Уведомление | 72 часа после осведомлённости | Первичная оценка, воздействие на данные (категории, примерные количества, государства-члены) и техники ATT&CK |
| Итоговый | Один календарный месяц после уведомления | Первопричина и меры по смягчению |

Итоговый отчёт следует за уведомлением, поэтому сначала формируется уведомление. Каждый этап включает разделы предыдущего.

Каждый факт в отчёте указывает, откуда он известен: наблюдается в уликах, введён клиентом или выведен. У выведенного факта есть степень уверенности и причина, названная детектором. Оценка, категории данных, государства-члены, предполагаемая причина, принятые меры, контактное лицо и техники вводятся клиентом на странице инцидента перед формированием.

## Форматы

| Формат | Назначение |
|---|---|
| JSON | Каноническая, проверяемая форма |
| STIX 2.1 | Набор индикаторов для инструментов threat intelligence |
| PDF | Читаемый документ, отображающий нелатинские письменности, с отказом от ответственности, QR-кодом и хешем отчёта в нижнем колонтитуле каждой страницы |

На странице инцидента для каждого этапа есть кнопка загрузки по каждому формату. Из командной строки:

```bash
rdc incident export <id> --stage early-warning
rdc incident export <id> --stage notification --format stix
rdc incident export <id> --stage final --format pdf --out ./reports
```

Формат по умолчанию JSON. `--format` действует только вместе с `--stage`. Файл записывается под идентификатором отчёта.

## Подпись и проверка

Каждый отчёт подписывается ключом отчётов Ed25519, а идентификатор отчёта, этап и хеш заносятся в публичный реестр. Подпись охватывает каноническое содержимое отчёта, поэтому любое изменение после подписания обнаруживается.

Отчёт проверяется в трёх местах:

- Страница проверки по адресу `/account/verify/report/<id>`, которую открывает QR-код в PDF. Проверка выполняется в браузере по опубликованному ключу отчётов, ничего не загружается. JSON-файл проверяется полностью. PDF в браузере повторно захешировать нельзя, поэтому страница подтверждает, что PDF несёт хеш отчёта, и для полной проверки отсылает к JSON-файлу.
- Командная строка, для JSON-отчёта:

```bash
rdc forensics verify --report ./reports/<report-id>.json
```

Команда завершается с кодом 1, если содержимое или подпись не совпадают. PDF проверяется через JSON-отчёт, из которого он создан.

- Штамп улик внутри отчёта, который фиксирует результат Verify evidence для окна: кто проверял, какой версией и когда.

## Соответствие полей

Каждое поле отчёта сопоставлено с режимами, по которым клиент отчитывается, чтобы содержимое можно было перенести без повторного ввода. Сопоставление охватывает три режима: NIS2 ст. 23(4), формат уведомления об инцидентах из Регламента исполнения (ЕС) 2025/302 и GDPR ст. 33(3). Примеры:

| Поле отчёта | NIS2 | GDPR |
|---|---|---|
| Момент осведомлённости | Art. 23(4)(a) | Art. 33(1) |
| Хронология | Art. 23(4)(d) | Art. 33(3)(a) |
| Контактное лицо | Art. 23(4) | Art. 33(3)(b) |

Поле, не имеющее аналога в режиме, объясняет почему, а не опускается. Например, в уведомлении по ст. 33(3) GDPR нет ни регистрационного номера, ни времени закрытия.

## Чего отчёт не утверждает

На каждом этапе печатаются два заявления:

- Записи потоков доказывают объём и назначение, но не содержимое.
- Является ли инцидент существенным или подлежащим уведомлению, решает клиент.

Rediacc ничего не подаёт регулятору от имени клиента.
