# フォレンジック

フォレンジックは、リポジトリ内で動くソフトウェアが侵害されたあとに、2つの問いに答えます。いつデータが持ち出されたのか、そしてどのデータが持ち出されたのか。Rediacc はサードパーティ製ソフトウェアの穴をふさぐことはできないため、侵害を生き延びる証拠を記録します。記録を書き込むのは、マシン上でリポジトリのサンドボックスの外側にある root 権限のコレクターで、記録はお客様の管理者が触れられないバケットに送られます。

記録から分かるのは、量、宛先、タイミングです。フロー記録が証明するのは量と宛先であり、内容ではありません。[インシデントワークフロー](/ja/docs/incident-response)がこれらを読み取り、[インシデントレポート](/ja/docs/incident-reports)が規制当局向けの署名付き文書にまとめます。

## 記録される内容

キャプチャはリポジトリ単位です。リポジトリはホストネットワークを使うため、トラフィックは IP アドレスではなく cgroup(リポジトリ自身のスライス)で帰属を判定します。

| 記録 | 内容 |
|---|---|
| ネットワークフロー | 時刻、プロセス、宛先アドレスとポート、プロトコル、送信・受信バイト数、判明している場合は DNS 名、判明している場合は宛先の ASN と国 |
| ファイルオープン | 機密リストに一致するパスについて、時刻、プロセス、パス |
| ハートビート | すべてのバッチに含まれる署名付きマーカー。コレクターが止まると、無音ではなく欠落として現れます |

既定の機密リストは、`.env` ファイル、鍵と証明書のファイル(`*.pem`、`*.key`、`id_rsa*`、`id_ed25519*`)、パスワードデータベース(`*.kdbx`)、データベースのダンプとファイル(`*.sql`、`*.dump`、`*.bak`、`*.sqlite*`)、`pgdata` のようなデータベースのデータディレクトリを対象とします。リポジトリごとにリストを拡張することも、独自のパターンに置き換えることもできます。

パケットのペイロードとファイルの内容は記録されません。

## キャプチャレベル

各リポジトリのレベルは1つで、既定は最小のレベルです。上位のレベルは、下位のレベルが記録するものをすべて記録します。

| レベル | 記録内容 |
|---|---|
| `basic` | 宛先、ポート、プロトコルごとの5分間サマリー(送受信バイト数付き) |
| `standard` | 1分ごとのフロー記録(プロセスと DNS 名付き) |
| `full` | Standard に加えて、機密パスのファイルオープン |

レベルはリポジトリごとに設定します。

```bash
rdc forensics level mail basic
rdc forensics level mail standard
rdc forensics level mail full
```

コレクターは、レベルをプランに含まれる範囲に制限します。プランにフォレンジックのクォータがない場合、リポジトリは何も記録しません。

### スパイクトリガー

どのレベルでもトリガーが有効になります。リポジトリが24時間観測されたあと、1分間の送信バイト数がそのリポジトリ自身の移動平均の10倍(かつ1分あたり50 MiB)を超えると、リポジトリは24時間 Full に切り替わります。発火した分は平均に反映されないため、1回の持ち出しによって、次の持ち出しを捕らえるはずの基準値が押し上げられることはありません。

## プランとクォータ

フォレンジックは有料プラン向けで、プランが有料の間だけ記録します。アップグレード直後は履歴がありません。

| プラン | フォレンジックのクォータ |
|---|---|
| Free、Community | 0(何も記録されません) |
| Professional | 25 GB |
| Business | 125 GB |
| Enterprise | 512 GB、または Rediacc 管理者が設定するカスタムクォータ |

クォータはプランのバックアップクォータの4分の1で、バックアップの集計とは別です。クォータを増やすにはプランのアップグレードが必要です。

クォータがいっぱいになると、古い記録から順に削除されます(FIFO)。直近7日分はロックされており、バケットが7日間ロックするため削除されません。ロックされたバイト数だけでクォータを超える場合、新しいバッチは拒否されます。7日分の想定取り込み量が収まらない場合、レベルは Basic に制限されます。オーナーと管理者には、クォータの80パーセント到達時、上限が Basic に下がったとき、バッチが拒否されたときに通知が届きます。

宣言済みインシデントの範囲に入る記録は、インシデント終了の30日後まで削除から保護されます。[インシデント対応](/ja/docs/incident-response)をご覧ください。

## 送信と完全性

コレクターは30秒ごとにバッチを切り出します。各バッチはマシンのスプールキーで署名され、直前のバッチのハッシュを含むため、削除または編集されたバッチがあれば連鎖が切れます。バッチは、マシンのライセンスブロブから発行される作成専用の署名付き URL でアップロードされるので、マシンは記録を追加できますが、上書きや削除はできません。接続が途切れた間は、バッチはローカルの署名付きスプールで待機し、接続が戻ると送信されます。

夜間のコンパクションで、バッチはリポジトリごとの日次ファイルと、マシンごとのヘッダーファイルにまとめられます。ヘッダーファイルにはすべての署名付きヘッダーが列挙され、欠落があれば印が付きます。アカウントの監査日次ファイルも、組織と日ごとに同じ方法で連鎖します。

`rdc forensics verify` と調査ページの Verify evidence ボタンは、これらの連鎖を再計算します。[インシデント対応](/ja/docs/incident-response)をご覧ください。

## 検知

異常検知は2回行われます。マシン上の統計的検知器が即座に反応し、リポジトリを Full に切り替えます。サーバーも取り込み時に独自の検知器を動かすため、ホストが侵害されても検知は残ります。ログレコードごとに AI が動くことはありません。

検知器は層になっており、各リポジトリは自身のトラフィックから学習します。

| 検知器 | 検出対象 |
|---|---|
| 週の時間帯別ベースライン | その時間帯のリポジトリの通常のリズムから外れたバイト数、接続数、異なる宛先の数、新しい DNS 名、新しいプロセス |
| Half-Space Trees | それまでに見たフローと似ていないフロー |
| ECOD と HBOS | 外れ値としてスコアされるフローのバッチと、スコアを押し上げた特徴量 |
| 初出 | これまで開いたことのない機密ファイルを開いたプロセス |

各検知結果には、それを生んだ特徴量ごとの理由が付き、説明はその理由から組み立てられたテンプレートです。オフライン時に言語モデルは使いません。検知結果はアカウント通知となり、オーナー、管理者、セキュリティ担当者にメールで届きます。マシンがオフラインの場合は、ローカルで即座に対応し(Full キャプチャと署名付きスプールへの記録)、接続が戻ったらアラートを送信します。そのとき、元の検知時刻は保持されます。

### モデルバンドル

検知器のパラメーターは、署名付きバンドルとして `data.rediacc.com/models/` で公開されます。コンテンツアドレス指定のファイル、renet に組み込まれたオフラインの Ed25519 モデルキーで署名されたマニフェスト、最小 renet バージョン、増える一方のバージョン番号で構成され、ダウングレードは拒否されます。バンドルはインストール前に検証され、直前のバンドルに戻すこともできます。

```bash
renet models status
renet models update
renet models rollback
```

エアギャップ環境のインストールには、`--no-models` を渡さない限り、`rdc server bundle` の中に同じ署名付きバンドルが含まれます。

## サーバーが読み取れる内容

アカウントサーバーは記録を読み取ります。タイムライン、検証、サーバー側の検知器がそれを必要とするためです。読み取るのは、宛先、ポート、プロセス名、DNS 名、バイト数、機密ファイルのパスです。パケットのペイロードやファイルの内容は受け取りません。

受信側のクライアントアドレスは、記録内では切り詰めて保存され(IPv4 は /24、IPv6 は /48)、完全なアドレスは別セクションに置かれて30日後に削除されます。削除されたセクションのハッシュは署名付きヘッダーに残るので、連鎖は引き続き検証でき、検証ツールはそのアドレスを伏せ字として報告します。送信先は、それが証拠そのものなので、完全なまま残ります。

お客様は調査を通じて記録を開きます。調査には、有料プラン、オーナーまたは管理者のロール、直近の再認証が必要で、すべての閲覧は監査されます。Rediacc サポートがフォレンジックデータを見られるのは、お客様が発行する期限付きの許可がある場合に限られます。処理条件は[データ処理契約](/ja/data-processing-agreement)に記載しています。
