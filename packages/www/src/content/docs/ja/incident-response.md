# インシデント対応

ここでいうインシデントとは、お客様自身のリポジトリ内で起きるものです。調査ページ、`rdc incident` コマンド、`rdc repo flows` と `rdc repo opens` のリーダーは、いずれも[フォレンジック](/ja/docs/forensics)で説明した記録をもとに動作します。Rediacc 自身のシステムで起きたインシデントは、[セキュリティインシデント対応](/ja/docs/security-incident-response)に従います。

## アクセス

調査には、有料プランとオーナーまたは管理者のロールが必要です。調査を開くときは直近の再認証が求められ、開いた調査は60分間有効です。すべての閲覧は監査ログに記録されます。

Rediacc サポートがフォレンジックデータを見られるのは、お客様が発行するサポート許可がある場合に限られます。許可の有効期間は最長7日で、いつでも取り消せます。

CLI の読み取りには `forensics:read` スコープが必要で、宣言と終了には `incident:manage` が必要です。オーナーと管理者の CLI ログインは、ブラウザーでの昇格承認のあと、両方を持ちます。直近の昇格承認が必要だとコマンドが応答した場合は、アカウントポータルが承認を求め、そのあとコマンドを再実行できます。

## タイムライン

Investigate ページは、1つの範囲(リポジトリまたはマシン)を、5種類の行からなる1本のタイムラインにまとめます。コンソールの監査イベント、実行、ネットワークフロー、ファイルオープン、異常です。前回のスナップショット以降の変更を、そのスナップショットと比較できます。時間ウィンドウのスクラバーで期間を設定し、1つのウィンドウは最大31日です。

証拠のない区間は、マシン名と理由を示す欠落行として表示され、空白のままにはなりません。行の上には、1分あたりの送信バイト数のグラフと、上位の宛先の一覧があります。

同じ読み取りはコマンドラインからも使えます。

```bash
rdc repo flows mail --since 24h
rdc repo flows mail --since 2026-11-20T00:00:00Z --until 2026-11-21T00:00:00Z
rdc repo opens mail --since 7d
```

`--since` と `--until` には、ISO 8601 の時刻か、`90m`、`24h`、`7d` のような現在から遡る期間を指定できます。既定のウィンドウは直近24時間です。フロー行には、時刻、プロセス、宛先、送受信バイト数、判明している場合は ASN と国が表示されます。オープン行には、時刻、プロセス、パスが表示され、機密パスには印が付きます。

## 証拠の検証

Verify evidence は、そのウィンドウについて、監査日次ファイルのハッシュチェーンと、フォレンジック記録の署名付きバッチチェーンをブラウザー内で再計算し、すべての欠落と編集を一覧にします。バッチの署名は、アカウントサーバーがマシンごとに固定したスプールキーで検証されます。証拠の中に書かれた鍵は信頼されません。結果は、エクスポートされるレポートに刻印されます。

2 GiB を超える証拠はブラウザーには大きすぎます。同じモジュールをコマンドラインから実行できます。

```bash
rdc forensics verify --dir ./incident-evidence
rdc forensics verify --dir ./incident-evidence --since 7d --machine-key web-1=<public-key-hex>
```

欠落または編集が見つかると、コマンドは終了コード 1 で終わります。`--machine-key <machine>=<public-key-hex>`（鍵は16進数64文字） はディレクトリの外から鍵を渡すもので、繰り返し指定できます。外部の鍵がないマシンは失敗します。

## インシデントの宣言

宣言すると証拠が凍結されます。まずアカウント側の記録が作られ、そのあとリポジトリが調査用に準備されます。

1. インシデントが、ウィンドウ、宣言者、組織が認識した時刻とともに記録されます。
2. 削除保留がウィンドウをカバーし、バケットのロックルールもそこまで延長されるため、FIFO でもその期間は削除できません。
3. リポジトリがフォレンジックスナップショットとしてフォークされ、`incident-<id>` タグが付きます。
4. リポジトリのキャプチャレベルが Full に切り替わります。

認識の時点から3つの期限が始まります。認識時刻は宣言より前に設定できますが、後にはできません。早期警戒は認識の24時間後、通知は72時間後、最終報告は通知の暦月で1か月後が期限です(通知が記録されるまでは、通知の期限から数えます)。ページには各期限が、保留中、6時間以内に期限、期限超過、完了のいずれかで表示されます。

```bash
rdc incident declare mail
rdc incident declare mail --since 48h --aware-at 2026-11-20T09:30:00Z
rdc incident status
rdc incident status <id>
```

マシン側のステップが失敗した場合も、記録と保留は残り、コマンドは終了コード 1 で終わって、失敗したステップだけを再実行するコマンドを表示します。

```bash
rdc incident declare mail --resume <id>
```

`--resume` は元の宣言のウィンドウと認識時刻を引き継ぐため、`--since`、`--until`、`--aware-at` は併用できません。

## 証拠のエクスポート

`rdc incident export` は、インシデントのウィンドウをディレクトリに書き出します。期限付きのインシデント記録、統合されたタイムライン、送信バイト数の集計、チェーンの生マニフェスト、マニフェストに列挙された生ファイルです。マニフェストに監査日次ファイルやフォレンジックのヘッダーファイルが含まれる場合は、その過程でチェーンが検証され、結果は `verification.json` に出力されます。証拠に欠落や編集があると、コマンドは終了コード 1 で終わります。

```bash
rdc incident export <id>
rdc incident export <id> --out ./incident-evidence
```

`--stage` を付けると、同じコマンドが代わりに署名付きレポートを書き出します。[インシデントレポート](/ja/docs/incident-reports)をご覧ください。

## インシデントの終了

```bash
rdc incident close <id>
```

すぐに解放されるものはありません。削除保留とバケットのロックルールは、終了の30日後に終わります。

## AI に質問する

調査ページには、開いている範囲とウィンドウについての質問に答えるアシスタントがあります。アシスタントはその範囲とウィンドウだけを読み、開いている調査から発行される使い捨てチケットを使います。チケットは15分間のみ利用できます。質問と読み取った行は、組織自身の AI プロバイダーに送られます。アシスタントは、ほかのコマンドと同じ権限ルールのもとで、上記の `rdc` コマンドを実行できます。

## コマンド

| コマンド | 用途 |
|---|---|
| `rdc repo flows <ref>` | ウィンドウ内のリポジトリのネットワークフロー |
| `rdc repo opens <ref>` | ウィンドウ内のリポジトリの機密ファイルオープン |
| `rdc forensics level <ref> <level>` | キャプチャレベルの設定 |
| `rdc forensics verify` | 証拠ディレクトリまたは署名付きレポートの検証 |
| `rdc incident declare <ref>` | インシデントを記録し、リポジトリをフォークして Full に切り替え |
| `rdc incident status [id]` | インシデントの一覧、または期限付きで1件を表示 |
| `rdc incident export <id>` | 証拠ウィンドウを書き出し、`--stage` では署名付きレポートを出力 |
| `rdc incident close <id>` | インシデントの終了 |
