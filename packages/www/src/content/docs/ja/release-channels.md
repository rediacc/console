RediaccはCLIの更新を2つのチャネルで提供します：**Stable**と**Edge**。どちらも同じプロダクトに接続するため、アカウント、プラン、制限はどちらのチャネルでも同じです。違いは、リリースが手元に届くまでの早さだけです。

## Stableチャネル

Stableは全ユーザーのデフォルトチャネルです。リリースは7日間のソーク期間に問題が報告されなかった後、Edgeから昇格されます。

- 保守的なアップグレード周期を希望する場合に推奨
- Edgeでの7日間のテスト後にデプロイ
- 緊急の場合はhotfixを直接プッシュ可能

## Edgeチャネル

Edgeはmainにマージされるたびに即座に変更を受け取ります。継続的にデプロイされる最新バージョンのソフトウェアです。

- mainへのマージごとにリリース
- Stableと同じアカウント、プラン、制限
- 新機能をいち早く試したい場合に最適

## 1つのプロダクト、2つのチャネル

アカウントは、どちらのチャネルを使っていても、データリージョンの`eu.rediacc.cloud`、`us.rediacc.cloud`、`asia.rediacc.cloud`のいずれかにあります。チャネルを切り替えても、アカウント、データ、サブスクリプションには影響しません。リージョンについては[データリージョン](/ja/docs/data-regions)をご覧ください。

## 比較

| | Stable | Edge |
|---|---|---|
| **デプロイ頻度** | 7日間のソーク後 | mainへの全マージ時 |
| **安定性** | 7日間テスト済み | 最新コード、ソーク時間が短い |
| **プランと制限** | 同じ | 同じ |
| **アカウントとデータ** | 共通 | 共通 |
| **最適な用途** | 本番環境、有料ワークロード | 早期アクセス、評価 |

## 昇格の仕組み

1. mainブランチへの全マージが即座にEdgeにデプロイされます。
2. 7日間問題なければ、EdgeはStableに自動的に昇格されます。
3. 緊急hotfixは両チャネルに同時にプッシュできます。

これにより、StableはEdgeより常に最大7日遅れることになります。ソーク期間により、EdgeからStableへ伝播する前にリグレッションを検出します。

## どのチャネルを選ぶべきか？

**Stableを選ぶ場合：**
- 7日間のソーク期間を持つ保守的なアップグレード周期を希望している
- 最新機能よりも最大限の信頼性を優先する

**Edgeを選ぶ場合：**
- 新機能を早く試したい
- プラットフォームを評価中である
- より新しく、テストが少ないコードに抵抗がない

## インストール

いずれかのチャネルからのインストールコマンド（パッケージマネージャーの設定やDockerタグを含む）については[インストール](/en/docs/installation)を参照してください。

## CLIチャネル管理

CLIはインストール時に設定されたチャネルを使用します。チャネルを切り替えるには：

```bash
rdc update --channel edge      # Edgeに切り替える
rdc update --channel stable    # Stableに切り替える
```
