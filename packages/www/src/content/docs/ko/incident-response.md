# 인시던트 대응

여기서 인시던트란 고객 자신의 리포지토리 안에서 일어나는 사고를 말합니다. 조사 페이지, `rdc incident` 명령, `rdc repo flows`와 `rdc repo opens` 리더는 모두 [포렌식](/ko/docs/forensics)에서 설명한 기록을 바탕으로 동작합니다. Rediacc 자체 시스템의 인시던트는 [보안 인시던트 대응](/ko/docs/security-incident-response)을 따릅니다.

## 접근

조사에는 유료 플랜과 소유자 또는 관리자 역할이 필요합니다. 조사를 열 때 최근 재인증을 요구하며, 열린 조사는 60분 동안 유효합니다. 모든 조회는 감사 로그에 기록됩니다.

Rediacc 지원팀은 고객이 발급한 지원 권한이 있을 때만 포렌식 데이터를 볼 수 있습니다. 권한은 최대 7일간 유지되며 언제든 철회할 수 있습니다.

CLI 읽기에는 `forensics:read` 스코프가, 선언과 종료에는 `incident:manage`가 필요합니다. 소유자와 관리자의 CLI 로그인은 브라우저에서 상향 승인을 거친 뒤 둘 다 갖습니다. 최근 상향 승인이 필요하다고 명령이 응답하면 계정 포털이 승인을 요청하고, 이후 명령을 다시 실행하면 됩니다.

## 타임라인

Investigate 페이지는 하나의 범위(리포지토리 또는 머신)를 다섯 종류의 행으로 이루어진 하나의 타임라인으로 병합합니다. 콘솔 감사 이벤트, 실행, 네트워크 플로우, 파일 열기, 이상 징후입니다. 마지막 스냅샷 이후의 변경 사항을 그 스냅샷과 비교할 수 있습니다. 시간 창 스크러버로 기간을 정하며, 한 창은 최대 31일입니다.

증거가 없는 구간은 머신과 사유를 밝히는 공백 행으로 나타나며, 빈 구간으로 남지 않습니다. 행 위쪽에는 분당 송신 바이트 차트와 상위 목적지 목록이 있습니다.

같은 조회를 명령줄에서도 사용할 수 있습니다.

```bash
rdc repo flows mail --since 24h
rdc repo flows mail --since 2026-11-20T00:00:00Z --until 2026-11-21T00:00:00Z
rdc repo opens mail --since 7d
```

`--since`와 `--until`에는 ISO 8601 시각이나 `90m`, `24h`, `7d`처럼 현재로부터 거슬러 올라가는 기간을 쓸 수 있습니다. 기본 창은 최근 24시간입니다. 플로우 행에는 시각, 프로세스, 목적지, 송수신 바이트, 알려진 경우 ASN과 국가가 표시됩니다. 열기 행에는 시각, 프로세스, 경로가 표시되며 민감한 경로에는 표시가 붙습니다.

## 증거 검증

Verify evidence는 해당 창에 대해 감사 일일 파일의 해시 체인과 포렌식 기록의 서명된 배치 체인을 브라우저에서 다시 계산하고, 모든 공백과 편집을 나열합니다. 배치 서명은 계정 서버가 머신별로 고정해 둔 스풀 키로 확인합니다. 증거 안에 적힌 키는 신뢰하지 않습니다. 결과는 내보낸 보고서에 찍힙니다.

2 GiB를 넘는 증거는 브라우저에서 처리하기에 너무 큽니다. 같은 모듈을 명령줄에서 실행할 수 있습니다.

```bash
rdc forensics verify --dir ./incident-evidence
rdc forensics verify --dir ./incident-evidence --since 7d --machine-key web-1=<public-key-hex>
```

공백이나 편집이 발견되면 명령은 종료 코드 1로 끝납니다. `--machine-key <machine>=<public-key-hex>`(키는 16진수 64자)는 디렉터리 밖에서 키를 제공하며 반복해서 쓸 수 있습니다. 외부 키가 없는 머신은 실패합니다.

## 인시던트 선언

선언하면 증거가 동결됩니다. 먼저 계정 기록이 만들어지고, 그다음 리포지토리가 조사를 위해 준비됩니다.

1. 인시던트가 창, 선언자, 조직이 인지한 시점과 함께 기록됩니다.
2. 삭제 보류가 창을 덮고 버킷 잠금 규칙이 그 위로 확장되므로, FIFO가 해당 날짜를 지울 수 없습니다.
3. 리포지토리가 포렌식 스냅샷으로 포크되며 `incident-<id>` 태그가 붙습니다.
4. 리포지토리의 캡처 수준이 Full로 전환됩니다.

인지 시점부터 세 개의 기한이 시작됩니다. 인지 시점은 선언보다 앞서 설정할 수 있지만 뒤로는 설정할 수 없습니다. 조기 경보는 인지 24시간 후, 통지는 72시간 후, 최종 보고서는 통지 후 달력 기준 1개월이 기한입니다(통지가 기록될 때까지는 통지 기한부터 계산합니다). 페이지는 각 기한을 대기 중, 6시간 이내 마감, 기한 초과, 완료 중 하나로 표시합니다.

```bash
rdc incident declare mail
rdc incident declare mail --since 48h --aware-at 2026-11-20T09:30:00Z
rdc incident status
rdc incident status <id>
```

머신 단계가 실패해도 기록과 보류는 그대로 남고, 명령은 종료 코드 1로 끝나며 실패한 단계만 다시 실행하는 명령을 알려 줍니다.

```bash
rdc incident declare mail --resume <id>
```

`--resume`은 원래 선언의 창과 인지 시점을 유지하므로 `--since`, `--until`, `--aware-at`은 함께 쓸 수 없습니다.

## 증거 내보내기

`rdc incident export`는 인시던트의 창을 디렉터리에 기록합니다. 기한이 포함된 인시던트 기록, 병합된 타임라인, 송신 바이트 집계, 원본 체인 매니페스트, 매니페스트에 나열된 원본 파일입니다. 매니페스트에 감사 일일 파일이나 포렌식 헤더 파일이 있으면 그 과정에서 체인이 검증되고 결과는 `verification.json`에 저장됩니다. 증거에 공백이나 편집이 있으면 명령은 종료 코드 1로 끝납니다.

```bash
rdc incident export <id>
rdc incident export <id> --out ./incident-evidence
```

`--stage`를 쓰면 같은 명령이 대신 서명된 보고서를 작성합니다. [인시던트 보고서](/ko/docs/incident-reports)를 참고하세요.

## 인시던트 종료

```bash
rdc incident close <id>
```

바로 해제되는 것은 없습니다. 삭제 보류와 버킷 잠금 규칙은 종료 30일 후에 끝납니다.

## AI에게 묻기

조사 페이지에는 열려 있는 범위와 창에 대한 질문에 답하는 어시스턴트가 있습니다. 어시스턴트는 그 범위와 창만 읽으며, 열린 조사에서 발급되는 일회용 티켓을 사용합니다. 티켓은 15분 동안만 사용할 수 있습니다. 질문과 읽은 행은 조직 자체의 AI 제공업체로 전송됩니다. 어시스턴트는 다른 명령과 같은 권한 규칙에 따라 위의 `rdc` 명령을 실행할 수 있습니다.

## 명령

| 명령 | 용도 |
|---|---|
| `rdc repo flows <ref>` | 창 안에서의 리포지토리 네트워크 플로우 |
| `rdc repo opens <ref>` | 창 안에서의 리포지토리 민감 파일 열기 |
| `rdc forensics level <ref> <level>` | 캡처 수준 설정 |
| `rdc forensics verify` | 증거 디렉터리 또는 서명된 보고서 검증 |
| `rdc incident declare <ref>` | 인시던트를 기록하고 리포지토리를 포크한 뒤 Full로 전환 |
| `rdc incident status [id]` | 인시던트 목록, 또는 기한과 함께 하나를 표시 |
| `rdc incident export <id>` | 증거 창을 기록하거나, `--stage`로 서명된 보고서를 작성 |
| `rdc incident close <id>` | 인시던트 종료 |
