# 인시던트 보고서

선언된 인시던트([인시던트 대응](/ko/docs/incident-response))에서는 고객이 규제 기관에 제출할 세 가지 단계별 보고서가 생성됩니다. Rediacc는 증거를 바탕으로 문서를 생성합니다. 인시던트가 중대한지, 보고 대상인지는 여전히 고객의 판단이며, 모든 보고서에 그 점이 명시됩니다.

## 단계

각 단계에는 필요한 섹션만 들어갑니다. 해당 단계에서 요구하지 않는 섹션은 빈칸으로 남지 않고 생략됩니다.

| 단계 | 기한 | 추가 내용 |
|---|---|---|
| 조기 경보 | 인지 24시간 후 | 헤더, 타임라인, 침해 지표, 악의적 영향 및 국경 간 영향 의심 여부 |
| 통지 | 인지 72시간 후 | 초기 평가, 데이터 영향(범주, 대략적 건수, 회원국), ATT&CK 기법 |
| 최종 | 통지 후 달력 기준 1개월 | 근본 원인과 완화 조치 |

최종 보고서는 통지 다음에 이어지므로 통지를 먼저 생성합니다. 각 단계에는 이전 단계의 섹션이 포함됩니다.

보고서의 모든 사실에는 어떻게 알게 되었는지가 표시됩니다. 증거에서 관찰되었는지, 고객이 입력했는지, 추정되었는지입니다. 추정된 사실에는 신뢰도와 탐지기의 사유가 붙습니다. 평가, 데이터 범주, 회원국, 추정 원인, 취한 조치, 연락 담당자, 기법은 생성 전에 고객이 인시던트 페이지에서 입력하는 항목입니다.

## 형식

| 형식 | 용도 |
|---|---|
| JSON | 표준이자 검증 가능한 형식 |
| STIX 2.1 | 위협 인텔리전스 도구용 지표 번들 |
| PDF | 비라틴 문자도 표시하는 읽기 쉬운 문서로, 면책 문구, QR 코드, 보고서 해시가 모든 페이지 하단에 들어갑니다 |

인시던트 페이지에서는 각 단계마다 형식별 다운로드 버튼이 있습니다. 명령줄에서는 다음과 같이 합니다.

```bash
rdc incident export <id> --stage early-warning
rdc incident export <id> --stage notification --format stix
rdc incident export <id> --stage final --format pdf --out ./reports
```

형식의 기본값은 JSON입니다. `--format`은 `--stage`와 함께 쓸 때만 적용됩니다. 파일은 보고서 ID로 저장됩니다.

## 서명과 검증

각 보고서는 Ed25519 보고서 키로 서명되며, 보고서 ID, 단계, 해시는 공개 기록에 남습니다. 서명은 보고서의 표준 내용을 대상으로 하므로 서명 이후의 모든 변경이 탐지됩니다.

보고서는 세 곳에서 확인할 수 있습니다.

- `/account/verify/report/<id>`의 검증 페이지. PDF의 QR 코드가 이 페이지를 엽니다. 확인은 브라우저에서 공개된 보고서 키를 기준으로 수행되며 아무것도 업로드되지 않습니다. JSON 파일은 완전히 확인됩니다. PDF는 브라우저에서 다시 해시할 수 없으므로, 페이지는 PDF에 보고서의 해시가 있음을 확인하고 완전한 확인을 위해 JSON 파일을 안내합니다.
- 명령줄. JSON 보고서의 경우:

```bash
rdc forensics verify --report ./reports/<report-id>.json
```

내용이나 서명이 일치하지 않으면 명령은 종료 코드 1로 끝납니다. PDF는 그 기반이 된 JSON 보고서를 통해 검증합니다.

- 보고서 안의 증거 스탬프. 해당 창에 대한 Verify evidence의 결과로, 누가 어떤 버전으로 언제 검증했는지를 기록합니다.

## 항목 대응표

보고서의 각 항목은 고객이 보고하는 규제 체계에 대응되므로, 내용을 다시 입력하지 않고 옮겨 쓸 수 있습니다. 대응표는 세 가지 체계를 다룹니다. NIS2 제23조 제4항, 시행규칙(EU) 2025/302의 인시던트 통지 양식, GDPR 제33조 제3항입니다. 예시:

| 보고서 항목 | NIS2 | GDPR |
|---|---|---|
| 인지 시점 | 제23조(4)(a) | 제33조(1) |
| 시간순 경과 | 제23조(4)(d) | 제33조(3)(a) |
| 연락 담당자 | 제23조(4) | 제33조(3)(b) |

어떤 체계에 대응하는 항목이 없으면 생략하지 않고 그 이유를 밝힙니다. 예를 들어 GDPR 제33조 제3항의 통지에는 참조 번호나 종료 시각이 없습니다.

## 보고서가 주장하지 않는 것

모든 단계에 두 가지 문장이 인쇄됩니다.

- 플로우 기록이 증명하는 것은 양과 목적지이며 내용은 아닙니다.
- 인시던트가 중대한지, 보고 대상인지는 고객의 판단입니다.

Rediacc는 고객을 대신해 규제 기관에 아무것도 제출하지 않습니다.
