# 보안 모델

이 페이지에서는 설정 저장소가 무엇을 보호하는지, 어떤 키가 무엇을 여는지, 호출자 유형별로 무엇에 접근할 수 있는지 설명합니다. 설정 절차는 [설정 저장소](/ko/docs/config-storage)를, 세션과 토큰은 [계정 보안 및 API](/ko/docs/account-security)를 참고하세요.

## 누가 무엇을 볼 수 있는가

저장된 설정은 세 겹으로 암호화됩니다. SDK 계층과 조직 암호 구문 계층은 서버가 키를 관리합니다. 가운데 계층은 콘텐츠 암호화 키(CEK)이며, 키 슬롯 보유자만 잠금을 풀 수 있습니다. 기기에 보관된 슬롯 시크릿과 서버가 보관한 시크릿이 합쳐져야 열리므로, 어느 한쪽만으로는 열리지 않습니다.

| 공격자가 가진 것 | 설정 내용을 볼 수 있는가 | 이유 |
|---|---|---|
| 데이터베이스 사본만 | 볼 수 없음 | 설정 블롭은 데이터베이스가 아니라 오브젝트 스토리지에 있음 |
| 데이터베이스와 오브젝트 스토리지 | 볼 수 없음 | 조직 암호 구문 계층에는 Worker 시크릿이, CEK 계층에는 슬롯 시크릿이 필요함 |
| 서버 전체 침해 | 슬롯 시크릿 없이는 볼 수 없음 | 서버 계층은 뚫리지만 CEK는 패스키 PRF 출력이나 160비트 복구 키트 뒤에 남으며, 둘 다 추측할 수 없음 |
| 제거된 구성원의 기기 | 이미 가져간 내용 | CEK 순환 이후의 버전은 계속 닫혀 있음 |
| 유출된 에이전트 URL | 해당 사용자 권한으로 설정 하나 | [에이전트와 원격 MCP](#agents-and-remote-mcp) 참고 |

서버는 여전히 메타데이터(설정 ID, 팀, 버전, 타임스탬프, 블롭 크기)를 볼 수 있고, 요청을 거부하거나 지연하거나 삭제할 수 있습니다. 악성 포털 코드를 제공하는 운영자는 브라우저에서 키를 읽을 수 있습니다. 모든 블롭은 저장소, 설정, 팀, 버전에 묶여 있어 서버가 들키지 않고 바꾸거나 수정할 수 없으며, CLI는 이미 본 버전보다 오래된 버전을 거부합니다.

## 키 범위

- 조직마다 설정 저장소가 하나, 저장소마다 CEK가 하나입니다. 팀은 서버 측 접근 제어이지 암호학적 격리가 아닙니다. 복구 키트나 키 슬롯은 조직 전체의 CEK를 엽니다.
- 키 슬롯은 저장소, 사용자, 방식별로 고유하므로 복구 키트는 사용자와 조직마다 하나입니다. 두 조직에 속한 사용자는 키트를 두 개 가지며, 팀 키트는 없습니다.
- 머신 시크릿은 머신과 조직마다 하나이며, 헤드리스 머신을 등록하는 데 쓰입니다.
- 각 설정은 CEK 아래에 자체 콘텐츠 키를 가집니다. 에이전트 권한 부여에는 설정 하나의 콘텐츠 키만 들어 있으므로, 이것으로 조직의 다른 설정은 열리지 않습니다.
- 각 설정의 권한 부여 정책은 CEK와 레코드 포인터에서 파생된 키 아래에 있는 별도의 레코드입니다. 정책 키 하나를 가진 사람은 해당 포인터의 레코드만 엽니다.

## 에이전트와 원격 MCP

에이전트 권한 부여는 원격 MCP URL 뒤에 있는 키 보유자 유형입니다. 설정 하나의 콘텐츠 키와, 권한 부여 자체의 팀 설정 및 조직 수준 설정의 정책 키를 담고 있으며 CEK는 담지 않습니다. 따라서 에이전트는 담당 사용자가 읽을 수 있는 것과 정확히 같은 것을 읽습니다.

- **유효 기간.** URL은 기본 7일, 최대 30일 동안 유효하며, 이후 만료되거나 취소됩니다. 만료된 권한 부여는 거부되고 클라이언트가 다시 승인합니다.
- **범위.** 권한 부여는 설정 하나에만 닿으며 하나의 리전(eu, us, asia)에 속합니다. 다른 리전에 제시된 URL은 올바른 리전을 알려 주며 거부되고, 전달되지 않습니다. 온프레미스 설치는 단일 리전입니다.
- **정책.** 에이전트는 사람의 명시적 동의와 정책 상한이 모두 허용하는 범위에서만 동작합니다. 상한은 팀 정책으로 좁혀진 조직 정책입니다. 에이전트는 정책을 수정하거나, 시크릿 값을 읽거나, 자신의 권한 부여를 넓힐 수 없습니다.
- **피해 범위.** 유출된 URL은 만료되거나 취소될 때까지 해당 설정 하나에 대해 그 사용자로서 동작합니다. 해당 리전의 호스팅 실행기 밖에서는 아무것도 열지 못합니다.

도구 출력은 사용자가 연결한 모델 제공자에게 전달되며, 이 제공자는 Rediacc가 선택하지 않습니다.

### 온프레미스

경로에 Cloudflare가 없습니다. 클라우드의 Worker 시크릿은 고객 호스트의 환경 변수나 설정이 되므로, 위 표의 Worker 시크릿 경계는 호스트 접근으로 대체되고 도구 호출은 고객 자체의 데몬 실행기에서 실행됩니다.

## 정책

정책은 설정 항목마다 봉인되는 별도의 레코드이며, 저장소, 설정, 팀, 버전, 키 세대를 묶는 인증 데이터가 함께 들어갑니다. 서버는 이를 읽을 수 없고, 재전송되거나 바꿔치기된 레코드는 무결성 태그 검증에 실패합니다. 버전 1 정책 레코드는 거부됩니다.

조직 정책은 조직 소유자나 관리자만, 팀 정책은 팀 관리자(또는 소유자나 관리자)만 쓸 수 있습니다. 쓰기에는 2FA와 상승된 세션이 필요하며, 저장소가 패스키를 요구하면 연결된 패스키도 필요합니다. 모든 구성원과 이들을 처리하는 모든 실행기가 정책을 읽습니다. 조직이 잠근 키는 팀 정책에서 무시됩니다.

## 복구할 수 있는 것

| 상황 | 복구 방법 |
|---|---|
| 패스키 분실 | 복구 키트로 잠금을 풀고 새 패스키를 등록 |
| 키트 분실 | 사용 가능한 패스키로 다시 생성합니다. 이전 인쇄본은 쓸 수 없게 됩니다 |
| 둘 다 분실 | 소유자나 관리자가 구성원 핸드오프로 구성원을 다시 추가 |
| 마지막 키 보유자가 둘 다 분실 | 복구 불가이며, 그래서 두 번째 키 보유자를 권장합니다 |
| 구성원 제거 | 해당 슬롯과 토큰이 즉시 사라집니다. CEK 순환은 구성원이 보관한 키에 대해 이후 버전을 닫습니다 |
| CEK 순환 | CEK를 새 세대로 다시 감싸고 모든 복구 키트를 무효화 |

서버는 키 보유자가 두 명 미만이 되고 복구 슬롯도 남지 않게 되는 슬롯 삭제, 구성원 제거, 구성원 탈퇴를 거부합니다. 모든 구성원은 등록 시 필수 복구 키트를 받으며, 이를 보관하는 것은 구성원의 책임입니다.
