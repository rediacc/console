# 백업 및 복원

앱이 프로덕션에서 실행 중입니다. 이제 백업해두세요. `rdc`는 앱, 데이터베이스, 파일, 구성을 포함한 전체 저장소를 두 번째 머신에 복사하고, 첫 번째 머신이 사라졌을 때 그 복사본으로 되돌립니다.

이 튜토리얼은 그것을 설명만 하지 않습니다. 실제 머신 두 대에서 그대로 실행하고, 마지막에는 데이터를 직접 읽어 확인합니다.

## 튜토리얼 보기

![Tutorial: Backup and restore](/assets/tutorials/tutorial-backup-restore.cast)

## 세 가지 단계

![복사, 복원, 증명](/img/tutorials/tutorial-backup-restore/slide-1.svg)

1. 저장소를 직접 관리하는 머신에 **복사**합니다.
2. 그 복사본을 독립된 저장소로 **복원**합니다.
3. 데이터를 다시 읽어 **증명**합니다.

## 7단계: 데이터가 살아남았다

<TutorialStep number={7} />

두 결과를 나란히 놓고 비교해봅시다. 1단계, 원본 머신의 원본 저장소에서:

```text
order-1042 paid 2026-08-16
```

7단계, 두 명령어 전까지는 존재하지도 않았던 저장소에서, 그것도 다른 하드웨어 위에서:

```text
order-1042 paid 2026-08-16
```

이것이 이 튜토리얼입니다. 백업이 성공했다는 보고가 아니라, 그 데이터 한 줄을 다른 머신에서 그대로 읽어낸 것입니다.

## 8단계: 되돌릴 수 있는 백업

<TutorialStep number={8} />

계정을 사용하는 실제 환경에서는 전체 흐름이 다음과 같습니다.

```bash
rdc backup snapshot my-app
rdc backup manifests my-app
rdc backup restore my-app --as my-app-yesterday --at <snapshot-id> --up
```

스냅샷, 보존 정책, 검증에 대한 자세한 내용은 [백업 및 복원 가이드](/ko/docs/backup-restore)에서 다룹니다.
