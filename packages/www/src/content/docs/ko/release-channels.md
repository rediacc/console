Rediacc는 CLI 업데이트를 두 가지 채널로 배포합니다: **Stable**과 **Edge**. 두 채널 모두 같은 제품에 연결되므로 계정, 플랜, 제한이 어느 채널에서나 동일합니다. 채널의 차이는 릴리스가 얼마나 빨리 도착하느냐뿐입니다.

## Stable 채널

Stable은 기본 채널입니다. 릴리스는 보고된 문제 없이 Edge에서 7일간 머문 후에만 해당 채널에 도달합니다.

- 보수적인 업그레이드 주기를 선호하는 경우 권장됩니다.
- Edge에서 7일 테스트 후 배포됩니다.
- 중요한 경우 핫픽스를 직접 푸시할 수 있습니다.

## Edge 채널

Edge는 main에 병합되는 순간 모든 변경 사항을 받습니다. 지속적으로 배포되는 소프트웨어의 라이브 버전입니다.

- main에 병합될 때마다 릴리스됩니다.
- Stable과 같은 계정, 플랜, 제한을 사용합니다.
- 새로운 기능을 일찍 써 보고 싶을 때 적합합니다.

## 하나의 제품, 두 개의 채널

계정은 어느 채널을 쓰든 데이터 리전의 `eu.rediacc.cloud`, `us.rediacc.cloud`, `asia.rediacc.cloud` 중 한 곳에 있습니다. 채널을 바꿔도 계정, 데이터, 구독에는 영향이 없습니다. 리전에 대한 내용은 [데이터 리전](/ko/docs/data-regions)을 참고하세요.

## 비교

| | Stable | Edge |
|---|---|---|
| **배포 주기** | 7일 소크 후 | main에 매 병합 시 |
| **안정성** | 7일 테스트됨 | 프로덕션, 지속적으로 배포됨 |
| **플랜 및 제한** | 동일 | 동일 |
| **계정 및 데이터** | 공유 | 공유 |
| **적합한 용도** | 프로덕션, 유료 워크로드 | 조기 액세스, 평가 |

## 프로모션 작동 방식

1. main 브랜치에 매 병합 시 Edge에 즉시 배포됩니다.
2. 7일 동안 문제가 없으면 Edge가 자동으로 Stable로 프로모션됩니다.
3. 중요한 핫픽스는 두 채널에 동시에 푸시될 수 있습니다.

따라서 Stable은 Edge보다 최대 7일 뒤처집니다. 소크 기간은 Edge의 회귀가 Stable에 도달하기 전에 이를 포착합니다.

## 어느 채널을 선택해야 하나요?

**Stable을 선택하세요:**
- 7일 소크 기간이 있는 보수적인 업그레이드 주기를 선호하는 경우
- 최신 기능보다 최대 안정성을 선호하는 경우

**Edge를 선택하세요:**
- 새 기능을 일찍 시험해보고 싶은 경우
- 플랫폼을 평가 중인 경우
- 최신의 덜 테스트된 코드를 사용하는 것에 익숙한 경우

## 설치

각 채널의 설치 명령, 패키지 관리자 구성, Docker 태그는 [설치](/ko/docs/installation)를 참조하세요.

## CLI 채널 관리

CLI는 설치 시 구성한 채널을 사용합니다. 전환하려면:

```bash
rdc update --channel edge      # Edge로 전환
rdc update --channel stable    # Stable로 전환
```
