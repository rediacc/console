# 포렌식

포렌식은 리포지토리 안에서 실행되는 소프트웨어가 침해된 뒤 두 가지 질문에 답합니다. 데이터가 언제 빠져나갔는지, 그리고 어떤 데이터가 빠져나갔는지입니다. Rediacc는 서드파티 소프트웨어의 취약점을 막을 수 없으므로, 침해 이후에도 남는 증거를 기록합니다. 기록은 머신에서 리포지토리 샌드박스 밖에 있는 root 권한의 수집기가 작성하며, 고객의 관리자가 접근할 수 없는 버킷으로 전송됩니다.

기록에는 양, 목적지, 시점이 나타납니다. 플로우 기록이 증명하는 것은 양과 목적지이며 내용은 아닙니다. [인시던트 워크플로](/ko/docs/incident-response)가 이를 읽고, [인시던트 보고서](/ko/docs/incident-reports)가 규제 기관에 제출할 서명된 문서로 만듭니다.

## 기록되는 내용

캡처는 리포지토리 단위입니다. 리포지토리는 호스트 네트워크를 사용하므로, 트래픽은 IP 주소가 아니라 cgroup(리포지토리 자체의 슬라이스)으로 귀속됩니다.

| 기록 | 내용 |
|---|---|
| 네트워크 플로우 | 시각, 프로세스, 목적지 주소와 포트, 프로토콜, 송신·수신 바이트, 알려진 경우 DNS 이름, 알려진 경우 목적지의 ASN과 국가 |
| 파일 열기 | 민감 목록과 일치하는 경로에 대한 시각, 프로세스, 경로 |
| 하트비트 | 모든 배치에 들어가는 서명된 표식으로, 수집기가 멈추면 침묵이 아니라 공백으로 드러납니다 |

기본 민감 목록은 `.env` 파일, 키와 인증서 파일(`*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`), 비밀번호 데이터베이스(`*.kdbx`), 데이터베이스 덤프와 파일(`*.sql`, `*.dump`, `*.bak`, `*.sqlite*`), 그리고 `pgdata` 같은 데이터베이스 데이터 디렉터리를 포함합니다. 리포지토리는 이 목록을 확장하거나 자체 패턴으로 바꿀 수 있습니다.

패킷 페이로드와 파일 내용은 기록되지 않습니다.

## 캡처 수준

각 리포지토리에는 수준이 하나 있으며, 기본값은 가장 낮은 수준입니다. 높은 수준은 낮은 수준이 기록하는 모든 것을 기록합니다.

| 수준 | 기록 내용 |
|---|---|
| `basic` | 목적지, 포트, 프로토콜별 5분 요약(송수신 바이트 포함) |
| `standard` | 1분마다 플로우 기록(프로세스와 DNS 이름 포함) |
| `full` | Standard에 더해 민감한 경로의 파일 열기 |

수준은 리포지토리별로 설정합니다.

```bash
rdc forensics level mail basic
rdc forensics level mail standard
rdc forensics level mail full
```

수집기는 수준을 플랜에 포함된 범위로 제한합니다. 플랜에 포렌식 할당량이 없으면 리포지토리는 아무것도 기록하지 않습니다.

### 급증 트리거

모든 수준에서 트리거가 작동합니다. 리포지토리가 24시간 동안 관찰된 뒤, 1분 동안의 송신 바이트가 그 리포지토리 자체 이동 평균의 10배(그리고 분당 50 MiB)를 넘으면, 리포지토리는 24시간 동안 Full로 전환됩니다. 트리거를 발동시킨 분은 평균에 반영되지 않으므로, 한 번의 유출이 다음 유출을 잡아내야 할 기준선을 끌어올릴 수 없습니다.

## 플랜과 할당량

포렌식은 유료 플랜용이며, 플랜이 유료인 동안에만 기록합니다. 업그레이드하면 기록이 없는 상태에서 시작합니다.

| 플랜 | 포렌식 할당량 |
|---|---|
| Free, Community | 0(아무것도 기록하지 않음) |
| Professional | 25 GB |
| Business | 125 GB |
| Enterprise | 512 GB, 또는 Rediacc 관리자가 설정한 맞춤 할당량 |

할당량은 플랜 백업 할당량의 4분의 1이며 백업 집계와는 별도입니다. 할당량을 늘리려면 플랜을 업그레이드해야 합니다.

할당량이 가득 차면 가장 오래된 기록부터 삭제됩니다(FIFO). 최근 7일분은 잠겨 있어 삭제되지 않으며, 버킷이 7일 동안 잠그기 때문입니다. 잠긴 바이트만으로 할당량을 넘으면 새 배치는 거부됩니다. 예상되는 7일치 수집량이 들어가지 않으면 수준은 Basic으로 제한됩니다. 소유자와 관리자는 할당량의 80퍼센트에 도달했을 때, 상한이 Basic으로 내려갈 때, 배치가 거부될 때 알림을 받습니다.

선언된 인시던트 범위에 속하는 기록은 인시던트가 종료된 뒤 30일까지 삭제 대상에서 제외됩니다. [인시던트 대응](/ko/docs/incident-response)을 참고하세요.

## 전송과 무결성

수집기는 30초마다 배치를 만듭니다. 각 배치는 머신의 스풀 키로 서명되고 이전 배치의 해시를 담고 있어, 삭제되거나 편집된 배치가 있으면 체인이 끊어집니다. 배치는 머신의 라이선스 블롭에서 발급되는 생성 전용 사전 서명 URL로 업로드되므로, 머신은 기록을 추가할 수 있지만 덮어쓰거나 삭제할 수 없습니다. 연결이 끊기면 배치는 로컬의 서명된 스풀에서 대기하다가 연결이 돌아오면 전송됩니다.

야간 압축 과정에서 배치는 리포지토리별 일일 파일 하나와 머신별 헤더 파일 하나로 병합되며, 헤더 파일에는 서명된 모든 헤더가 나열되고 공백이 표시됩니다. 계정의 감사 일일 파일도 조직과 날짜별로 같은 방식으로 체인이 연결됩니다.

`rdc forensics verify`와 조사 페이지의 Verify evidence 버튼은 이 체인을 다시 계산합니다. [인시던트 대응](/ko/docs/incident-response)을 참고하세요.

## 탐지

이상 탐지는 두 번 실행됩니다. 머신의 통계적 탐지기가 즉시 반응해 리포지토리를 Full로 전환합니다. 서버도 수집 시점에 자체 탐지기를 실행하므로, 호스트가 침해되어도 탐지는 유지됩니다. 로그 레코드마다 AI가 실행되지는 않습니다.

탐지기는 계층으로 구성되며, 각 리포지토리는 자신의 트래픽에서 학습합니다.

| 탐지기 | 찾는 대상 |
|---|---|
| 주간 시간대별 기준선 | 해당 시간대의 리포지토리 평소 패턴을 벗어난 바이트, 연결, 고유 목적지, 새 DNS 이름, 새 프로세스 |
| Half-Space Trees | 이전에 본 플로우와 다른 플로우 |
| ECOD와 HBOS | 이상치로 점수가 매겨진 플로우 배치와 점수를 끌어올린 특징 |
| 처음 관찰 | 이전에 연 적 없는 민감한 파일을 여는 프로세스 |

각 탐지 결과에는 그 결과를 만든 특징별 이유가 붙고, 설명은 그 이유로 만든 템플릿입니다. 오프라인에서는 언어 모델을 쓰지 않습니다. 탐지 결과는 계정 알림이 되며 소유자, 관리자, 보안 담당자에게 이메일로 전달됩니다. 머신이 오프라인이면 로컬에서 즉시 대응하고(Full 캡처와 서명된 스풀에 기록), 연결이 돌아오면 경보를 전달하되 원래의 탐지 시각을 유지합니다.

### 모델 번들

탐지기 매개변수는 `data.rediacc.com/models/`에 서명된 번들로 게시됩니다. 콘텐츠 주소 방식의 파일, renet에 내장된 오프라인 Ed25519 모델 키로 서명된 매니페스트, 최소 renet 버전, 증가만 하는 버전 번호로 구성되어 다운그레이드는 거부됩니다. 번들은 설치 전에 검증되며, 이전 번들로 복원할 수 있습니다.

```bash
renet models status
renet models update
renet models rollback
```

에어갭 설치에는 `--no-models`를 지정하지 않는 한 `rdc server bundle` 안에 같은 서명된 번들이 포함됩니다.

## 서버가 읽을 수 있는 내용

계정 서버는 기록을 읽습니다. 타임라인, 검증, 서버 탐지기에 필요하기 때문입니다. 읽는 것은 목적지, 포트, 프로세스 이름, DNS 이름, 바이트 수, 민감한 파일 경로입니다. 패킷 페이로드나 파일 내용은 받지 않습니다.

수신 클라이언트 주소는 기록에 일부만 남겨 저장되고(IPv4는 /24, IPv6는 /48), 전체 주소는 별도 섹션에 두었다가 30일 뒤 삭제됩니다. 삭제된 섹션의 해시는 서명된 헤더에 남아 있으므로 체인은 계속 검증되며, 검증기는 해당 주소를 가려진 것으로 보고합니다. 송신 목적지는 그 자체가 증거이므로 전체가 유지됩니다.

고객은 조사를 통해 기록을 엽니다. 조사에는 유료 플랜, 소유자 또는 관리자 역할, 최근 재인증이 필요하며 모든 조회는 감사됩니다. Rediacc 지원팀은 고객이 발급한 기한 제한 권한이 있을 때만 포렌식 데이터를 볼 수 있습니다. 처리 조건은 [데이터 처리 계약](/ko/data-processing-agreement)에 있습니다.
