## نظرة عامة

يوفّر خادما MCP (Model Context Protocol) سجلّ الأدوات نفسه:

| الخادم | النقل | طريقة التشغيل | الأدوات |
|---|---|---|---|
| محلي | stdio | `rdc mcp serve`، يشغّله الوكيل | جميع الأدوات |
| بعيد | Streamable HTTP | `https://mcp.<region>.rediacc.cloud/g/<grantId>` | الأدوات البعيدة، أي جميع الأدوات عدا المذكورة في جدول الأدوات المحلية فقط |

**المتطلبات الأساسية:** للخادم المحلي، يجب تثبيت `rdc` وتكوينه مع جهاز واحد على الأقل. أما الخادم البعيد فيحتاج إلى منحة (grant) على تكوين.

## الخادم المحلي

يشغّل `rdc mcp serve` خادم MCP عبر stdio. يشغّله الوكيل كعملية فرعية ويتواصل معه عبر JSON-RPC.

### Claude Code

يحتوي ملف `.mcp.json` الخاص بالمشروع على الإدخال التالي:

```json
{
  "mcpServers": {
    "rdc": {
      "command": "rdc",
      "args": ["mcp", "serve"]
    }
  }
}
```

أو باستخدام تكوين مسمّى:

```json
{
  "mcpServers": {
    "rdc": {
      "command": "rdc",
      "args": ["mcp", "serve", "--config", "production"]
    }
  }
}
```

### Cursor

افتح Settings → MCP Servers → Add Server:

- **Name**: `rdc`
- **Command**: `rdc mcp serve`
- **Transport**: stdio

### الخيارات

| الخيار | الافتراضي | الوصف |
|--------|-----------|-------|
| `--config <name>` | (التكوين الافتراضي) | التكوين المسمّى المستخدم في جميع الأوامر |
| `--timeout <ms>` | `120000` | المهلة الافتراضية للأوامر بالميلي ثانية |

## الخادم البعيد

يعمل Worker واحد لـ MCP في كل منطقة على `mcp.<region>.rediacc.cloud`. يتصل كل وكيل بعنوان URL لمنحة واحدة: `https://mcp.<region>.rediacc.cloud/g/<grantId>`. تحدّد المنحة تكوينًا واحدًا وتاريخ انتهاء ونطاقًا: علامة للقراءة فقط، وقائمة بالأدوات المسموح بها، وأنماط glob لأسماء الأجهزة والمستودعات. تعمل استدعاءات الأدوات على المنفّذ الخاص بمؤسسة المنحة.

### بيانات الاعتماد

كلا الشكلين يحدّد المنحة؛ أما معرّف المنحة في عنوان URL فيسمّيها فقط.

| الشكل | الاستخدام | يُرسل بصيغة |
|---|---|---|
| رمز وصول OAuth | العملاء التفاعليون مثل claude.ai | `Authorization: Bearer <token>` |
| رمز حامل الوكيل `rmcp_<grantId>.<secret>` | الوكلاء بلا واجهة | `Authorization: Bearer` أو `x-api-key` |

تُرفض بيانات الاعتماد الموضوعة في سلسلة الاستعلام برمز 400. يتلقى رمز OAuth المفقود أو المنتهي أو العائد لمنحة أخرى الرمز 401 مع ترويسة `WWW-Authenticate: Bearer resource_metadata=...` التي تشير إلى مستند المورد المحمي للمنحة، فيجدّد عميل OAuth الرمز أو يسجّل الدخول. أما المنحة المجهولة والسر الخاطئ ورمز حامل الوكيل العائد لمنحة أخرى فتتلقى جميعها رمز 401 المجرّد نفسه.

### OAuth

الـ Worker خادم تفويض OAuth 2.1 مع PKCE (S256 فقط). يسجّل العملاء أنفسهم عبر مستند Client ID Metadata Document أو عبر التسجيل الديناميكي للعملاء على `/register`.

| نقطة النهاية | الغرض |
|---|---|
| `/.well-known/oauth-authorization-server` | بيانات الخادم الوصفية |
| `/.well-known/oauth-protected-resource/g/<grantId>` | مستند المورد المحمي لمنحة واحدة |
| `/authorize` | يبدأ التفويض ويعيد التوجيه إلى صفحة الحساب `/account/mcp/authorize` |
| `/oauth/token` | تبادل الرمز والتجديد والإلغاء |
| `/register` | التسجيل الديناميكي للعملاء |

يرسل العميل `resource=https://mcp.<region>.rediacc.cloud/g/<grantId>`. لا يكتمل التفويض إلا للمنحة التي يسمّيها المورد، ولا يعمل الرمز إلا على عنوان URL الخاص بمنحته. يحمل التوجيه من `/authorize` معرّفًا موقّعًا للاستخدام مرة واحدة ولا يحمل أي سر.

### مدة صلاحية الرموز

لا يعيش الرمز أطول من منحته.

| الرمز | مدة الصلاحية |
|---|---|
| رمز الوصول | الأقصر بين ساعة واحدة والوقت المتبقي للمنحة |
| رمز التجديد | الأقصر بين 30 يومًا والوقت المتبقي للمنحة |

يعيد كل تبادل للرمز وكل تجديد البحث عن المنحة. تردّ المنحة المنتهية أو الملغاة أو التي دُوِّر مفتاحها بالرمز `invalid_grant` وتلغي منحة OAuth. تُدوَّر رموز التجديد، ويؤدي تقديم الرمز نفسه مرتين إلى إلغاء المنحة.

### تكوين واحد لكل منحة

تخدم المنحة التكوين الواحد الذي تسمّيه فقط. يُرفض استدعاء `tools/call` الذي يتضمن وسيطًا يسمّي تكوينًا آخر (`config` أو إحدى صيغ كتابته) برمز `REDIACC_GRANT_SCOPE` قبل تشغيل أي شيء. من لديه عدة تكوينات يفوّض منحة واحدة لكل تكوين. الأداة الخارجة عن قائمة المنحة المسموح بها، أو أداة الكتابة ضمن منحة للقراءة فقط، لا تظهر في `tools/list` وتُرفض عند استدعائها.

### المناطق

يبدأ معرّف المنحة باسم منطقته، مثل `eu_`. يتلقى الطلب إلى `/g/<grantId>` على Worker منطقة أخرى الرمز 421 مع عنوان URL الصحيح:

```json
{
  "code": "REDIACC_WRONG_REGION",
  "message": "This grant lives in the us region. Use https://mcp.us.rediacc.cloud/g/us_...",
  "region": "us",
  "mcpUrl": "https://mcp.us.rediacc.cloud/g/us_..."
}
```

لا تُقبل المنحة أبدًا كمورد OAuth أو جمهور للرمز أو هدف للتفويض خارج منطقتها.

### حالات المنحة والحدود

تظل المنحة التي انتهت أو أُلغيت أو فقدت مفتاحها بسبب تدوير مفاتيح مخزن التكوين تردّ على `initialize` و`tools/list`. ثم يعيد كل `tools/call` الرمز `REDIACC_GRANT_EXPIRED` أو `REDIACC_GRANT_REVOKED` أو `REDIACC_KEY_ROTATED` مع `reauthUrl` يفتحه المستخدم للتفويض من جديد.

تسمح كل منحة بـ 60 استدعاءً في الدقيقة و5 استدعاءات قيد التنفيذ في وقت واحد. يعيد الاستدعاء الذي يتجاوز أيًّا من الحدّين `REDIACC_RATE_LIMITED` مع `retryAfterSeconds`.

## أمثلة على سير العمل

**التحقق من حالة جهاز:**
> "ما حالة جهاز الإنتاج لديّ؟"

يستدعي الوكيل `machine_status` ويحصل على تفاصيل الاتصال ومعلومات النظام والحاويات والخدمات والمستودعات واستخدام الموارد.

**نشر تطبيق:**
> "انشر gitlab على جهاز staging لديّ"

يستدعي الوكيل `repo_up` مع `name: "gitlab"` و`machine: "staging"`، فيُنشر المستودع ويُعاد النجاح أو الفشل.

**متابعة مهمة طويلة:**
> "استعد نسخة nextcloud الاحتياطية من ليلة أمس"

يستدعي الوكيل `backup_restore`. الأمر الذي يتجاوز مهلته يعيد مقبض مهمة، ثم يستدعي الوكيل `job_wait` (حتى 50 ثانية في كل استدعاء) و`job_logs` إلى أن تنتهي المهمة.

**تصحيح خدمة معطلة:**
> "nextcloud لديّ بطيء، اكتشف السبب"

يستدعي الوكيل `machine_health` ثم `machine_containers` و`repo_logs`، ويقترح إصلاحًا.

## الأمان

يطبّق خادم MCP المحلي طبقتين من الحماية. حدود الخادم البعيد موضحة في [الخادم البعيد](#الخادم-البعيد).

### وضع النسخ فقط (الافتراضي)

يعمل الخادم افتراضيًا في **وضع النسخ فقط**: لا تستطيع أدوات الكتابة (`repo_up` و`repo_down` و`repo_delete` و`repo_exec`) العمل إلا على مستودعات النسخ (fork). لا يمكن للوكلاء لمس المستودعات الأصلية (grand). هذا بحكم التصميم.

> **أسرار المستودعات متاحة عبر CLI فقط بحكم التصميم.** أداتا `repo_secret_set` و `repo_secret_unset` مستبعدتان عمدا من أدوات MCP. تستلزم عمليات الكتابة شرطا مسبقا `--current <previous-value>` (أو `--rotate-secret` للإقرار بتدوير غير مُتحقق منه)، وهذا الإجراء يستوجب إشراف بشري مباشر. على الوكلاء الذين يريدون اقتراح تدوير سر أن يستدعوا `repo_secret_get` للتحقق من البصمة، ثم يُمرروا أمر CLI الموجّه للمشغّل إلى المستخدم عبر الحقل `next.options[].run` في غلاف أخطاء JSON. راجع [أمان وكلاء الذكاء الاصطناعي](/en/docs/ai-agents-safety#structured-next-action-hints) للاطلاع على النمط الكامل، و[المستودعات § الأسرار](/en/docs/repositories#secrets) لتعليمات الاستخدام.

لمنح وكيل صلاحية تعديل المستودعات الأصلية، صدّر `REDIACC_ALLOW_GRAND_REPO` في طرفيتك **قبل بدء الوكيل الذي يستضيف خادم MCP**:

```bash
export REDIACC_ALLOW_GRAND_REPO='gitlab'   # مستودع واحد
# أو 'repo1,repo2,repo3' (المسافات البيضاء حول المُدخَلات تُتجاهل)، أو '*' لجميع المستودعات
claude   # أو cursor أو gemini إلخ
```

يُتحقق التجاوز من سلسلة السلف: يُعتبر فقط عندما كان موجوداً بالفعل في بيئة عملية الوكيل نفسه، مما يعني أنك صدّرته قبل بدء الوكيل (وخادم MCP الذي أنشأه). لا يستطيع الوكيل منح نفسه الوصول بضبط المتغير في منتصف الجلسة. لا توجد علامة خادم لهذا بقصد: علامة في وسائط خادم MCP لا تحمل إثباتاً عن من وضعها، بينما فحص السلف يفعل. الوصول على مستوى الآلة (مثل `term connect <machine>` دون مستودع) لا يزال يتطلب `*`؛ قائمة أسماء المستودعات لا تفتح هذا الوصول.

### مفاتيح SSH لكل مستودع والصندوق المحمي من جانب الخادم

لكل مستودع زوج مفاتيح SSH خاص به. يُنشر المفتاح العام في `authorized_keys` بادئةً `command=` تُجبر جميع جلسات SSH على المرور عبر `renet sandbox-gateway <repo-name>`، وهو ForceCommand من جانب الخادم لا يمكن لأي عميل تجاوزه، بما في ذلك VS Code.

**آلية العمل:**
1. ينشئ `rdc repo create` أو `rdc repo fork` زوج مفاتيح ed25519 فريدا لكل مستودع
2. يُنشر المفتاح العام على الخادم البعيد مع `command="renet sandbox-gateway <name>"`
3. تمر كل اتصالات SSH التي تستخدم هذا المفتاح عبر البوابة التي تطبّق:
   - **Landlock LSM**، قيود نظام الملفات على مستوى النواة مقيّدة بمسار تثبيت المستودع
   - **OverlayFS home overlay**، تُسجَّل الكتابات إلى `$HOME` لكل مستودع بشكل منفصل، بينما تمر القراءات إلى المجلد الرئيسي الفعلي
   - **TMPDIR خاص بالمستودع** في `<datastore>/.interim/sandbox/<name>/tmp/`
   - **وصول Docker** عبر مقبس Docker المعزول الخاص بالمستودع
   - **تخفيض الصلاحيات** إلى المستخدم الموحد (`rediacc`)
4. يُحمَّل ملف `.envrc` الخاص بالمستودع تلقائيا لإعداد Docker والبيئة

**مسموح بالقراءة والكتابة**: مسار تثبيت المستودع، مساحة عمل الصندوق المحمي الخاصة بالمستودع، المجلد الرئيسي (عبر overlay)، مقبس Docker
**مسموح بالقراءة فقط**: مسارات النظام (`/usr`، `/bin`، `/etc`، `/proc`، `/sys`)
**محظور**: مسارات تثبيت المستودعات الأخرى، ملفات النظام خارج القائمة المسموح بها

**تكامل VS Code**: يحصل كل مستودع على تثبيت خادم VS Code خاص به في `<datastore>/.interim/sandbox/<name>/.vscode-server/`. يمكن فتح مستودعات متعددة في آن واحد ببيئات صندوق محمي مستقلة، دون مشاركة الخادم بين المستودعات.

هذا يمنع الانتقال الجانبي. حتى لو استطاع وكيل الحصول على وصول صدفة إلى نسخة ما، فلن يستطيع قراءة أو تعديل مستودعات أخرى على نفس الجهاز. تستخدم الاتصالات SSH على مستوى الجهاز (دون مستودع) مفتاح الفريق وليست مقيّدة بصندوق محمي.

## البنية المعمارية

خادم MCP المحلي عديم الحالة. يشغّل كل استدعاء أداة `rdc` كعملية فرعية معزولة بالأعلام `--output json --yes --quiet`. وهذا يعني:

- لا تسرب للحالة بين استدعاءات الأدوات
- يستخدم تكوين `rdc` الحالي ومفاتيح SSH الخاصة بك
- الأخطاء في أمر واحد لا تؤثر على الأوامر الأخرى
