# تخزين الإعدادات

يزامن تخزين الإعدادات إعداد واجهة سطر الأوامر عبر الأجهزة. تُشفَّر الإعدادات على الجهاز بمفتاح تشفير محتوى (CEK) لا يحتفظ به الخادم أبداً. يوضح قسم [الأمان](#security) بدقة ما الذي يحميه ذلك وما لا يحميه.

## طرق فك القفل (فتحات المفاتيح)

هناك مفتاح تشفير محتوى (CEK) واحد لكل مخزن، يُغلَّف بشكل مستقل لكل طريقة فك قفل، على غرار فتحات مفاتيح LUKS. أي فتحة واحدة تفتح المفتاح نفسه، ويمكن إضافة الفتحات أو إزالتها دون إعادة تشفير بياناتك:

| الطريقة | ما هي | ملاحظات |
|--------|-----------|-------|
| **مفتاح المرور** | مفتاح مرور WebAuthn مع امتداد PRF | الخيار الأقوى؛ مدعوم بالعتاد |
| **كلمة المرور الرئيسية** | كلمة مرور تختارها، تُقوَّى باستخدام PBKDF2-SHA256 (600,000 تكرار) | تعمل بدون عتاد يدعم PRF؛ وتتيح أيضاً التسجيل بدون واجهة في واجهة سطر الأوامر |
| **رمز الاسترداد** | رمز يُنشأ بالصيغة `RC1-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX` | يُعرض مرة واحدة فقط عند الإنشاء؛ احفظه في مكان آمن |

تغذي كل طريقة المسار نفسه: تُنتج الفتحة سراً يتحد مع سر يحتفظ به الخادم لفك تغليف مفتاح CEK. لا يكفي أي من النصفين بمفرده، ولا يصل سر الفتحة إلى الخادم أبداً. فتحة كلمة المرور الرئيسية هي الأضعف بين الثلاث: يملك الخادم كل ما يلزم لتجربة تخمين كلمة المرور دون اتصال، لذا يجب أن تكون كلمة المرور قوية. لا تعاني فتحتا مفتاح المرور ورمز الاسترداد من هذا الضعف.

تُدار الفتحات من البوابة في صفحة تخزين الإعدادات. المؤسسات التي تريد فك قفل بالعتاد فقط يمكنها تفعيل سياسة **طلب مفتاح المرور**، التي ترفض أي فتحة غير مفتاح مرور وتُلغيها من المخزن بالكامل.

فك القفل مرتبط بالجهاز: تفك القفل مرة واحدة على جهاز جديد، وبعدها تعمل عمليات واجهة سطر الأوامر اليومية (push/pull) دون الحاجة لمفتاح مرور أو كتابة كلمة مرور.

## المتطلبات الأساسية

- **المصادقة الثنائية** مفعّلة على حسابك
- لطريقة **مفتاح المرور**: مزود مفتاح مرور يدعم PRF، مثل مفتاح أمان FIDO2 (كـ YubiKey)، أو iCloud Keychain، أو Google Password Manager، أو 1Password، أو Dashlane
- **المتصفح**: Chrome 133+، أو Edge 133+، أو Firefox 130+، أو Safari 17+

ينطبق شرط PRF على فتحة مفتاح المرور فقط. أما طريقتا كلمة المرور الرئيسية ورمز الاسترداد فتعملان مع أي متصفح مدعوم.

## الإعداد

1. انتقل إلى **تخزين الإعدادات** في الشريط الجانبي، ثم انقر على **إعداد تخزين الإعدادات**
2. تتحقق قائمة المتطلبات من متصفحك والمصادقة الثنائية وحالة الجلسة
3. اختر طريقة فتح القفل الأولى، ثم انقر على **إنشاء مخزن تكوين**:
   - **مفتاح المرور (Passkey)**، إذا كان مزوّدك يدعم PRF: تلمس مفتاح الأمان مرتين، مرة لتسجيله ومرة لاشتقاق مفاتيح التشفير.
   - **كلمة المرور الرئيسية**، وتعمل مع أي متصفح، بما في ذلك مزوّدو مفاتيح المرور الذين لا يدعمون PRF مثل Bitwarden.
   - اختياريًا **رمز استرداد**، يُعرض مرة واحدة ويجب حفظه قبل إنشاء المخزن.
4. اكتمل الإعداد. تحتفظ واجهة سطر الأوامر بسرّ فتح القفل في سلسلة مفاتيح نظام التشغيل.

يمكن إضافة مفتاح مرور لاحقًا من صفحة Config Storage. احتفظ بطريقتين على الأقل لفتح القفل، حتى لا يمنعك من الوصول مصادِقٌ مفقود أو غير مدعوم.

## توافق مزودي PRF

| المزود | دعم PRF | المنصات |
|----------|:-----------:|-----------|
| YubiKey / مفاتيح أمان FIDO2 | ✅ | Windows 11، macOS، Linux |
| iCloud Keychain | ✅ | macOS 15+، iOS 18+ |
| Google Password Manager | ✅ | Android |
| 1Password | ✅ | Android، iOS |
| Dashlane | ✅ | متعدد المنصات |
| إضافة Bitwarden | ❌ | استخدم كلمة المرور الرئيسية بدلًا منه |
| Windows Hello | ❌ | غير مدعوم |

## التسجيل بدون واجهة في واجهة سطر الأوامر

يمكن لجهاز بلا متصفح (خادم، أو عامل CI، أو خدمة تنفيذ) التسجيل في مخزن قائم باستخدام طريقة كلمة المرور الرئيسية:

```bash
rdc config remote enable --password
```

المتطلبات:

- **فتحة كلمة مرور رئيسية** مُهيَّأة مسبقاً عبر البوابة (يحتفظ المتصفح بالمفتاح أثناء التهيئة، لذا لا يمكن أن تكون هذه الخطوة نفسها بدون واجهة)
- **رمز وصول API يحمل نطاق `config:enroll`** لمصادقة الطلب

التسجيل عملية قراءة: تجلب واجهة سطر الأوامر معاملات KDF العامة للفتحة والمفتاح المُغلَّف، وتشتق سر كلمة المرور محلياً، وتفك تغليف مفتاح CEK على الجهاز نفسه. يمنح ذلك الجهاز القدرة على فك تشفير الإعدادات ومزامنتها؛ ولا يُعدِّل المخزن.

## التفعيل والقراءة بلا اتصال

يربط أمر `rdc config remote enable` الإعداد النشط بالمخزن. عندما يكون المخزن فارغاً، يقوم التفعيل بـ**تعبئته من إعدادك المحلي الحالي**: تُدفع الموارد المحلية كأول إصدار للمخزن، ثم تُسحب مرة أخرى لإثبات صحة الدورة الكاملة. عندما يحتوي المخزن على محتوى بالفعل، فإن التفعيل يوفّق معه بدلاً من الكتابة فوقه (يتوقف عند تباين حقيقي ما لم تمرر `--force`).

بعد التفعيل، يحتفظ الإعداد بـ**ذاكرة تخزين مؤقت للقراءة** كاملة، مشفّرة أثناء التخزين بنفس آلية أي إعداد محلي، بحيث يبقى المخزن قابلاً للاستخدام عندما يتعذر الوصول إلى خادم الحساب:

- **تعمل القراءات دون اتصال.** يُقدَّم المحتوى المخزَّن مؤقتاً مع تحذير بعدم الحداثة على stderr، موسوماً بإصدار وطابع زمني للتخزين المؤقت (`cachedVersion` / `cachedAt`).
- **تتطلب الكتابة الخادم وتفشل بأمان.** لا توجد قائمة انتظار كتابة دون اتصال: أي كتابة لا يمكنها الوصول إلى الخادم تفشل مع ذكر اسم الخادم. إذا نجح أمر كتابة، فإن التغيير موجود على الخادم.
- **تُحل التعديلات المتزامنة من جهازين** عبر السحب-إعادة التطبيق-إعادة الدفع (pull-replay-repush): يقبل الخادم الدفع فقط فوق الإصدار الذي يستبدله، وتُعاد محاولة الدفع الخاسر فوق النسخة الحديثة، بحيث لا يُستبدَل تعديل متزامن في مكان آخر.
- **الإعداد المحلي** (الذي لا يحتوي على كتلة `remote`) لا يتأثر بأي من ذلك ويعمل بالكامل دون اتصال.

## ما الذي تتم مزامنته

تتم مزامنة كل شيء في الإعداد، بما في ذلك معرّف الشبكة الخاص بكل مستودع، باستثناء هذه الحقول المحلية على الجهاز: `schemaVersion`، و`version`، و`remote`، و`encryption`، و`renetPath`، و`credentials.masterPasswordVerifier`، وحقلَي تسجيل الدخول `account.accountServer` و`account.e2ePublicKey`. تسجيل الدخول والخروج يتم لكل جهاز على حدة.

## الإصدارات والاستعادة

يحتفظ الخادم بآخر 50 إصداراً لكل إعداد.

```bash
rdc config remote versions
rdc config remote restore <version>
```

تنشر الاستعادة المحتوى القديم كإصدار جديد فوق الإصدار الحالي؛ ولا تُرجع رقم الإصدار إلى الوراء أبداً. يحصل كل جهاز على المحتوى المستعاد عند عملية السحب (pull) التالية، وتُسجَّل الاستعادة في سجل التدقيق.

## تدوير المفتاح

يؤدي تدوير مفتاح CEK الخاص بالمخزن إلى إعادة تغليفه تحت جيل جديد:

- **تُبطَل رموز الاسترداد دائماً** عند التدوير، لذا أنشئ رمزاً جديداً واحفظه بعد ذلك
- تبقى **فتحة كلمة المرور الرئيسية** صالحة فقط إذا أُعيد إدخال كلمة المرور أثناء معالج التدوير
- تُبلَّغ أي فتحة متروكة عند جيل أقدم بأنها قديمة بدلاً من أن تفشل بخطأ فك تشفير غامض
- تُلغى رموز الإعداد الخاصة بالأعضاء الآخرين، ويُطلب من أي جهاز لا يزال يحمل المفتاح القديم إعادة التفعيل باستخدام `rdc config remote enable`

## إدارة الأعضاء

تخزين الإعدادات محدد لكل مؤسسة. تتم إدارة الأعضاء عبر بوابة الويب:

- **عرض الأعضاء**: تخزين الإعدادات ← الأعضاء
- **إضافة عضو**: حالياً عبر واجهة سطر الأوامر فقط (واجهة الويب مخططة)
- **إزالة عضو**: انقر على زر الإزالة في صفحة الأعضاء (يتطلب المصادقة الثنائية + إعادة المصادقة)

تمنع الحمايات الأمنية إزالة آخر عضو نشط أو إزالة نفسك.

تخضع الإعدادات داخل المخزن أيضاً لنطاق كل فريق، لكن هذا النطاق هو **تحكم وصول من جانب الخادم، وليس عزلاً تشفيرياً**: يُشفِّر مفتاح CEK واحد على مستوى المؤسسة إعدادات جميع الفرق، ويفرض الخادم أي الفرق يمكن لعضو معين قراءتها.

## الأمان

**ما هو محمي.** الإعدادات المخزَّنة سرّية في مواجهة اختراق تخزين الخادم وفي مواجهة مشغِّل سلبي. كل كتلة بيانات (blob) مرتبطة بمخزنها، وإعدادها، وفريقها، وإصدارها، لذا لا يستطيع الخادم استبدال كتلة بيانات إعداد بأخرى أو تعديلها دون أن يُكتشف ذلك.

**ما هو غير محمي.** يمكن لمشغِّل يقدّم شيفرة بوابة خبيثة قراءة المفتاح في المتصفح. كما يمكن لمشغِّل حجب أحدث إصدار عن جهاز لم يره من قبل.

| ما يستطيع الخادم فعله | ما لا يستطيع الخادم فعله |
|---|---|
| رؤية معرّفات الإعدادات، والفرق، وأرقام الإصدارات، والطوابع الزمنية، وأحجام كتل البيانات، وعدد الحقول التي يلتزم بها الإعداد ونوع كل حقل، وعناوين IP الخاصة بالعملاء | رؤية أسماء الأجهزة أو المستودعات أو المخازن (فهي معمّاة) أو أي قيمة إعداد |
| رفض الإعدادات أو تأخيرها أو حذفها وسجل تاريخها | تقديم محتوى إعداد على أنه إعداد آخر، أو تعديله، دون أن يكتشف الجهاز ذلك |
| تقديم إصدار قديم لجهاز لم يرَ إصداراً أحدث قط | تقديم إصدار لواجهة سطر الأوامر أقدم من إصدار رأته من قبل: ترفضه واجهة سطر الأوامر |
| تجربة تخمين كلمة المرور الرئيسية دون اتصال | فتح فتحة مفتاح مرور أو رمز استرداد |

ضمانات أخرى:

- **مفتاح مقسم**: يتطلب فك التشفير كلاً من سر الفتحة (على الجهاز) وسر الخادم
- **الحذف يتطلب معرفة**: إزالة قيمة مثبَّتة من إعداد تتطلب إثبات أن القيمة كانت معروفة، بحيث لا يستطيع طرف بوصول جزئي حذف حقول بصمت
- **رموز متجددة**: يُدوِّر كل طلب رمز الإعداد؛ يرتبط الرمز بعنوان IP الخاص باستخدامه الأول وتنتهي صلاحيته بعد 7 أيام
- **الإلغاء**: إزالة عضو تحذف فتحات مفاتيحه ورموزه دفعة واحدة؛ ما سبق أن سحبه يبقى على جهازه، وتدوير مفتاح CEK يمنع مفتاحاً احتفظ به من فتح إصدارات لاحقة

## استكشاف الأخطاء وإصلاحها

| الخطأ | السبب | الحل |
|-------|-------|-----|
| PRF not supported | المصادق يفتقر إلى امتداد PRF | استخدم YubiKey، أو iCloud Keychain، أو 1Password، أو Dashlane، أو أضف فتحة كلمة مرور رئيسية |
| X25519 not supported | إصدار المتصفح قديم جداً | حدّث إلى Chrome 133+، أو Edge 133+، أو Firefox 130+، أو Safari 17+ |
| Already configured | يوجد مخزن لمؤسستك بالفعل | قم بزيارة /account/config-storage للإدارة |
| Config storage not configured | الخادم يفتقر إلى تخزين blob | اتصل بمسؤولك لتكوين R2/RustFS |
| Token expired | لا يوجد نشاط لمدة 7 أيام، أو غيّر الجهاز شبكته | يتجدد تلقائياً عبر تسجيل الدخول؛ إذا لم يكن هناك تسجيل دخول محفوظ، شغّل `rdc subscription login` أو `rdc config remote enable` |
| عاد الإعداد بإصدار أقدم | أعاد الخادم نسخة أقدم مما رآه هذا الجهاز من قبل | لم يتغيّر شيء محلياً؛ أعد المحاولة، وأبلغ إن استمر الأمر |
| Cannot remove last member | سيؤدي إلى قفل المخزن نهائياً | أضف عضواً آخر أولاً |
| Stale slot | الفتحة أقدم من آخر عملية تدوير للمفتاح | أعد إضافة الفتحة (يجب إعادة إنشاء رموز الاسترداد بعد كل تدوير) |
